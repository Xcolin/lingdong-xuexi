# 变更提案：完成灵动学习剩余交付

## Why

项目核心业务已在本地闭环（源码迁移至 V84、11 类导出数据集、后端全量 189 类 797 项通过），但距离可验收交付仍存在三类缺口：内部开发（剩余数据集、统计口径、导入验收、角色矩阵、附件生命周期）、外部通道（真实短信、微信订阅消息）、运维与真实环境验收（CI/部署/UAT）。既有 `docs/superpowers/plans/2026-09-09-lingdong-remaining-development.md` 的 R01-R10 计划与代码进度出现文档滞后（README 仍记 V63/V67 基线），需要一个统一、可勾选、与当前代码对齐的执行路线，避免范围漂移和重复盘点。

## What Changes

- 收口在途的 R06 学生任务报表数据集（V84 已写代码、红灯已确认，待整合验证），并同步 README 与总计划基线至 V84。
- 完成 R06 数据集矩阵剩余两类：机构任务统计、考勤台账；实施已固化的 R-002 活跃度与 R-004 机构统计口径。
- 完成学员批量导入的真实事务边界与固定业务样例验收（重复、越权、部分失败、事务边界）。
- 补齐 R04 六角色 × 两端操作入口矩阵，并建设角色看板复杂统计（仅 Web），家长首页外的矩阵缺口逐项闭环。
- 完成 R08 附件生命周期：持久化存储目录（重启可读）、保留归档、销毁闭环及越权/路径穿越/销毁后访问测试。
- 将四项外部依赖决策（Maven 工具链门槛、短信供应商参数、微信订阅消息模板、定位功能启用）标记为暂缓，按用户决策"项目开发完毕后补齐"处理：不阻塞内部开发，执行到对应收口项时再逐项确认。
- 建立 R09 运维交付：CI（后端测试、Web 测试与构建、小程序类型检查与双构建、迁移校验、密钥扫描，失败即阻断）、部署运行手册、健康监测、告警、日志脱敏、备份恢复脚本与演练、安全/性能测试场景。
- 完成 R10 最终验收：受控发布远程 V78-V84 迁移与独立默认模板配置、MySQL/Redis 与短信/微信真机验证、双端六角色主流程 UAT、需求追溯矩阵（BRD→页面→API→表→测试→验收结果）、生成新状态报告（不覆盖旧审计证据）。

## Capabilities

### New Capabilities

本变更为交付路线基线（roadmap），不直接引入新的 spec 级行为；各具体功能在其独立增量变更中声明各自的能力规格。

### Modified Capabilities

无。现有能力的行为需求不变，本变更仅组织剩余工作的执行顺序与验收口径。

## Impact

- **不直接修改业务代码**：本变更产物为 proposal.md 与 tasks.md，作为后续增量实施的统一路线。
- **后续增量涉及范围**：`server/`（exportjob 适配器、attachment 存储、统计模块、Flyway V85+）、`web/` 与 `miniapp/`（导出入口、角色看板、矩阵缺口页面）、`tools/`（发布检查脚本）、`docs/`（基线同步、部署文档）、远程 MySQL（V78-V84 受控发布）。
- **依赖关系**：R09 依赖 R08 与阶段 2 决策；R10 依赖前述全部任务；外部参数（短信、微信模板）不提供时对应项保持"通道未配置"，不虚构发送成功。
- **既有约束沿用**：测试通过率不等于业务完成率；Flyway 迁移不可修改已执行版本；Git 提交由用户自行处理；`application-local.yml` 凭据不进代码、文档与构建产物。
