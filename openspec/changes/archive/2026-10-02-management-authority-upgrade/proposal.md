# 管理端权限与组织体系升级提案

## Why

管理端当前的授权体系存在结构性割裂：权限目录（`sys_permission`）与菜单/按钮目录（`sys_menu`）是两套对不上的编码体系，授权只能在权限列表中逐条下拉授予；组织树调整层级需走申请-审核流程且无排序能力；菜单管理缺少拖拽与按钮批量维护。随着管理端进入深化运营阶段，权限维护成本高、组织初始化依赖手工、管理效率低的矛盾集中显现，需要一次性完成归一升级。

## What Changes

**组织树管理**
- 组织树支持拖拽调整同级顺序与层级结构（防环校验），系统管理员操作直接生效（不走申请-审核流），保留权限校验与审计记录
- 组织节点新增行政区划字段；字典新增行政区划类型并初始化重庆市 38 个区县（26 区 + 8 县 + 4 自治县）数据
- 组织树初始化：重庆市（CITY）→ 38 区县（REGION）节点，V90+ 迁移幂等插入，不破坏存量组织数据
- 内置组织类型新增：城市（CITY）、国家（COUNTRY）、家庭（FAMILY）；COUNTRY 仅建类型暂不入树，FAMILY 供家庭组织使用
- 既有"申请停用/申请删除"变更审核流程保持不变（仅拖拽路径直接生效）

**角色与权限授予**
- 角色列表侧支持批量勾选用户一键授予角色；组织范围角色需同时指定组织，全局角色按 GLOBAL 授予
- 权限授予改为按菜单树勾选（勾选页面 + 权限按钮即授予对应权限），批量勾选后一次保存
- 权限/角色列表行内提供快捷授权按钮，选中主体可直接点击授权

**菜单与按钮管理**
- 菜单管理维护：类别、名称、编码、路由、图标、顺序、状态；移除"绑定已有路由/动作选项"与权限绑定 UI
- 菜单下按钮支持批量添加与批量修改
- 菜单与按钮支持拖拽排序及层级调整，直接生效
- **权限编码统一**：菜单编码、权限按钮编码即权限编码（`sys_permission` 由菜单/按钮 CRUD 按编码自动同步，无需手工新增）；授权勾选菜单树即获得对应权限；后端运行时权限判定链路（`PermissionDecisionService` 与既有权限注解）零改动
- 按钮分两类：权限按钮（编码对齐权限码，参与授权勾选）与纯 UI 按钮（查询/重置等，仅显示控制，不参与授权）
- 存量迁移：V90+ 将 V88/V89 按钮目录中权限型按钮重编码为对应权限码，纯 UI 按钮编码不动
- 小程序端权限（V69-V71 等）不纳入菜单树，维持现有授予方式

## Capabilities

### New Capabilities
- `organization-tree-administration`: 组织树拖拽管理（顺序/层级/防环校验/直接生效与审计）、行政区划字段与字典、内置组织类型扩展（CITY/COUNTRY/FAMILY）、重庆市 38 区县初始化
- `role-authorization`: 角色侧批量授予用户、菜单树勾选式批量权限授予、列表行内快捷授权入口
- `menu-button-management`: 菜单与按钮维护（类别/名称/编码/路由/图标/顺序/状态）、按钮批量添加修改、拖拽排序与层级调整、编码-权限自动同步、权限按钮与纯 UI 按钮分类

## Impact

- **数据库**：新增 V90+ Flyway 迁移（组织行政区划字段、行政区划字典与组织初始化、内置组织类型、按钮目录重编码、编码-权限同步所需约束）；全部幂等，不破坏存量数据
- **后端**：`organization`（拖拽排序/移动接口、行政区划）、`iam`（批量角色授予、菜单树勾选授权接口）、`menu`（按钮批量 CRUD、层级移动、编码-权限同步、菜单树授权视图）；`PermissionDecisionService`、权限注解拦截链路不改
- **Web 前端**：组织管理页（拖拽树、行政区划）、IAM 管理页（菜单树勾选授权、行内快捷授权、批量授用户）、菜单管理页（拖拽、按钮批量维护、字段调整）
- **小程序**：无改动
- **审计**：拖拽生效、批量授予、编码同步均写入既有审计体系（`sys_iam_change_audit` / 组织变更审计）
- **测试基线**：后端 839 项、Web 269 项既有测试需保持通过；新增能力按 TDD 补充测试
