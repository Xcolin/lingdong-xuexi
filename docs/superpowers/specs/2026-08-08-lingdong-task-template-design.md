# 灵动学习 V34 任务模板设计

## 1. 设计依据与范围

原始素材只明确两类模板：系统预置常用任务模板，以及家长本人可见的个人模板。系统预置示例为“每日阅读30分钟”“口算练习”；家长可以选用模板创建任务，也可以把自定义任务保存为个人模板；个人模板支持编辑、删除和排序。

V34 严格落地上述范围，不新增机构模板、教师模板、模板审批、模板共享、模板市场或模板导入导出。当前小程序只有学生身份，没有家长会话，因此 V34 的模板管理与选用仅进入 Web 家长任务页；小程序公共能力固定不可用，也不增加学生模板入口。

## 2. 角色、权限与功能开关

1. 系统模板由 Flyway 预置，V34 不提供在线新增、编辑、删除接口；所有活动主家长只读可见。
2. 个人模板只归属创建家长。活动主家长可以创建、读取、编辑、逻辑删除和排序本人模板，其他家长、教师、机构管理员和系统角色不能替代操作。
3. 新增独立开关 `LEARNING_TASK_TEMPLATE`。模板能力同时依赖该开关和 `LEARNING_TASK_MANAGEMENT`；任一停用后 Web 入口隐藏，后端全部模板接口拒绝。
4. 新增 Web 权限 `LEARNING_TASK_TEMPLATE_READ` 和 `LEARNING_TASK_TEMPLATE_MANAGE_PERSONAL`，只授予内置家长角色。动态 RBAC 变更仍可撤销授权。
5. 公共能力增加 `learningTaskTemplateEnabled`，仅 Web 在双开关启用时返回 true，小程序固定返回 false。

## 3. 模板数据模型

### 3.1 模板主表

新增 `learn_task_template`：

- `id`：应用层生成的 19 位雪花 `BIGINT` 主键。
- `template_scope`：`SYSTEM` 或 `PERSONAL`。
- `owner_user_id`：个人模板为家长用户标识，系统模板为空。
- `owner_scope_key`：服务端派生的唯一作用域键，系统模板为 `SYSTEM`，个人模板为家长用户标识字符串。
- `template_name`：模板显示名称，去空白后 1 至 50 字。
- `active_name_key`：启用时等于模板名称，删除时为空；与作用域键组成唯一约束，使并发重名失败且删除后可复用原名称。
- `task_title`：任务标题，1 至 50 字。
- `difficulty_level`：1 至 3；基础积分不存储，选用时仍由任务服务按难度计算。
- `duration_minutes`：1 至 1440 分钟。
- `category_code`：可空；创建或编辑时必须是当前启用的任务分类字典项。
- `remark`：可空，最长 200 字。
- `sort_order`：非负整数。系统模板使用固定顺序，个人模板由家长排序。
- `status`：`ENABLED` 或 `DELETED`；删除为逻辑删除。
- `version_no`：正整数乐观版本；每次编辑、删除或排序成功后递增。
- `created_by_user_id`、`updated_by_user_id`、`created_at`、`updated_at`：审计字段。

约束：系统模板的拥有者必须为空，个人模板的拥有者必须非空；同一家长活动个人模板名称唯一；删除后允许重新使用原名称。`owner_scope_key` 和 `active_name_key` 均由服务端维护，客户端不得提交。

### 3.2 模板标签表

新增 `learn_task_template_tag`，保存模板与任务标签字典代码，主键同样为应用层雪花标识；`(template_id, tag_code)` 唯一。标签创建或编辑时必须为当前启用的任务标签字典项。

模板不保存计划日期、目标学生、来源类型、来源组织、审核人、审核时限、基础积分、任务状态、生成类型、周期配置、打卡、附件、顺延、审核或积分。这样可以避免过期关系和历史事实被模板复制。

## 4. 业务流程与接口

### 4.1 查询与选用

`GET /api/v1/task-templates` 返回全部启用系统模板和当前家长启用个人模板，分组后分别按 `sort_order ASC, id ASC` 排序。所有雪花标识按字符串返回。

家长在 Web 新建家庭任务时打开模板库，选择模板后只预填标题、难度、时长、分类、标签和备注；计划日期、学生、审核人和固定任务配置仍由家长在普通任务编辑器中确认。最终创建继续调用现有任务草稿接口，后端按现有家庭范围重新校验，不新增绕过任务校验的一键发布接口。

### 4.2 保存与编辑个人模板

`POST /api/v1/task-templates` 创建个人模板。请求只包含模板名称和六类可复用任务字段；服务端固定写入 `PERSONAL` 和当前用户。个人模板最多 100 个，超过时拒绝创建。

`PATCH /api/v1/task-templates/{id}` 编辑本人启用的个人模板，请求包含完整可编辑字段和 `versionNo`；条件更新失败返回状态冲突。系统模板、其他家长模板和已删除模板统一按不可访问资源处理。

家长可以在任务编辑器中把当前已填写配置保存为个人模板，也可以在模板库中编辑。保存模板不会创建、编辑或发布学习任务。

### 4.3 删除与排序

`DELETE /api/v1/task-templates/{id}?versionNo={versionNo}` 逻辑删除本人个人模板。删除不影响已由该模板预填并创建的任务。

`PUT /api/v1/task-templates/personal-order` 请求包含当前全部启用个人模板的字符串标识和各自版本号，最多 100 项。服务端在一个事务内校验归属、无重复、集合完整和版本一致，再按数组顺序写入从 10 开始、步长 10 的排序值并递增版本。任一项冲突整单失败，不产生部分排序。

## 5. Web 交互

1. 家长任务页增加“任务模板”入口，新建任务抽屉增加“从模板选择”和“保存为个人模板”操作；仅角色、权限和能力同时满足时显示。
2. 模板库使用“系统模板/个人模板”分页签。系统模板只显示选用；个人模板显示选用、编辑、删除、上移和下移，图标按钮提供中文提示。
3. 选用模板后关闭模板库并回填任务编辑器，页面明确保留日期、学生和审核人等待确认，不自动发布。
4. 新建或编辑个人模板使用同一表单校验；删除需二次确认。排序成功后刷新服务器顺序，失败时恢复服务器结果并显示中性错误。
5. 系统模板空态与个人模板空态分别呈现；功能停用、权限撤销或会话失效时直达操作同样失败，不依赖按钮隐藏。

## 6. 事务、并发与错误

1. 创建和编辑模板主表与标签处于同一事务；先校验字典，再写主表和标签。任一步失败整体回滚。
2. 编辑、删除和排序均使用 `version_no` 条件更新，防止多窗口覆盖。模板名称唯一约束作为并发最后防线，数据库异常转换为统一状态冲突。
3. 对象越权统一返回资源不存在；字段错误返回校验错误；重复名称、数量上限、版本冲突和排序集合变化返回状态冲突；功能停用返回 `FEATURE_DISABLED`。
4. API 不接受模板范围、拥有者、基础积分、创建人、状态或排序审计字段，避免客户端提权或伪造派生数据。

## 7. 测试与验收

1. Flyway 从空库执行 V1-V34，核对 60 张显式非自增 `BIGINT id` 主键表、两张新表约束索引、系统模板、开关、权限和角色授权；所有初始化标识为 19 位数字。
2. 后端覆盖系统与个人可见范围、个人数量上限、字典校验、重名、编辑版本、逻辑删除、排序集合完整性、跨家长越权、双开关和 Web 客户端边界。
3. 持久化测试验证主表与标签原子写入、版本递增、删除后名称复用、排序回滚和系统模板只读。
4. Web 组件测试覆盖入口门禁、系统/个人分组、模板预填、保存个人模板、编辑、删除、排序和失败反馈。
5. 执行后端全量测试、Web 全量测试与生产构建、uni-app 类型检查和 H5/微信小程序构建；静态扫描确认 Web 产物包含模板入口、小程序产物不包含家长模板管理入口。

## 8. 非本版本范围

机构模板、教师模板、模板共享、模板审批、模板市场、模板导入导出、系统模板在线维护、家长小程序模板管理均不属于原始素材已确认范围。若后续新增，必须先补充原始需求并单独设计权限、组织数据范围和端侧流程。
