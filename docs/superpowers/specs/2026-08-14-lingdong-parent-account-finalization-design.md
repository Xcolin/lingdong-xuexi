# 灵动伴随 V43 家长账号最终注销与匿名化设计

## 1. 目标与依据

V43 承接 V42 已进入冷静期的家长注销申请。依据原始需求，家长解除全部学生关系并经过 7 天冷静期后，账号正式注销，个人数据按法律法规要求匿名化或删除。

本工作包只处理家长账号最终注销，不实现学生账号注销，也不实现原手机号失效时由机构或平台人工核验。法规和原始需求未给出统一业务数据删除期限，因此 V43 不自行设定任务、积分、审核、日志或附件的物理删除日期。

## 2. 方案选择

采用“保留内部主键、去除直接身份、保留必要历史事实”的方案：

1. 不物理删除 `sys_user`，避免破坏任务、积分、审核、关系和安全审计的外键与事实一致性。
2. 将用户状态置为 `CANCELLED`，用户名替换为只含内部用户标识的不可登录匿名值，展示名替换为“已注销用户”，手机号和密码摘要清空。
3. 删除微信绑定中的 `app_id/open_id/union_id` 直接身份记录，使原微信身份可按正常规则绑定其他有效账号。
4. 协议接受、首次引导、历史亲子关系、任务、积分、审核和安全事件按内部用户标识保留；这些记录不再能通过手机号、用户名或微信身份反查自然人。
5. 全部活动会话立即撤销。注销完成后不支持恢复账号，只能重新注册新账号。

不采用物理级联删除，因为现有大量业务表引用用户主键，级联删除会破坏审计和统计事实；也不只做账号禁用，因为那仍保留手机号、微信身份和显示名称，不满足匿名化目标。

## 3. 状态与并发规则

1. 仅处理 `COOLING_OFF`、`active_scope_key = 'ACTIVE'`、`cooling_ends_at <= 当前时间` 且到达下次执行时间的申请。
2. 每个申请在独立事务中锁定注销申请和用户，重复调度或多实例并发只能有一个事务完成。
3. 执行前再次统计活动主家长和副家长关系。若关系数大于零，本次不注销，记录 `ACTIVE_RELATIONSHIP` 并延后重试；不得强行解除关系。
4. 功能开关 `PARENT_ACCOUNT_LIFECYCLE` 停用时暂停自动终结，既有申请和历史数据保留。
5. 用户已不是有效家长、申请已撤销或已终结时跳过，不重复匿名化。
6. 单个账号失败不能回滚同批其他账号。技术异常由下一次调度重试，日志只记录申请标识和错误类别，不记录个人信息。
7. 成功后注销申请更新为 `FINALIZED`，活动范围键关闭并记录终结时间；该状态不可逆。

## 4. 数据库与 Flyway

新增 `V43__finalize_parent_account_cancellation.sql`，不修改 V1-V42。

在 `auth_parent_account_cancellation` 增加：

- `finalization_attempts INT NOT NULL DEFAULT 0`：已登记的终结尝试次数。
- `next_finalize_at TIMESTAMP NULL`：下一次允许执行时间；历史活动申请初始化为冷静期结束时间。
- `last_finalize_error_code VARCHAR(64) NULL`：只保存稳定错误码，不保存异常文本和个人信息。
- 到期扫描索引：`status, next_finalize_at, id`。

V43 不新增业务表，因此现有 70 张主键表数量不变；所有后续新表仍必须使用应用层 19 位雪花 `BIGINT` 主键。

## 5. 应用组件

### 5.1 终结事务服务

`ParentAccountFinalizationService` 负责单个注销申请：

1. 校验功能开关并锁定申请。
2. 校验冷静期和下次执行时间。
3. 锁定用户并重新检查家长身份和活动亲子关系。
4. 关系恢复时登记延后，不修改用户。
5. 删除微信绑定，匿名化用户主记录，撤销全部会话。
6. 将申请更新为 `FINALIZED`。

上述写入位于同一事务，任一步失败全部回滚，不允许出现账号已匿名化但申请仍活动，或申请已终结但账号仍可登录。

### 5.2 批处理与调度

`ParentAccountFinalizationBatchService` 分页读取到期申请标识，并逐个调用独立事务服务。`ParentAccountFinalizationSchedulingConfiguration` 使用配置化 cron、批量大小和启停项，测试环境默认关闭。批处理每次只处理有限数量，防止长事务和数据库突发压力。

配置前缀为 `lingdong.parent-account-finalization`：

- `scheduling-enabled`：是否启用自动终结。
- `batch-size`：单次最大处理数量，默认 100。
- `cron`：默认每 10 分钟执行。
- `relationship-retry-delay`：因关系恢复延后的间隔，默认 1 天。

## 6. 前端边界

V43 不新增 Web 或小程序操作页。V42 页面在冷静期结束后继续显示“待执行注销”，直到后台成功终结；成功终结会撤销所有会话，用户再次访问时回到登录页。Web 和 uni-app 仍为独立前端应用，不共享会话存储。

## 7. 安全与验收

1. 空 H2 MySQL 兼容库连续执行 V1-V43，V43 字段、索引和历史数据回填正确。
2. 未到期、已撤销、已终结和功能停用申请不执行。
3. 活动亲子关系恢复时账号保持有效，记录稳定错误码并延后重试。
4. 成功后用户状态为 `CANCELLED`，手机号和密码为空，用户名和展示名已匿名化，微信绑定不存在，全部会话失效。
5. 历史任务、积分、审核和关系记录数量不因注销减少，仍通过匿名内部用户标识保持事实一致。
6. 并发和重复执行最多一次成功；单个失败不影响同批其他申请。
7. 后端全量测试、Web 全量测试与构建、uni-app 类型检查及 H5/微信小程序构建全部通过。
