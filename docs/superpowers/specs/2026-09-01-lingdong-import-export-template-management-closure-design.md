# 灵动学习 V55 导入导出模板管理闭环设计

## 1. 设计依据

本设计承接以下已确认需求与既有实现：

1. 业务需求说明书 `BRD-3.2-07` 要求统一配置导入、导出模板，支持模板版本、默认模板和启停管理。
2. `BRD-4.2-06` 要求形成可按模板类型、适用模块和状态筛选的模板台账。
3. FSD-SYS-03 要求同一适用模块、同一模板类型最多一个默认模板；模板变更只影响新任务，历史导入记录和导出文件保留原模板版本。
4. V14 已建立 `sys_import_export_template`，并实现创建、设置默认、停用和当前默认模板查询的最小应用服务。
5. V51 已提供统一数据字典管理，V54 已提供附件规则、文件元数据、业务关系、受控内容存储和附件总开关。
6. Web 与小程序是独立前端应用；复杂系统配置只在 Web 提供，小程序不增加模板管理页面、接口或路由。

V55 在 V14 基础上完成模板配置管理闭环，不修改 V1 至 V54 历史迁移。

## 2. 范围与非目标

### 2.1 本期范围

1. 模板台账按名称、模板类型、适用模块和状态组合筛选，最多返回 200 条。
2. 系统管理员或获得动态权限的 Web 角色上传模板文件并创建不可变模板版本。
3. 启用、停用模板，并在停用默认模板时同步取消默认标记。
4. 将启用模板设为所属模块、所属类型的唯一默认模板。
5. 按模板读取权限受控下载历史或当前模板文件。
6. 使用乐观锁防止并发启停、并发设置默认和重复覆盖。
7. 接入独立功能开关、动态 RBAC、统一附件规则和统一数据字典选项。
8. 提供独立 React Web 管理页面，并完成桌面与窄屏交互验收。

### 2.2 明确不纳入 V55

1. 不实现业务数据导入、逐行校验、字段映射、错误文件或部分成功处理。
2. 不实现异步导出任务、导出数据口径、敏感数据审批、脱敏或下载通知。
3. 不实现 Excel、CSV 或 PDF 内容生成，也不解析模板业务字段。
4. 不接入云对象存储、病毒扫描、Office 转码或在线预览。
5. 不在小程序增加模板配置、批量导入或复杂导出能力。
6. 不为模板变更增加系统审核流程。业务需求列出的高风险任务未包含普通模板创建、启停和默认切换；未来若模板涉及敏感导出，审批属于导出任务执行阶段。

## 3. 核心设计决策

### 3.1 模板版本不可变

模板的 `module_code`、`template_type`、`version` 和 `file_id` 创建后不可修改。管理员需要替换文件、调整适用模块或升级内容时，应创建新的模板版本。系统不提供覆盖文件、修改版本号或删除模板接口，以保证未来业务任务能够持续引用确定版本。

模板名称是版本记录的一部分，V55 同样不提供原地编辑。这样可以避免页面上的“编辑”实际改写历史含义。

### 3.2 默认模板唯一

V14 的 `(module_code, template_type, default_scope_key)` 唯一约束继续作为数据库最终防线：默认模板使用 `DEFAULT`，非默认模板使用 `ID:<模板标识>`。

创建默认模板或切换默认模板时，应用服务先锁定同模块、同类型模板组，再撤销原默认模板并设置目标模板。整个过程在同一事务内完成，避免两个管理员并发设置不同默认模板时出现覆盖或唯一约束异常。

### 3.3 统一附件，不复制文件能力

模板文件固定以附件模块编码 `IMPORT_EXPORT_TEMPLATE`、文件分类 `TEMPLATE_FILE` 登记。上传必须命中附件规则管理中已启用的对应规则；允许扩展名、内容类型、单文件大小和批量数量不在模板模块重复配置。

V55 提取可复用的受控附件内容服务，统一完成元数据登记、随机存储键生成、内容保存、SHA-256 摘要、完成确认、读取和失败补偿。现有任务图片继续在进入该公共服务前执行 JPG/PNG 真实格式校验，业务权限仍由任务模块负责，不放宽现有访问边界。

模板创建成功后增加文件关系：

- `module_code`：`IMPORT_EXPORT_TEMPLATE`
- `business_id`：模板标识
- `relation_type`：`TEMPLATE_FILE`
- `visible_scope`：`SYSTEM_CONFIGURATION`

模板下载只返回文件内容、原始文件名和内容类型，不返回存储键、文件系统路径、对象存储参数或摘要原文。

### 3.4 字典选项统一来源

V55 初始化并使用以下数据字典：

| 字典类型 | 字典项 | 用途 |
|---|---|---|
| `IMPORT_EXPORT_TEMPLATE_TYPE` | `IMPORT`、`EXPORT` | 模板类型选择与中文展示 |
| `IMPORT_EXPORT_TEMPLATE_MODULE` | `STUDENT`、`LEARNING_TASK`、`REPORT` | 学员导入、任务导入、报表导出适用模块 |
| `IMPORT_EXPORT_TEMPLATE_STATUS` | `ENABLED`、`DISABLED` | 状态筛选与中文展示 |

模板页面通过模板选项接口读取当前启用字典项，不要求用户额外拥有数据字典管理权限。创建模板时，后端再次验证模板类型和适用模块对应字典项仍处于启用状态。模板生命周期仍只接受系统定义的 `ENABLED`、`DISABLED`，字典只决定可选项与显示名称，不能增加未知生命周期状态。

## 4. 数据库迁移 V55

V55 执行以下变更：

1. 为 `sys_import_export_template` 增加 `version_no BIGINT NOT NULL DEFAULT 0`。
2. 新增全局功能开关 `IMPORT_EXPORT_TEMPLATE_MANAGEMENT`，默认启用。
3. 新增 Web 权限 `IMPORT_EXPORT_TEMPLATE_READ`、`IMPORT_EXPORT_TEMPLATE_MANAGE`。
4. 将两项权限默认授予内置 `SYS_ADMIN`，其他内置角色不自动获得。
5. 初始化三类模板字典及七个字典项。
6. 所有迁移新增主键、权限授权关系和字典标识均使用预生成的 19 位雪花数字。

V55 不新增模板执行任务表，不回填或改写既有模板业务数据。V14 可能存在的历史模板即使没有文件关系，仍可通过 `file_id` 查询和下载；V55 新建模板必须同时建立业务关系。

## 5. 权限与功能开关

### 5.1 动态 RBAC

| 权限编码 | 能力 |
|---|---|
| `IMPORT_EXPORT_TEMPLATE_READ` | 查询模板、读取字典选项、查看安全文件元数据和下载模板文件 |
| `IMPORT_EXPORT_TEMPLATE_MANAGE` | 上传并创建模板版本、启用、停用和设置默认模板 |

Controller 使用 `@RequirePermission`，应用服务同时通过 `PermissionDecisionService` 校验 Web 客户端动态权限，避免未来新增入口绕过权限。系统审核员、机构管理员、教师、家长和学生默认没有模板管理权限；系统管理员可通过 RBAC 将权限授予新增的运维等自定义角色。

### 5.2 开关依赖

模板管理有效能力定义为：

`WEB 客户端 && IMPORT_EXPORT_TEMPLATE_MANAGEMENT 启用 && ATTACHMENT_SERVICE 启用`

任一开关关闭时：

1. Web 菜单、直达页面、按钮和弹窗全部不可见。
2. 后端模板管理接口统一拒绝访问，旧链接不能绕过。
3. 小程序能力固定返回不可用，不增加模板管理代码。
4. 历史模板、文件和关系不删除；重新启用后恢复查询。

## 6. 后端接口

统一路径为 `/api/v1/import-export-templates`。

| 方法与路径 | 权限 | 行为 |
|---|---|---|
| `GET /options` | `IMPORT_EXPORT_TEMPLATE_READ` | 返回当前启用的模板类型、适用模块和状态中文选项 |
| `GET /` | `IMPORT_EXPORT_TEMPLATE_READ` | 按名称、类型、模块、状态组合查询模板台账 |
| `POST /` | `IMPORT_EXPORT_TEMPLATE_MANAGE` | 使用 `multipart/form-data` 上传文件并创建一个不可变模板版本 |
| `POST /{id}/enable` | `IMPORT_EXPORT_TEMPLATE_MANAGE` | 按 `versionNo` 启用模板 |
| `POST /{id}/disable` | `IMPORT_EXPORT_TEMPLATE_MANAGE` | 按 `versionNo` 停用模板；若为默认项则同步取消默认 |
| `POST /{id}/default` | `IMPORT_EXPORT_TEMPLATE_MANAGE` | 按 `versionNo` 将启用模板设为所属分组唯一默认项 |
| `GET /{id}/download` | `IMPORT_EXPORT_TEMPLATE_READ` | 下载模板文件，允许读取已停用的历史模板 |

创建请求包含 `templateName`、`templateType`、`moduleCode`、`version`、`defaultTemplate` 和单个 `file`。响应中的模板、文件及关系标识均按字符串输出，另含模板名称、类型、模块、版本、安全文件名、文件大小、默认标记、状态、`versionNo`、创建时间和更新时间。

不提供修改和删除接口。业务模块未来创建导入或导出任务时，只能引用启用模板的明确标识和版本，不能只保存“当前默认”文本。

## 7. 业务流程

### 7.1 查询流程

1. Web 读取公共能力和当前用户权限。
2. 两个开关均启用且用户拥有读取权限时显示菜单。
3. 页面并行读取模板选项和模板台账。
4. 查询条件为空时返回最近更新的最多 200 条；组合筛选由后端统一标准化。

### 7.2 创建版本流程

1. 管理员填写名称、类型、适用模块、版本和默认标记，选择一个文件。
2. 后端依次校验功能开关、动态权限、字典项、字段长度和同模块同类型版本唯一性。
3. 文件进入统一附件服务，按 `IMPORT_EXPORT_TEMPLATE/TEMPLATE_FILE` 规则校验并保存。
4. 应用服务创建模板记录并建立模板文件关系。
5. 请求设为默认时锁定模板组，撤销原默认项后设置新模板为默认。
6. 任一步骤失败时事务回滚，并补偿删除本次尚未关联的物理内容，不保留可被误用的临时文件。

### 7.3 启停与默认切换流程

1. 前端提交当前 `versionNo`。
2. 后端锁定目标记录并比较版本；版本不一致返回冲突。
3. 启用只改变状态；不会自动成为默认模板。
4. 停用时清除默认标记并增加版本号。
5. 设置默认只允许启用模板；锁定同组后切换默认项，并分别增加发生状态变化记录的版本号。
6. 相同版本下重复提交当前状态返回当前结果，不产生多余版本变化；过期版本始终返回冲突并要求刷新。

## 8. Web 页面设计

新增独立路由 `/import-export-templates`，菜单名称为“导入导出模板”。页面采用适合后台重复操作的紧凑布局，不使用营销式首屏或嵌套卡片。

1. 顶部筛选区：模板名称、模板类型、适用模块、状态，以及查询、重置命令。
2. 主表字段：名称、类型、适用模块、版本、文件名、文件大小、默认项、状态、更新时间和操作。
3. 有管理权限时显示“新增模板版本”、设为默认、启用和停用操作；只有读取权限时保持完整只读台账与下载能力。
4. 新增弹窗使用类型和模块下拉、版本及名称输入、单文件上传、默认项开关；提交期间禁止重复操作。
5. 默认模板使用明确图标与文字状态，不能只依赖颜色表达。
6. 文件下载使用下载图标按钮和工具提示；不支持 Office 在线预览时不展示虚假预览入口。
7. 桌面宽表允许表格内部横向滚动；390px 窄屏下筛选项纵向排列、弹窗宽度不超过视口、页面本身不得产生横向溢出。
8. 接口失败保留当前筛选条件并提供重试；409 版本冲突提示刷新后重试。

## 9. 异常与安全规则

| 场景 | 结果 |
|---|---|
| 功能开关关闭 | 409，前端隐藏全部入口 |
| 缺少动态权限 | 403，不依赖页面隐藏作为安全边界 |
| 模板不存在或不可访问 | 404，避免泄露资源存在性 |
| 类型或模块字典项停用 | 400，不允许新建使用 |
| 同模块、同类型、同版本重复 | 409，不覆盖旧版本 |
| 版本号过期 | 409，返回明确刷新提示 |
| 停用模板设为默认 | 409 |
| 模板附件规则缺失或停用 | 409，提示先完成附件规则配置 |
| 文件扩展名、类型或大小不符合规则 | 400 |
| 文件状态不是 `AVAILABLE` | 409，不创建模板 |
| 内容存储失败或数据库失败 | 整体失败并执行补偿，不返回半成功模板 |

日志、异常和 API 响应不得包含文件内容、存储键、绝对路径、SHA-256 原文、数据库密码、Redis 密码或微信密钥。文件名用于 `Content-Disposition` 时使用框架编码，不直接拼接响应头。

## 10. 测试与验收

### 10.1 后端

1. Flyway V1 至 V55 连续迁移通过，历史迁移无差异。
2. V55 全部新增标识为 19 位数字，模板主键继续由雪花算法生成。
3. 覆盖查询筛选、字典启停、创建版本、文件规则、唯一版本、唯一默认、启停、默认切换、幂等和版本冲突。
4. 覆盖动态允许、用户明确禁止、自定义角色授权和未授权访问。
5. 覆盖两个功能开关分别关闭时全部接口拒绝。
6. 覆盖上传成功、存储失败补偿、数据库失败补偿、受控下载和敏感字段不出现在响应。
7. 回归任务打卡图片上传、读取、下载、删除及附件关闭后的纯文字打卡。

### 10.2 Web

1. 覆盖菜单和直达路由的开关、读取权限与管理权限组合。
2. 覆盖筛选、重置、新增、上传、设为默认、启停、下载、冲突刷新和错误重试。
3. 执行全量单元测试、类型检查和生产构建。
4. 使用 1280px 桌面与 390px 窄屏检查表格、弹窗、下载和空状态，确认无页面级横向溢出或文字遮挡。

### 10.3 应用隔离与静态审计

1. uni-app 不新增模板管理页面、路由或管理 API，类型检查、H5 和微信小程序构建继续通过。
2. 扫描小程序源码和构建产物，确保没有定位或地图调用。
3. 扫描源码、迁移和文档，确保没有数据库、Redis、微信等真实密钥。
4. 执行 `git diff --check`，并确认不存在临时预览入口或测试文件。

本地验收不连接远程 MySQL、Redis、共享测试、预生产或生产环境，也不宣称完成业务 UAT。
