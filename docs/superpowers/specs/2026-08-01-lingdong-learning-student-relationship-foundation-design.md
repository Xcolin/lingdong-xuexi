# 灵动学习学生与家校关系基础设计

**版本**：V1.0  
**日期**：2026-08-01  
**状态**：已确认，进入实施  
**依据**：`FSD-STU-01`、数据库设计第 5.2 节、权限与安全设计第 3.3 节。

## 1. 本轮目标与范围

本轮建立学习业务依赖的最小事实源：学生档案、主家长关系、机构关联，以及按本人亲子关系或机构管理员关联范围读取学生的目录和详情。所有表主键使用应用层生成的 19 位雪花 `BIGINT`。

本轮不实现学生账号登录码、二维码、微信绑定、家长邀请、副家长、主家长变更、解绑、转班转学、学生注销、任务、积分、附件头像和小程序页面。小程序尚无真实登录与会话，不能安全暴露家长创建入口；待小程序认证完成后，再由相同后端接口接入小程序。

## 2. 关系模型

### 2.1 学生档案

`edu_student` 保存独立于 `sys_user` 的学生业务档案，字段为学生姓名、可选年级编码、可选的未来学生账号标识、状态和审计时间。未来学生登录功能可以回填学生账号标识；本轮不创建学生登录账号，不生成或保存登录码。

学生状态仅在数据库中预留 `ENABLED`、`DISABLED` 枚举，首轮所有新增学生均为 `ENABLED`，不提供状态变更接口。

### 2.2 家庭关系

家庭路径由已经拥有 `PARENT` 角色的当前登录用户创建学生。服务端在同一事务内创建学生与一条 `PRIMARY`、`ACTIVE` 的亲子关系。请求不接受家长用户标识，防止代他人建立家庭关系。

`edu_parent_student` 使用“主家长活动范围键”唯一约束保证每名学生最多一位活动主家长；本轮没有解绑或副家长能力，不以应用层判断代替数据库约束。

### 2.3 机构关系

机构路径由已配置为目标组织管理员、并拥有 `ORG_ADMIN` 角色的当前登录用户创建学生。请求必须携带启用组织标识，服务端验证该用户的 `sys_organization_admin` 记录后，在同一事务中创建学生与一条 `ENROLLMENT`、`ACTIVE` 的机构关系。

本轮仅允许直接关联指定组织节点，不按组织树下级扩展，也不提供转班、转学、停用或历史关系变更。机构关联绝不赋予读取家庭私有任务、奖励、积分或复盘的权利。

## 3. 授权与可见性

| 操作 | 路由权限 | 业务范围校验 |
|---|---|---|
| 家长创建学生 | `STUDENT_CREATE` | 当前身份必须拥有 `PARENT`，且请求不得携带组织标识。 |
| 机构创建学生 | `STUDENT_CREATE` | 当前身份必须拥有 `ORG_ADMIN`，目标组织启用且当前用户是该组织管理员。 |
| 查询学生目录/详情 | `STUDENT_READ` | 系统管理员可读取全量；家长仅能读取活动亲子关系学生；机构管理员仅能读取与其直接管理组织存在活动机构关系的学生。 |

`STUDENT_CREATE` 在 V19 中授予 `PARENT`、`ORG_ADMIN`，`STUDENT_READ` 授予 `SYS_ADMIN`、`PARENT`、`ORG_ADMIN`，使动态 RBAC 先拦截无权请求；应用服务随后执行上述对象范围校验。系统管理员只可读取全量目录，不以系统管理员身份代替家长或机构管理员创建学生，保持家庭和机构创建事实清晰。

学生目录查询必须在 SQL 中按当前用户的有效亲子关系、直接组织管理员关系过滤，禁止先查全量再在前端隐藏。用户同时具有家长和机构管理员角色时，目录取两个范围的并集且不重复。

## 4. HTTP 契约

### 4.1 `POST /api/v1/students`

请求字段：`studentName`（必填，1 至 64 个字符）、`gradeCode`（可选，最长 64 个字符）、`organizationId`（可选，19 位字符串）。

未传 `organizationId` 时执行家庭创建路径；传入时执行机构创建路径。学生和关系写入必须在同一事务中完成，任一校验或写入失败时均不保留半成品数据。成功返回 HTTP 201 与学生安全响应。

### 4.2 `GET /api/v1/students`

可选参数：`keyword`（学生姓名模糊匹配，最长 64 个字符）、`page`（默认 1）、`pageSize`（默认 20，范围 1 至 100）。结果稳定按 `created_at DESC, id DESC` 排序，返回 `{ items, page, pageSize, total }`。目录项只返回学生档案公开字段，不返回家长手机号、亲子关系细节、账号散列、会话或登录码。

### 4.3 `GET /api/v1/students/{id}`

按与目录完全相同的对象范围规则读取单个学生。无可见关系时统一返回 `404 RESOURCE_NOT_FOUND`，不得暴露学生是否存在；缺少路由权限时返回 `403 ACCESS_DENIED`。

## 5. 数据库与迁移

V19 新增 `edu_student`、`edu_parent_student`、`edu_student_organization` 三张表以及 `STUDENT_CREATE`、`STUDENT_READ` 两项 Web 操作权限和角色授权。迁移只使用预生成的 19 位雪花常量；不插入学生、关系、密码、会话、登录码或远程环境数据。

本轮仅在本地 H2 MySQL 兼容模式验证 Flyway。用户提供的 MySQL/Redis 连接信息只放在被忽略的 `application-local.yml`，默认配置继续使用环境变量占位；不得连接、迁移或清理远程数据库。

## 6. 前端边界

当前 Web 管理端和 uni-app 小程序保持独立。学生与关系 API 先由后端集成测试验证，不创建无法完成真实认证与授权的数据录入页面。待小程序会话认证完成后，家长创建和本人学生目录使用本轮稳定接口；待机构学生管理列表的组织范围需求明确后，再在 Web 接入对应页面。

## 7. 验证范围

1. Flyway V1-V19 可从空库顺序应用，所有新增主键为 19 位数字。
2. 家长创建学生会自动建立唯一活动主家长关系；家长不能通过请求关联组织。
3. 机构管理员仅能在其直接管理的启用组织创建学生；无组织管理员关系或停用组织时拒绝。
4. 家长、机构管理员、系统管理员各自目录范围正确；跨家庭、跨机构详情统一返回 404。
5. 无 `STUDENT_CREATE` 或 `STUDENT_READ` 权限的已认证用户返回 403。
6. 后端全量测试、Web 与小程序独立构建继续仅在本地环境执行。
