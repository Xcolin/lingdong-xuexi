# 周报订阅 Web 请求契约

## 范围

对应 V63-D，复用已实现的本人订阅 GET/PUT 接口。仅新增 Web 独立请求封装，不混用小程序接口，不增加业务字段，不开放尚未接通微信的页面入口。

## 字段与行为

- 学生标识始终使用字符串，并作为独立路径段编码，避免雪花标识精度丢失。
- 响应保留 studentId、enabled、version；enabled 仅代表系统内偏好，不表示微信授权或消息送达。
- 修改请求仅提交 enabled、version，显式选取字段，不透传调用方附带的用户标识或授权声明。订阅人仍由服务端会话确定。
- 取消直接使用相同 PUT 接口，不先调用开启资格或读取接口；服务端负责取消权限及待发记录联动。
- 版本冲突和其他业务失败原样交给调用方，不自动覆盖版本或重试写入。统一 HTTP 层原有会话刷新策略保持不变。

## 验收与后续

四项请求契约测试覆盖标识、白名单、取消与冲突。该模块不产生可见页面变化，不新增数据库迁移。页面状态、渠道授权和真实微信投递尚未完成，不能据此计入完整订阅分值。

后端补充 5 项 MockMvc HTTP 契约测试：GET 公开字段与字符串标识、PUT 服务端身份和版本传递、无效请求体与非法路径拒绝、权限/状态/功能停用错误映射。联合已有偏好与排程专项共 14 项通过。HTTP 测试服务与身份解析为替身，服务层真实数据库边界由独立订阅专项覆盖，不将两者混称端到端认证验收。
