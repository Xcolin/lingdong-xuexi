# 灵动学习平台认证与设备会话设计

## 1. 目标与范围

本次仅实现平台账号的密码认证、受控会话、当前登录主体和设备会话管理，为后续 Web 管理端提供真实身份上下文。认证后端使用不透明访问凭证和刷新凭证，服务端按会话状态校验，从而支持退出、指定设备下线和一键下线后的立即失效。

本次范围包括：

1. 系统管理员为平台账号设置或重置密码。
2. 启用的平台账号使用账号名和密码登录，建立 Web 设备会话。
3. 访问凭证刷新、当前会话退出、当前用户信息查询、设备列表、指定设备下线和一键下线。
4. Spring Security 的请求身份解析；除健康检查和登录/刷新接口外，`/api/v1/**` 必须具有有效会话。
5. 统一的认证失败、会话失效和权限拒绝响应，不返回密码、原始令牌或内部异常。

本次明确不实现：手机号验证码、微信登录和绑定、学生登录码、学生扫码、注册、忘记密码、图形验证码、短信服务、登录风控、通用操作审计和 Redis 会话缓存。这些能力依赖尚未建设的学生关系、短信供应商或微信绑定模型，后续必须以独立设计与 Flyway 版本实现。

## 2. 方案选择

采用数据库保存会话状态和令牌摘要的方案，而不在首轮使用无法即时撤销的纯自包含令牌。服务端生成高熵访问凭证和刷新凭证，仅将其 SHA-256 摘要落库；客户端只保存原始凭证并在 HTTPS 请求中携带访问凭证。每次受保护请求均根据访问凭证摘要查找处于有效状态的会话，因此设备下线和一键下线立刻生效。

相比纯 JWT，该方案能够直接满足设备管理和会话撤销要求，且避免将角色、权限或组织范围快照写入难以即时失效的令牌。相比一开始引入 Redis 会话存储，数据库事实源更适合当前尚未有完整缓存域和统一监控的阶段；后续可在不改变认证 API 的前提下增加缓存。

密码使用 Spring Security 的 BCrypt 强散列，校验密码长度为 8 至 20 位且必须同时包含字母和数字。令牌通过 `SecureRandom` 生成，禁止写入日志、数据库明文、异常信息或响应日志。

## 3. 数据模型与状态

既有 `sys_user.password_hash` 是密码凭证的唯一事实源，认证服务只更新该字段，不新增重复的密码凭证表。Flyway `V15` 新增以下表，使用应用层生成的 19 位雪花 `BIGINT id` 主键：

| 表 | 核心字段 | 说明 |
|---|---|---|
| `auth_device_session` | user_id、client_type、device_id、device_name、access_token_hash、refresh_token_hash、access_expires_at、refresh_expires_at、status、last_active_at、signed_out_at | 一次登录对应一条可追溯会话，状态为 `ACTIVE`、`SIGNED_OUT`、`REVOKED` 或 `EXPIRED`。令牌摘要唯一，便于查找和防止重复使用。 |

用户是否可登录以既有 `sys_user.status = ENABLED` 为准。首轮只接受 `UserType.PLATFORM` 且客户端类型为 `WEB` 的账号密码登录；其他用户类型和客户端类型须在对应业务账号模型完成后再开放。

## 4. 流程与规则

### 4.1 设置密码

系统管理员提交目标平台账号和新密码。服务端校验操作者具有 `SYS_ADMIN` 角色、目标用户存在且属于平台账号、密码符合复杂度规则，然后更新既有 `sys_user.password_hash`。该应用服务不接受前端传入的用户身份作为授权依据；后续 HTTP 接口必须使用当前会话身份完成权限判断。

### 4.2 密码登录

客户端提交账号名、密码、设备标识和设备名称。服务端按账号名查询启用的平台用户，读取凭证散列并比较密码；失败时返回统一认证失败结果，不区分账号不存在、账号停用、未设置密码或密码错误。成功后生成访问凭证和刷新凭证，写入 `ACTIVE` 会话并返回会话标识、到期时间和两类原始凭证。

访问凭证有效期为 30 分钟，刷新凭证有效期为 7 天。期限由认证配置提供，测试环境可覆盖；生产环境不得使用硬编码的弱密钥或测试令牌。

### 4.3 请求认证和刷新

受保护请求从 `Authorization: Bearer <访问凭证>` 读取凭证，计算摘要并查询会话。只有状态为 `ACTIVE`、访问凭证未过期且所属用户启用时，才建立 Spring Security 身份。身份至少包含用户标识、会话标识、客户端类型和角色代码；后续权限、功能开关和数据范围通过该身份上下文处理。

刷新接口只接受有效的 `ACTIVE` 会话和未过期刷新凭证。刷新成功后必须轮换访问凭证和刷新凭证，使旧刷新凭证立即失效，并更新最后活跃时间。刷新失败返回统一认证失败结果。

### 4.4 退出与设备管理

当前会话退出：将当前会话更新为 `SIGNED_OUT`，同一会话的访问和刷新凭证均立即失效。

指定设备下线：当前用户只能下线自身会话；服务端先校验会话归属，再更新为 `REVOKED`。一键下线：撤销当前用户全部 `ACTIVE` 会话，包括发起请求的当前会话。设备查询仅返回当前用户的活动会话，不返回令牌摘要或密码散列。

## 5. HTTP 契约

首轮提供如下真实认证接口，统一置于 `/api/v1/auth`：

| 方法与路径 | 用途 | 认证要求 |
|---|---|---|
| `POST /sessions/password` | 平台账号密码登录 | 公开。 |
| `POST /sessions/refresh` | 刷新当前会话凭证 | 公开，仅依据请求体中的刷新凭证校验。 |
| `DELETE /sessions/current` | 退出当前设备 | 有效访问凭证。 |
| `GET /me` | 返回当前用户、角色代码和会话摘要 | 有效访问凭证。 |
| `GET /devices` | 查询当前用户的活动设备会话 | 有效访问凭证。 |
| `DELETE /devices/{sessionId}` | 下线指定自身设备会话 | 有效访问凭证。 |
| `POST /devices/sign-out-all` | 撤销当前用户所有活动会话 | 有效访问凭证。 |

“系统管理员设置密码”仅先提供应用服务，不在本次增加绕过完整用户管理授权模型的临时 REST 接口。用户管理 API 与认证基础完成后统一建设。

## 6. 错误处理与安全边界

认证失败、令牌缺失、令牌过期或会话失效统一返回 `AUTH_REQUIRED` 和 HTTP 401；已认证但无权操作他人会话返回 `ACCESS_DENIED` 和 HTTP 403。登录失败不泄露账号是否存在、是否停用或密码是否已设置。请求体、响应、日志和异常中不得出现密码、原始访问凭证、原始刷新凭证或密码散列。

健康检查 `GET /api/v1/health` 保持公开；其余已有或未来 `/api/v1/**` 接口默认要求认证，待功能开关、权限和数据范围拦截器接入后在已认证基础上继续收紧。

## 7. 验证范围

自动化测试至少覆盖：Flyway 建表和雪花主键；密码复杂度与 BCrypt 散列；系统管理员设置密码；启用平台账号登录；停用用户和错误密码被拒绝；刷新凭证轮换；退出、指定设备下线和一键下线立即使访问凭证失效；设备归属拒绝；健康检查公开且受保护认证接口拒绝匿名访问；`/me` 仅返回必要身份摘要。

本次仅在本地 H2/Flyway 测试环境验证。尚未在共享测试、预生产或生产 MySQL 执行迁移；正式环境必须补充空库与升级库迁移、HTTPS、密钥管理和安全测试。
