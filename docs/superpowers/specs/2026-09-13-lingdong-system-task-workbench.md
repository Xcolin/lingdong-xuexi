# 系统任务工作台与查询闭环（R04/R07）

当前 `audit` 模块已有系统任务状态机，组织、缓存、接口服务和敏感导出各自负责批准后的业务执行。直接暴露内部 `SystemTaskApplicationService.approve` 会跳过领域执行，不能作为统一审批接口。

本阶段先完成 Web 系统角色工作台：新增独立只读权限和分页查询，系统管理员只看本人提交任务，系统审核员看已提交任务与审批历史，不展示他人草稿。角色重叠时优先按审核员范围处理且不显示提交操作。列表和详情返回任务类型、状态、影响范围、申请人 ID、申请说明、审批人/时间/意见等现有审计字段；19 位 ID 为字符串。不返回业务原始 JSON 或接口凭据。

页面支持状态筛选、分页总数、详情、错误重试，并在进入、恢复焦点和打开详情前重新校验当前 Web 会话、系统角色和独立读取权限。管理员从工作台查询本人结果；审核员查看任务后进入有当前领域权限及功能能力的原处理页面，由原领域 API 完成审批与执行。没有已实现处理器的任务明确显示不可在该页执行，不伪装通过或生效。

新通用查询权限不会授予任何领域写权限。单笔查询应用同一行范围，越权统一不可见。查询服务实时复核启用账号、角色与动态权限；详情不可信任客户端传入申请人 ID。无需新增表；最新 V71，新增读取权限使用 V72，旧迁移不修改。

实施核对后限定当前可见类型为组织停用/移动/删除、缓存清除、接口服务变更和敏感导出；仅枚举而无处理入口的类型暂不纳入。列表、总数和详情使用相同类型及行范围过滤，同时要求领域功能开关与读取/审核权限。敏感导出还要求附件、模板和导出三个开关。领域关闭后不得从通用入口继续读取其标题、说明或数量。跳转只进入原领域页面，不承诺自动定位某个 taskId。

验证先证明新 HTTP 入口缺失，再验证系统管理员本人/他人、审核员草稿不可见/已提交可读、普通角色、停用账号、跨端和权限撤回。前端验证实际 total、分页、详情、失败清空、恢复焦点撤权和处理页面跳转。原领域执行测试继续作为审批执行依据。本阶段不宣称小程序系统角色登录、公告、全部业务载荷或通用功能开关管理完成。
