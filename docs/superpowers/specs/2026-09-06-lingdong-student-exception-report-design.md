# 灵动学习 V61 学生异常报备设计

## 1. 目标与需求追溯

V61 对应 `BRD-3.6-09`、教师端异常报备、异常报备台账和 WBS-07，落实教师针对授权班级学生提交出勤异常、学习状态异常、心态异常，机构管理员在授权组织范围内查看和处理，记录永久留存。

本专项不采集位置、不生成轨迹或考勤记录，不读取家庭任务、家庭积分、家长复盘和亲子隐私。复杂统计、Excel 导出、微信服务通知和完整站内消息中心不在 V61 实现，分别由后续报表与消息专项承接。

## 2. 方案选择

采用独立 `exceptionreport` 业务模块，不并入定位考勤模块，也不复用通用操作日志代替业务事实。异常报备主记录保存当前处理状态，只追加动作记录保存每次提交和处理事实；同一业务事务内写入本地消息事件，由未来消息分发器消费。

相比把报备并入考勤模块，该方案允许定位功能停用时继续处理学习和心态异常；相比只写通用审计日志，该方案能稳定支持机构后台台账、对象范围查询和永久成长档案。

## 3. 角色与数据范围

1. 教师可在 Web 和小程序创建报备，并查看本人当前授权班级范围内的报备；选择学生时必须同时存在活动教师班级关系和学生班级关系。
2. 机构管理员可在 Web 和小程序查看授权组织子树内的报备并标记已处理，不能越过组织管理员范围。
3. 系统管理员、系统审核员、家长和学生默认不获得异常报备操作权限；系统审核员不参与普通业务报备处理。
4. 教师班级关系或学生班级关系失效后，不再通过当前范围列表读取该班报备；历史记录仍永久保留，不级联删除。
5. 范围外报备统一按资源不存在处理，避免泄露学生或报备是否存在。

## 4. 状态与流程

异常类型固定为 `ATTENDANCE`、`LEARNING_STATUS`、`MENTAL_STATE`，对应出勤异常、学习状态异常、心态异常。报备状态固定为 `SUBMITTED` 和 `HANDLED`，只允许从已提交流转为已处理，不允许撤回、编辑、删除或重新打开。

教师提交时填写班级、学生、异常类型和事实描述。服务端重新校验教师、班级、学生三者当前关系，创建主记录和 `SUBMIT` 动作记录，并写入面向所属组织管理员的 `EXCEPTION_REPORT_SUBMITTED` 本地消息事件。

机构管理员处理时提交处理说明。服务端锁定主记录，校验组织范围和版本，将状态改为已处理，追加 `HANDLE` 动作记录，并写入面向报备教师的 `EXCEPTION_REPORT_HANDLED` 本地消息事件。重复处理返回状态冲突，不覆盖第一次处理事实。

## 5. 数据设计

1. `edu_exception_report`：报备主记录，包含学生、班级、报备教师、异常类型、事实描述、创建幂等键、当前状态、报备和处理时间、处理人、版本号。
2. `edu_exception_report_action`：不可变动作记录，包含报备、动作类型、操作人、前后状态、处理说明和发生时间；不提供更新或删除能力。
3. `msg_local_event`：本地消息事件出口，包含事件类型、业务类型、业务标识、接收对象类型、接收对象标识、内容摘要、状态和发生时间；V61 只写入 `PENDING` 事件，不声明已经送达。
4. 三张表主键均为应用层生成的 19 位雪花 `BIGINT`，不使用自增；外键使用限制删除，报备和处理记录永久保留。

## 6. 权限、开关与接口

新增默认启用的 `STUDENT_EXCEPTION_REPORT` 功能开关。关闭后 Web 和小程序入口全部隐藏，后端拒绝新建、列表、详情和处理请求，不产生新报备、动作记录或消息事件。

新增 `EXCEPTION_REPORT_CREATE`、`EXCEPTION_REPORT_READ`、`EXCEPTION_REPORT_HANDLE` 三项 `BOTH` 权限。教师获得创建和读取权限，机构管理员获得读取和处理权限。

接口如下：

1. `GET /api/v1/exception-reports/class-options`：教师返回本人活动班级，机构管理员返回组织范围内有效班级。
2. `GET /api/v1/exception-reports/student-options`：返回教师指定活动班级内的有效学生。
3. `GET /api/v1/exception-reports`：按班级、学生、异常类型、状态分页查询授权范围内报备。
4. `POST /api/v1/exception-reports`：教师创建报备。
5. `GET /api/v1/exception-reports/{id}`：查询报备详情和不可变动作历史。
6. `POST /api/v1/exception-reports/{id}/handle`：机构管理员标记已处理。

所有 19 位标识以字符串传输。创建请求使用教师加业务幂等键，相同请求重复提交返回同一结果；处理使用单向状态和版本号防止重复或并发覆盖。

## 7. 双端交互

Web 提供异常报备台账、筛选、详情、教师新建和机构管理员处理，不在 V61 提供导出和图表。小程序教师工作台增加“异常报备”入口，支持列表、新建和详情；机构工作台增加报备待处理入口，支持列表、详情和单项处理。

页面只展示学生姓名、脱敏账号、班级、异常类型、事实描述、状态和业务时间，不展示家庭任务、积分、家长信息或家庭复盘。按钮同时按公开能力、实时权限和对象状态失败关闭。

## 8. 异常与事务

1. 班级、学生或关系失效时拒绝创建，不保留半成品。
2. 无组织管理员接收人时仍保存报备和组织范围事件，不因通知出口不可投递而回滚业务事实。
3. 主记录、动作记录和本地消息事件在同一事务内写入；任一数据库写入失败整体回滚。
4. 处理并发冲突、重复幂等键、越权对象和功能关闭均返回明确业务错误，前端刷新当前事实。

## 9. 验收边界

后端测试覆盖迁移、19 位主键、类型和状态约束、幂等、并发、教师班级与学生对象范围、机构组织范围、不可变历史、消息事件和开关。Web 覆盖列表、新建、详情、处理和权限态；uni-app 覆盖教师与机构入口、直达拦截和单项操作，并通过 H5 与微信小程序构建。

真实 MySQL、Redis、微信、共享测试、预生产、生产和业务 UAT 不属于本地验收，不得因 H2 或 Mock 通过而标记为已执行。
