# 灵动学习 V31 任务图片打卡与统一附件访问设计

## 1. 目标与依据

V31 复用 V13 附件规则、文件元数据和业务关系，为学生任务打卡补齐统一上传、提交关联、学生回显、审核人预览和未关联文件删除。原始素材明确任务打卡支持文字、图片素材，通用附件格式包含 JPG/PNG，单文件最大 10 MB；V31 不新增音频、视频格式，不连接未确定的对象存储供应商。

## 2. 范围

### 2.1 本次实现

1. Flyway V31 为文件元数据固化模块、文件分类和内容摘要，种入任务打卡图片规则及附件上传/读取权限。
2. 新增供应商无关的文件内容存储端口和本地受控目录实现；数据库不保存文件二进制和本地绝对路径。
3. 新增统一附件上传、元数据读取、受控内容读取和未关联文件删除 API。
4. 学生打卡请求支持可空文字和最多 9 个文件标识，文字与附件至少一项非空。
5. 打卡事务校验文件状态、模块、分类、上传人和未被占用状态，再关联到新打卡记录；任一文件失败则打卡与全部关系一起回滚。
6. 学生任务详情和 Web 审核详情返回附件元数据，不返回存储键、磁盘路径或永久公开 URL。
7. uni-app 使用系统选图与统一上传 API，支持上传进度、失败重试、移除和图片预览；Web 审核抽屉使用带认证请求读取图片并预览。

### 2.2 明确不实现

1. 音频、视频、文档、Excel、PDF 的任务打卡入口。
2. 真实对象存储、CDN、微信临时素材、分片上传和断点续传。
3. 已提交或已审核打卡附件的物理删除；历史关系只读保留。
4. 附件规则 Web 管理页面、病毒扫描、内容识别和图片压缩。

## 3. 数据设计

`sys_file` 增加：

| 字段 | 规则 |
|---|---|
| `module_code` | 文件登记时固化，任务打卡固定为 `LEARNING_TASK_CHECKIN`。 |
| `file_category` | 文件登记时固化，V31 前端只使用 `IMAGE`。 |
| `content_sha256` | 上传完成时保存小写十六进制 SHA-256，用于内容完整性审计。 |

历史文件回填为 `LEGACY/UNCLASSIFIED`。任务附件继续使用 `sys_file_relation`，`module_code=LEARNING_TASK_CHECKIN`、`business_id=checkin_id`、`relation_type=EVIDENCE`、`visible_scope=TASK_PARTICIPANTS`。文件与同一打卡关系由既有唯一约束防重。

V31 种入图片规则：扩展名 `jpg/jpeg/png`，单文件最大 10 MB，单批最多 9 个，允许预览。所有表主键和基础数据标识均为 19 位雪花数字，不使用自增。

## 4. API 契约

| 方法与路径 | 权限 | 行为 |
|---|---|---|
| `POST /api/v1/attachments/uploads` | `ATTACHMENT_UPLOAD` | `multipart/form-data` 上传；V31 只接受任务打卡图片，返回文件元数据。 |
| `GET /api/v1/attachments/{fileId}` | `ATTACHMENT_READ` | 上传人或当前业务参与者读取元数据。 |
| `GET /api/v1/attachments/{fileId}/content` | `ATTACHMENT_READ` | 每次重新校验业务范围，响应受控内容流，不返回存储路径。 |
| `DELETE /api/v1/attachments/{fileId}` | `ATTACHMENT_UPLOAD` | 仅上传人删除尚无活动业务关系的文件；标记删除并清理内容。 |
| `POST /api/v1/task-assignments/{id}/check-ins` | 既有执行权限 | 请求增加 `fileIds`，文字与附件至少一项非空。 |

附件响应包含字符串 `id`、`originalName`、`contentType`、`sizeBytes`、`fileCategory`、`previewEnabled` 和内容端点；不包含 `storageKey`、服务器路径、桶名或凭证。

## 5. 权限与安全

1. 上传接口同时校验 `MINIAPP` 客户端、学生角色、`LEARNING_TASK_MANAGEMENT` 开关和任务附件模块白名单。
2. 文件名只用于显示和扩展名校验；实际存储键由服务端生成。所有本地路径通过根目录解析、标准化和前缀校验，禁止目录穿越。
3. 服务端不信任客户端 `Content-Type`，V31 同时校验扩展名、声明类型和文件头；JPG、PNG 文件头不符时拒绝。
4. 文件标识只能属于当前打卡提交用户，必须为 `AVAILABLE`、任务打卡模块、图片分类且没有活动业务关系。
5. 读取时上传人可读未关联文件；关联后仅任务所属学生本人和当前审核人可读。越权统一返回 404，避免文件标识枚举。
6. 删除只允许未关联文件；已提交、驳回或通过的历史附件不得物理删除。删除先标记元数据，再清理内容；内容清理失败记录错误并保留不可用状态。
7. 文件二进制、摘要、用户正文和真实路径不得写入业务日志。

## 6. 事务与失败处理

上传分为元数据登记、内容存储和完成确认。内容写入失败时不将文件标记为可用；打卡只能引用已完成文件。打卡关联与打卡记录、任务状态和事件处于同一数据库事务。文件内容不参与数据库事务，未关联文件由学生主动删除，后续运维清理任务再处理超时上传。

## 7. 前端边界

小程序详情最多选择 9 张图片，选择后逐文件上传并显示状态；提交成功清空文字和本地附件列表。Web 审核抽屉展示缩略图列表，点击后使用认证请求取得 Blob 并在预览弹窗中显示。Web 不提供学生上传，miniapp 不提供审核操作。

## 8. 验收

1. V1-V31 空库迁移成功，55 张既有表结构升级后仍保留历史，所有 19 位主键规则通过。
2. 非图片、伪造图片头、超过 10 MB、非学生客户端、他人文件、已关联文件和越权读取均被拒绝。
3. 纯文字、纯图片、文字加图片均可提交；空文字且无图片被拒绝；任一附件非法时不产生打卡或部分关系。
4. 学生和当前审核人可查看附件，其他学生、非当前审核人及无关系角色不可见。
5. Web、H5 和微信小程序构建通过，未把服务器路径、存储键或长期凭证打入前端产物。
