# 灵动学习 V32 任务待优化与顺延设计

## 1. 目标与需求依据

V32 实现原始素材 4.2.2.1、4.2.2.2、4.2.2.7 及 BRD 3.4.11：每日 23:59 将未提交打卡的进行中任务转为“待优化”，每日 00:00 将昨日待优化任务自动顺延到当日，并允许管理角色把待优化任务手动顺延到指定日期。全流程只奖不罚，不扣分、不降低积分系数，不使用负面文案。

本版本不实现复制昨日、任务模板、审核人失效转交、审核超时、周规则、节假日规则或消息投递。

## 2. 规则决策

1. 待优化扫描只处理基础状态为 `IN_PROGRESS`、截止时间已到且没有有效暂停的实例。待认领、待审核、已完成、免执行和有效暂停任务不处理。
2. 任务转为 `NEEDS_IMPROVEMENT` 后不产生积分、扣分或惩罚记录，只写中性任务事件。
3. 自动顺延每日 00:00 按上海时区处理前一业务日的待优化任务，目标日期固定为当日，目标状态重置为 `PENDING_CLAIM`。
4. 手动顺延只允许当前来源管理者操作。目标日期必须晚于当前业务日且不超过当前业务日后 7 天；学生端没有顺延入口。
5. 已手动顺延的实例不再被自动顺延。自动顺延后、学生尚未认领时，管理者可以再次手动指定日期，以最后一次手动顺延为准；学生已经认领、提交或完成后禁止覆盖。
6. 顺延不修改标题、难度、基础积分、时长、分类、标签、备注、来源、创建人和审核人。新目标任务定义关闭周期配置，防止顺延实例再次生成周期计划。
7. 顺延后的实例永久展示“隔夜迁移”标签。历史顺延记录保存原任务、目标任务、原日期、目标日期、模式、操作人和时间。
8. 原日期统计排除已迁移实例，目标日期统计包含迁移后的实例。成长复盘继续使用不可变快照和事实指纹；顺延发生后重算时追加版本，不改写旧版本。

## 3. 数据设计

### 3.1 `learn_task`

增加 `generation_type=NORMAL|DEFERRED` 和可空 `origin_task_id`。顺延时服务端克隆原任务定义及标签，生成 19 位雪花任务标识，状态直接为 `PUBLISHED`，计划日期改为目标日期，周期配置固定关闭。

### 3.2 `learn_task_assignment`

增加可空 `last_defer_type=AUTO|MANUAL`、`defer_count`、`overnight_migrated`、可空 `last_deferred_by_user_id` 和 `last_deferred_at`。顺延时保留实例标识，切换到克隆任务定义，更新计划日期与截止时间，清空认领/完成时间并重置为待认领。

### 3.3 `learn_task_defer_history`

字段为 19 位雪花主键、实例标识、源任务标识、目标任务标识、原计划日、目标计划日、顺延类型、可空操作人和发生时间。自动操作人为空，表示系统调度；手动操作人必须存在。历史只追加不更新。

### 3.4 事件约束

任务事件增加 `MARKED_NEEDS_IMPROVEMENT`，并允许系统事件的操作人为空。顺延审计由专用历史表承载，避免把未发生状态变化伪装为状态事件。

## 4. 事务与幂等

1. 单实例待优化处理锁定实例，条件更新 `IN_PROGRESS -> NEEDS_IMPROVEMENT`，终止已过期暂停并写事件，处于同一事务。
2. 单实例顺延锁定实例和当前任务定义，校验状态、来源范围和最新顺延模式；克隆任务、复制标签、更新实例、写历史处于同一事务。
3. 23:59 和 00:00 批处理均按实例标识游标分页，每个实例使用 `REQUIRES_NEW` 独立事务。单条失败记录摘要并继续，重复调度不重复迁移。
4. 自动顺延只查询前一日、待优化且最后顺延类型不是手动的实例；更新时再次锁定校验，防止与手动操作并发重复处理。
5. 自动顺延后手动改期复用同一实例，继续克隆当前任务定义并追加历史；旧克隆任务保留审计但不再关联活动实例。

## 5. API 与端侧

`POST /api/v1/managed-task-assignments/{id}/defer` 使用 Web 会话和 `TASK_ASSIGNMENT_DEFER` 权限，请求体为 `targetDate`。成功返回字符串实例标识、字符串目标任务标识、`status=PENDING_CLAIM`、目标日期、`deferType=MANUAL` 和 `overnightMigrated=true`。

Web 在可管理的待优化任务提供“顺延”操作和 1 至 7 天日期选择；自动顺延且尚未认领的任务仍可改期。小程序只显示“隔夜迁移”灰色来源标签和新的计划日期，不提供顺延按钮。

## 6. 安全与验收

1. 后端先校验功能开关、Web 客户端、动态权限，再校验家庭主关系、教师创建人或机构组织数据范围；越权统一返回 404。
2. 客户端不能提交学生、源任务、积分、来源、审核人、顺延类型或历史字段。
3. Flyway 从 V1 连续执行到 V32；新增表主键显式 `BIGINT`、禁止自增，初始化权限标识使用 19 位数字。
4. 自动化覆盖准确时点、有效暂停排除、重复扫描、自动顺延、手动优先、自动后手动、7 天边界、越权、功能停用、任务配置/标签复制、统计日期和积分不变。
