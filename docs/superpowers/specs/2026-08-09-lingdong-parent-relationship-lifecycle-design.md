# 灵动伴随 V38 家长关系生命周期设计

## 1. 目标与依据

V38 完成副家长邀请、主动确认、主副家长唯一性、主家长解除副家长关系、主家长自行解绑后的自动晋升、监护权转移和关系变更审计。设计只依据原始素材与 BRD 已确认规则：首次绑定者为主家长；一个学生最多同时存在一个主家长和一个副家长；副家长只读；主家长解绑时最早绑定的副家长晋升；无副家长时家庭管理暂停；监护权转移由原主家长发起、新主家长确认，原主家长降级为副家长。

本版本同时落实用户确认：被邀请手机号未注册时，持有人凭 5 分钟验证码主动确认后复用 V36 规则原子创建家长账号并绑定；已注册时绑定既有启用家长账号。真实短信与站内消息投递仍由后续批准环境验证，不伪造外部发送成功。

## 2. 方案比较与选择

### 方案一：复用当前关系表并增加邀请与审计表（采用）

`edu_parent_student` 继续表示当前有效关系，新增专用邀请表和不可变关系变更日志。状态变更对当前查询简单，现有主家长权限判断改动可控，历史由日志完整保存。

### 方案二：仅更新当前关系表

实现文件少，但解绑、晋升、转移会覆盖历史，无法回答谁在何时以何种方式变更关系，不满足审计和纠纷追溯要求，因此不采用。

### 方案三：所有关系都改为事件溯源

历史能力最强，但会迫使现有任务、积分、奖励和复盘查询全部重建投影，超出本需求边界，因此不采用。

## 3. 范围与非范围

V38 范围：

1. 主家长邀请一个副家长，验证码和邀请均为 5 分钟有效。
2. 被邀请人接受或拒绝，接受必须证明目标手机号控制权并接受当前协议。
3. 主家长解除副家长关系；副家长不能主动解绑。
4. 主家长解除自己的关系；存在副家长时自动晋升，不存在时进入无主家长状态。
5. 原主家长发起监护权转移；目标家长确认后成为主家长，原主家长降级为副家长。
6. 家庭待审核任务在新主家长产生时转交；无主家长时旧审核人失去操作权，任务保持待审核而不自动通过或删除。
7. 副家长可读取绑定学生的学生档案、家庭任务结果、积分、奖励和成长复盘，所有写操作仍要求活动主家长。
8. Web 与 uni-app 分别实现适用的邀请、确认、关系查看和解绑操作，两个应用不共享页面代码与会话。

V38 非范围：真实短信/站内消息投递、手机号换绑、家长账号注销、学生注销、转班转学、学生微信、关系纠纷人工仲裁。上述功能继续保留在主计划后续任务中。

## 4. 数据模型

### 4.1 当前关系

复用 `edu_parent_student`。`relation_role` 扩为 32 位并取 `PRIMARY_GUARDIAN` 或 `SECONDARY_GUARDIAN`；`status` 取 `ACTIVE` 或 `UNBOUND`。`primary_scope_key` 扩为 32 位：活动主家长使用 `PRIMARY`，活动副家长使用 `SECONDARY`，关闭关系使用 `CLOSED:<关系雪花标识>`。现有 `(student_id, primary_scope_key)` 唯一约束保证每个学生最多一个活动主家长和一个活动副家长。

同一家长与学生历史上重新绑定时复用受 `(parent_user_id, student_id)` 唯一约束保护的原关系行，重新设置角色、状态、范围键和 `bound_at`；完整历史不依赖当前行，而由变更日志保存。

### 4.2 关系邀请

新增 `edu_parent_relationship_invitation`：

- 主键 `id BIGINT` 由应用层生成 19 位雪花标识。
- `student_id`、`inviter_user_id`、可空 `invitee_user_id` 和目标手机号。
- `invitation_type` 为 `SECONDARY_BIND` 或 `PRIMARY_TRANSFER`。
- `status` 为 `PENDING`、`ACCEPTED`、`REJECTED`、`EXPIRED` 或 `CANCELLED`。
- `pending_scope_key` 在待处理时为 `PENDING`，关闭后为 `CLOSED:<邀请雪花标识>`；按学生、邀请类型和范围键唯一，同一学生同类邀请最多一个待处理。
- `expires_at` 固定为创建后 5 分钟；保存响应人和响应时间。

手机号按现有用户表口径保存，但普通列表和日志只允许脱敏展示。验证码、验证码摘要、微信标识、访问令牌和原始会话令牌不进入邀请表。

### 4.3 不可变审计

新增 `edu_parent_relationship_change_log`，记录学生、关系、操作类型、操作人、原家长/新家长、变更前后角色、关联邀请和发生时间。操作类型固定为 `BIND_SECONDARY`、`UNBIND_SECONDARY`、`UNBIND_PRIMARY_PROMOTE`、`UNBIND_PRIMARY_ORPHAN`、`TRANSFER_PRIMARY` 和 `REBIND_PRIMARY`。日志只新增，不更新和删除。

## 5. 状态与事务

### 5.1 副家长邀请

1. 活动主家长从 Web 或小程序选择自己的学生并输入目标手机号。
2. 服务端锁定学生全部家长关系，校验功能启用、操作者为活动主家长、目标不是本人、学生尚无活动副家长、目标家长未达到最多 10 名活动学生。
3. 关闭同类过期邀请，创建 5 分钟待处理邀请并发送 `SECONDARY_PARENT_BIND` 验证码。
4. 创建响应只返回邀请标识、脱敏手机号和到期时间，不返回验证码。
5. 被邀请人提交邀请标识、手机号、验证码、协议版本和设备信息；服务端原子消费验证码并锁定邀请。
6. 手机号无账号时复用 V36 建立 `FAMILY` 用户、`PARENT` 角色、家长档案和协议事实；已有账号必须启用且拥有家长角色。
7. 插入或重新激活 `SECONDARY_GUARDIAN` 关系，关闭邀请、写入审计并创建独立家长会话。

拒绝邀请也必须校验目标手机号验证码，只关闭邀请，不创建账号和关系。

### 5.2 解除关系与自动晋升

主家长解除副家长时锁定全部关系，将目标关系改为 `UNBOUND` 和关闭范围键，写审计。副家长即时失去所有学生数据范围，历史业务数据仍归学生所有。

主家长解除自己时：

- 存在活动副家长：先关闭原主关系，再按最早 `bound_at`、相同时间按关系 `id` 升序选定副家长并改为主家长；转交该学生全部家庭来源待审核任务并写转交记录。
- 不存在活动副家长：关闭原主关系，不删除学生或历史数据；所有依赖活动主家长的家庭写操作自然失败，待审核任务保持原状态但原家长无权处理。

### 5.3 监护权转移

原主家长创建 `PRIMARY_TRANSFER` 邀请。目标确认后在同一事务中锁定关系：目标现有副关系先释放 `SECONDARY` 范围键，原主关系降为副关系，目标关系插入、重新激活或升级为主关系。学生始终保持一个活动主家长；家庭待审核任务同步转交目标主家长。目标拒绝或邀请过期不改变当前关系。

## 6. 权限与端侧边界

新增后端功能开关 `PARENT_RELATIONSHIP_MANAGEMENT`，默认停用。停用后 Web、H5 和微信小程序隐藏全部关系管理入口，后端创建、响应、解绑和转移接口全部拒绝；只读历史关系仍按数据权限查询。

新增 Web/小程序共用业务权限：关系查询、邀请副家长、响应邀请、解除副家长、主家长自行解绑、发起监护权转移。RBAC 只提供粗粒度准入，服务端必须再次验证活动主/副关系和学生对象范围。

副家长只读通过查询服务显式支持 `existsActiveByParentAndStudent`；创建任务、审核、积分纠错、奖励配置/审批/核销、复盘补录、登录码重置和二维码签发继续使用 `existsActivePrimaryByParentAndStudent`。前端隐藏按钮不能替代后端判断。

## 7. API 边界

- `GET /api/v1/parent-relationships/students`：按当前活动关系返回可管理或只读的学生及关系角色，不依赖学习任务功能开关。
- `GET /api/v1/students/{studentId}/parent-relationships`：活动关系和脱敏家长信息。
- `POST /api/v1/students/{studentId}/secondary-parent-invitations`：主家长创建副家长邀请。
- `POST /api/v1/parent-relationship-invitations/{invitationId}/acceptance`：公开验证码确认，可创建家长账号并返回 `WEB` 或 `MINIAPP` 会话。
- `POST /api/v1/parent-relationship-invitations/{invitationId}/rejection`：验证码拒绝，不创建账号。
- `DELETE /api/v1/students/{studentId}/secondary-parent-relationships/{parentUserId}`：主家长解除副家长。
- `DELETE /api/v1/students/{studentId}/primary-parent-relationship`：主家长解除自己并触发晋升或无主状态。
- `POST /api/v1/students/{studentId}/primary-transfer-invitations`：原主家长发起监护权转移。

所有雪花标识以 JSON 字符串传输。公开响应不回显完整手机号、验证码、密码、令牌摘要或关系表内部范围键。

## 8. 异常与并发

错误验证码、手机号不匹配、未知/已关闭邀请统一返回中性失败；过期返回明确过期状态。关系不属于当前用户时按资源不存在处理，避免枚举。数据库唯一约束和行锁共同防止两个副家长同时接受、两个主家长同时产生、解绑与转移并发覆盖。验证码成功消费后即使后续业务冲突也不恢复，避免重放。

关系变更事务任一步失败时，关系、邀请、审计和任务转交整体回滚；Redis 验证码消费不回滚。真实通知失败不能伪造绑定成功，创建邀请时发送失败则事务失败并关闭本次流程。

## 9. 测试与验收

Flyway 测试验证 V1-V38 连续迁移、66 张显式非自增主键表、两个新表、关系范围键扩容、约束、权限和默认停用开关。后端覆盖未注册/已注册副家长、主动接受/拒绝、5 分钟过期、最多两个家长、每家长最多 10 名学生、并发接受、主家长解除副家长、自动晋升、无主状态、监护权转移、待审核任务转交、功能停用和越权。

Web 与 uni-app 分别覆盖入口、邀请、确认、关系展示、二次确认、只读副家长和功能停用直达。全量验收继续使用本地 H2、测试短信适配器和本地前端构建，不连接远程 MySQL、Redis、短信、微信、共享测试、预生产或生产环境。

2026-08-09 本地验收结果：后端 76 个测试套件、274 项测试全部通过；Web 14 个测试文件、50 项测试全部通过且生产构建成功；uni-app 类型检查、H5 构建和微信小程序构建成功。Flyway 从空库连续执行 V1-V38，66 张主键表均为显式非自增 `BIGINT id`；敏感字段日志扫描为零命中。
