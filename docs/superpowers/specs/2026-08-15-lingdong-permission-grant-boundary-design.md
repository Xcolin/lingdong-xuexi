# 灵动学习权限授权边界设计

**日期**：2026-08-15  
**状态**：进入实施  
**依据**：业务需求说明书 `BRD-3.1-04`、`BRD-3.1-05`、`BRD-3.1-11`，总计划 WBS-05。

## 1. 目标

在现有动态 RBAC、用户级 `ALLOW/DENY` 和组织数据范围基础上，补齐角色明确禁止、授权撤销、用户补充权限边界和 Web 管理闭环。权限变更后下一次请求实时生效，不依赖重新登录；功能开关仍优先于权限结果。

## 2. 当前差距

1. `sys_role_permission` 只能表达允许，无法落实“多个角色中任一明确禁止即拒绝”。
2. 角色权限只能新增，不能查询效果、改为禁止或撤销。
3. 用户权限虽可配置 `ALLOW/DENY`，但用户补充允许可赋给无任何活动角色的用户，不符合“在角色权限基础上补充”的要求。
4. Web 只能授予角色权限，不能查看和维护角色禁止权限、用户补充允许或用户限制权限。
5. 权限变更审计属于 `BRD-3.1-12`，本次不混入，避免把未完成审计错误标记为完成。

## 3. 权限计算顺序

1. 功能开关由业务入口先校验，关闭即拒绝。
2. 用户账号、权限目录和角色必须处于启用状态。
3. 任一活动角色对权限配置 `DENY`，立即拒绝。
4. 用户显式 `DENY`，立即拒绝。
5. 任一活动角色配置 `ALLOW`，允许进入功能权限层。
6. 用户显式 `ALLOW` 仅在用户至少有一个活动角色时生效。
7. 功能权限允许后，业务服务仍必须计算角色数据范围、用户组织范围和组织管理员范围交集；用户 `ALLOW` 不能扩大对象或组织范围。

角色禁止与用户禁止均属于明确禁止，不因另一个角色允许或用户补充允许而被覆盖。

## 4. 授权管理规则

1. 只有活动系统管理员可维护角色和用户权限，系统审核员、机构管理员及其他角色不能进入权限管理接口。
2. 系统管理员的可授权功能范围为系统内启用的权限目录；该角色负责全量权限运维，但不因此自动获得日常业务操作权限。
3. 角色权限支持 `ALLOW`、`DENY` 和撤销。撤销表示删除该角色的显式配置，不等同于禁止。
4. 用户权限支持 `ALLOW`、`DENY` 和撤销。为用户配置 `ALLOW` 时，目标用户必须至少具有一个活动角色；`DENY` 可用于立即收缩已有角色权限。
5. 用户补充允许只改变功能操作判断，不创建角色、不创建组织关系、不修改数据范围。目标业务接口仍按既有后端范围查询执行交集约束。
6. 内置角色和自定义角色均可维护权限效果；内置角色不能删除的既有规则不变。
7. 重复提交相同效果按幂等成功处理；撤销不存在的显式配置按幂等成功处理。

## 5. 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /api/v1/roles/{roleId}/permissions` | 查询角色显式权限及 `ALLOW/DENY` 效果。 |
| `PUT /api/v1/roles/{roleId}/permissions/{permissionId}` | 新增或更新角色权限效果。 |
| `DELETE /api/v1/roles/{roleId}/permissions/{permissionId}` | 撤销角色显式权限配置。 |
| `GET /api/v1/users/{userId}/permissions` | 查询用户显式补充或限制权限。 |
| `PUT /api/v1/users/{userId}/permissions/{permissionId}` | 复用现有路径，幂等配置用户 `ALLOW/DENY`。 |
| `DELETE /api/v1/users/{userId}/permissions/{permissionId}` | 撤销用户显式权限配置。 |

现有 `POST /api/v1/roles/{roleId}/permissions` 保留为向后兼容的 `ALLOW` 操作，Web 改用资源化 `PUT/DELETE` 接口。全部 19 位标识按 JSON 字符串返回。

## 6. 数据库与迁移

V49 不新增表：

1. 为 `sys_role_permission` 增加非空 `effect` 字段，默认并回填 `ALLOW`。
2. 增加 `ALLOW/DENY` 检查约束；现有唯一键继续保证每个角色对每项权限只有一个显式效果。
3. V49 不修改 `V1-V48`，不使用自增列，不新增非雪花基础标识。

## 7. Web 边界

Web 角色与权限页增加角色权限和用户权限两个管理视图，使用角色、用户和权限目录选择器展示当前显式效果，并提供允许、禁止和撤销操作。界面只向系统管理员开放；无权限、账号停用或服务端拒绝时不保留伪成功状态。小程序不提供平台 IAM 管理入口。

## 8. 验收

1. 角色 `DENY` 覆盖同用户其他角色 `ALLOW` 和用户 `ALLOW`。
2. 用户 `DENY` 覆盖角色 `ALLOW`；撤销用户禁止后恢复按角色计算。
3. 无活动角色用户不能通过用户补充 `ALLOW` 获得访问；用户 `DENY` 仍可配置。
4. 角色/用户权限新增、改效和撤销幂等，停用角色和停用权限不产生允许结果。
5. Web 可查询和维护显式效果，功能入口和后端接口均只允许系统管理员。
6. 后端全量测试、Web 全量测试与构建、uni-app 类型检查及双目标构建全部通过；不连接远程 MySQL、Redis、共享测试、预生产或生产环境。
