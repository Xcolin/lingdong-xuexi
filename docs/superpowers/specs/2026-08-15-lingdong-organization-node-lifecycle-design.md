# 灵动学习组织节点生命周期详细设计

## 1. 设计目标

本设计对应 `BRD-3.1-07`、`BRD-3.1-11`、`BRD-3.1-12` 以及总计划 WBS-05 的组织节点编辑、启停、移动和受控删除能力。V47 在现有区域、学校树新增能力上补齐节点生命周期，不扩展班级业务字段、地理考勤或通用数据范围组件。

本次必须满足：

1. 只有系统管理员可以直接编辑组织名称、排序和重新启用组织。
2. 停用、移动和删除属于高风险组织变更，只能由系统管理员发起，且只能由系统审核员审批。
3. 系统审核员不能创建、编辑或提交组织变更，也不能审批非系统管理员提交的任务。
4. 父节点停用后，下级节点保留自身状态和历史数据，但整个子树不得产生新业务。
5. 组织移动必须原子更新目标节点及全部后代的路径和有效状态，禁止循环层级。
6. 组织删除只允许没有子节点、没有任何现存业务或权限引用的空叶子节点；其他节点只能停用。
7. 组织变更、审批结果和生效结果必须保留不可变审计。
8. V47 新增表主键和基础权限标识全部使用应用层生成的 19 位雪花 `BIGINT`，禁止自增。

## 2. 范围边界

### 2.1 本次实现

- 组织节点名称、排序的乐观锁编辑。
- 已停用节点的直接重新启用。
- 停用、移动、删除变更申请、提交、审批、驳回和生效。
- 组织树显式状态、有效状态和版本号展示。
- 组织有效性统一校验，覆盖当前机构管理员、学生机构关系、教师班级、机构/教师任务和机构侧账号安全操作的新业务入口。
- Web 组织树维护与系统审核员组织变更待办。
- `ORGANIZATION_MANAGEMENT` 全局功能开关，默认启用；停用后菜单、按钮和直达接口拒绝。

### 2.2 本次不实现

- 组织类型编辑、停用和删除。
- 班级学年、学期、容量、班主任等班级业务字段。
- 机构管理员自行调整组织树。
- 通用角色数据范围组件和组织管理员授权上限。
- 地理围栏、考勤、轨迹或地图代码。
- 共享测试、预生产、生产数据库迁移及真实环境联调。

## 3. 方案选择

采用“低风险直接编辑，高风险系统任务审批”的方案。

- 名称、排序不改变数据边界，由系统管理员直接修改并写审计。
- 重新启用不扩大原有树结构，由系统管理员直接执行，但必须重新校验父级并重算子树有效状态。
- 停用会阻断业务，移动会改变组织数据范围，删除不可逆，因此必须通过系统任务审批。
- 不采用全部直接修改方案，因为这违反高风险组织节点变更的审批要求。
- 不采用只做编辑、长期推迟高风险操作方案，因为无法完成 WBS-05 的组织生命周期闭环。

## 4. 数据模型

### 4.1 `sys_organization` 扩展

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `effective_status` | `VARCHAR(16)` | 综合自身和全部祖先后的有效状态，值为 `ENABLED` 或 `DISABLED`。 |
| `version_no` | `INT` | 乐观锁版本，从 1 开始，每次有效修改递增。 |

`status` 继续表示节点自身状态。`effective_status` 是业务写入准入事实：节点自身启用但祖先停用时，`status=ENABLED`、`effective_status=DISABLED`。

### 4.2 `sys_organization_change`

每个高风险变更对应一个系统任务：

| 字段 | 说明 |
|---|---|
| `id` | 19 位雪花主键。 |
| `task_id` | 唯一关联 `sys_system_task`。 |
| `organization_id` | 目标组织标识，只保存数值，不建立外键，以允许受控删除后保留申请。 |
| `change_type` | `DISABLE`、`MOVE`、`DELETE`。 |
| `target_parent_id` | 移动目标父节点，其他类型为空。 |
| `expected_version` | 发起时组织版本，审批生效时再次比较。 |
| `organization_code_snapshot` | 组织编码快照。 |
| `organization_name_snapshot` | 组织名称快照。 |
| `from_parent_id_snapshot` | 原父节点快照。 |
| `reason` | 1 至 500 字变更原因。 |
| `execution_status` | `PENDING`、`APPLIED`、`FAILED`，与系统任务审批状态分离。 |
| `failure_reason` | 生效失败的中性原因，最多 500 字，不记录 SQL 或敏感数据。 |
| `created_at` | 创建时间。 |

### 4.3 `sys_organization_change_audit`

不可变记录直接编辑、重新启用、高风险申请、批准生效、驳回和执行失败。保存事件类型、目标组织标识、变更类型、前后父节点、前后状态、操作人、系统任务标识、原因和发生时间；不保存访问令牌、手机号或其他个人敏感信息。

### 4.4 权限与开关

新增 Web 权限：

- `ORG_NODE_UPDATE`：系统管理员直接编辑和重新启用。
- `ORG_NODE_CHANGE_SUBMIT`：系统管理员发起并提交高风险变更。
- `ORG_NODE_CHANGE_REVIEW`：系统审核员查看、批准或驳回组织变更。

新增全局功能开关 `ORGANIZATION_MANAGEMENT`，默认 `ENABLED`。开关关闭后 Web 隐藏组织管理和审核入口，后端管理查询及写接口返回 `FEATURE_DISABLED`；已存在组织仍可作为历史数据关联查询，但不能通过组织管理接口变更。

## 5. 状态与事务

### 5.1 直接编辑

系统管理员提交 `name`、`sortOrder`、`versionNo`。服务端锁定节点，校验版本、名称长度和同级名称唯一，更新后版本加一并写 `DIRECT_UPDATE` 审计。编码、类型和父节点不能通过此接口修改。

### 5.2 重新启用

系统管理员提交版本号。服务端锁定节点，节点自身状态改为 `ENABLED`；然后按当前祖先有效状态重算节点和全部后代的 `effective_status`。子节点自身为 `DISABLED` 时仍保持有效停用。整个过程在一个事务内完成并写 `ENABLE` 审计。

### 5.3 高风险变更申请

系统管理员选择停用、移动或删除并填写原因：

1. 锁定目标节点并做初始可行性校验。
2. 创建对应 `SystemTaskType.ORGANIZATION_DISABLE` 或新增的组织移动、删除任务类型。
3. 写入组织变更快照。
4. 同事务将系统任务从草稿提交为 `PENDING_REVIEW`。
5. 申请阶段不修改组织树。

同一组织存在系统任务状态为 `DRAFT`、`PENDING_REVIEW`，或任务为 `APPROVED` 且执行状态仍为 `PENDING` 的变更时，禁止重复发起。执行状态为 `FAILED` 的旧申请不阻塞重新发起。

### 5.4 审批与生效

系统审核员审批时先由现有系统任务状态机确认角色、待审核状态和提交人边界。批准后在独立事务内重新锁定组织并比较 `expected_version`：

- `DISABLE`：将自身状态和有效状态改为 `DISABLED`，将全部后代有效状态改为 `DISABLED`，保留后代自身状态。
- `MOVE`：禁止移动到自身或后代；目标父节点必须存在且有效启用；同级名称不得冲突；原子替换目标节点及后代路径、父级范围键和有效状态。
- `DELETE`：目标必须仍为同版本空叶子；显式检查 `sys_user_role`、`sys_organization_admin`、`sys_role_data_scope`、`sys_user_organization`、`sys_feature_toggle`、`edu_student_organization`、`edu_parent_binding_invitation`、`edu_teacher_class`、`learn_task`、`learn_task_assignment`、`growth_point_ledger`、`edu_student_organization_change`、`auth_parent_mobile_manual_recovery` 和 `auth_student_account_cancellation` 的当前引用，存在任一引用即拒绝；数据库外键继续作为最终防线。删除后保留变更快照和审计。

生效成功后变更执行状态改为 `APPLIED`，系统任务转为 `EFFECTIVE`。若批准后的业务执行因版本变化或引用变化失败，业务事务回滚，系统任务保持 `APPROVED`，随后以独立事务把变更执行状态改为 `FAILED` 并写失败审计；系统管理员修正数据后必须重新发起，不能复用旧快照。

驳回必须填写审批意见，系统任务转为 `REJECTED`，组织树不变化并写 `REJECT` 审计。

## 6. 组织有效性

V47 使用持久化 `effective_status`，避免每个业务查询重复递归祖先。

所有新增业务必须同时满足目标组织 `status=ENABLED` 且 `effective_status=ENABLED`。当前需要接入的入口包括：

- 组织节点和下级节点创建。
- 组织管理员、用户组织和角色组织范围配置。
- 学生创建、家长邀请、分班、转班和机构关系查询候选。
- 教师班级绑定。
- 机构任务、教师任务的来源组织、目标组织和审核人候选。
- 机构小程序身份持续校验。
- 机构人工换号和学生注销候选范围。

历史任务、积分、关系和审计查询不因有效停用而删除；仅新增、编辑、审核、分配等操作被拒绝。

## 7. API

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `PATCH /api/v1/organizations/{id}` | `ORG_NODE_UPDATE` | 修改名称和排序。 |
| `POST /api/v1/organizations/{id}/enable` | `ORG_NODE_UPDATE` | 重新启用并重算子树有效状态。 |
| `POST /api/v1/organization-changes` | `ORG_NODE_CHANGE_SUBMIT` | 创建并提交停用、移动或删除申请。 |
| `GET /api/v1/organization-changes` | 提交或审核权限 | 系统管理员查看本人申请，审核员查看待审核及已处理申请。 |
| `POST /api/v1/organization-changes/{taskId}/approve` | `ORG_NODE_CHANGE_REVIEW` | 批准并执行。 |
| `POST /api/v1/organization-changes/{taskId}/reject` | `ORG_NODE_CHANGE_REVIEW` | 驳回，意见必填。 |

所有雪花标识以 JSON 字符串传输。越权统一返回 `403`；资源不存在或无权感知返回 `404`；版本、重复申请、循环移动、引用阻止删除和状态冲突返回 `409`；开关关闭返回 `FEATURE_DISABLED`。

## 8. Web 交互

Web 组织管理页按角色显示：

- 系统管理员：组织树、节点详情、编辑、启用、停用申请、移动申请和删除申请。
- 系统审核员：仅显示组织变更审核列表、申请快照、影响节点和批准/驳回操作。
- 其他角色：不显示全局组织管理入口。

树节点展示自身状态和有效状态。因上级停用而不可用时显示“上级已停用”，不误写成节点自身停用。停用、移动和删除使用独立确认弹窗；删除按钮只表示提交删除申请，服务端仍在审批生效时复核引用。

小程序不增加全局组织树管理页面。机构小程序只消费有效组织范围，父节点停用后已有机构会话在下一次鉴权时失效。

## 9. 测试与验收

1. Flyway 从空库连续执行 V1-V47；新增表及权限主键均为 19 位雪花 `BIGINT`，无自增列。
2. 直接编辑覆盖同级重名、版本冲突、编码和类型不可改。
3. 停用覆盖申请不立即生效、只有审核员可审批、子树有效停用和历史自身状态保留。
4. 移动覆盖循环拒绝、停用目标父级拒绝、同级重名拒绝、路径与有效状态批量更新、审批前版本变化拒绝。
5. 删除覆盖非叶子拒绝、全部当前引用表阻止、空叶子删除和审计留存。
6. 组织有效性覆盖学生、教师、任务、机构管理员和机构小程序的新业务拒绝。
7. Web 覆盖角色入口、状态展示、申请、审批、驳回、功能停用和窄屏布局。
8. 运行后端全量测试、Web 全量测试与构建、uni-app 类型检查与双端构建，并扫描定位 API、敏感信息、自增主键和未完成清单。

## 10. 已确认结论

- V47 不对共享测试、预生产或生产数据库执行迁移。
- V47 不引入定位、地图或轨迹代码。
- V47 不物理删除存在任何引用的组织节点。
- V47 不允许系统审核员提交组织变更，也不允许系统管理员代替审核员批准。
- V47 不通过级联覆盖子节点自身状态，而是独立维护有效状态。
