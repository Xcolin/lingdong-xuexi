# 灵动学习学生微信授权登录详细设计

## 1. 设计目标

在不允许学生自主注册、不开放 Web 学生登录入口的前提下，为已由家长或机构创建且已关联主监护人的学生提供小程序微信快捷登录。首次授权必须同时校验 8 位学生账号、4 位学生登录码和发送至当前主监护人手机号的 6 位短信验证码；绑定后可使用同一微信身份快捷登录。

本次 V46 只包含学生自助绑定、学生微信快捷登录和主监护人解绑。主监护人手机号不可用时的机构人工处理属于高风险身份恢复，后续以独立功能开关、权限、审批和审计任务建设，不纳入 V46。

## 2. 原始需求约束

- 学生只能在小程序登录，不新增 Web 学生登录入口。
- 学生账号只能由家长或机构创建，微信授权不得创建学生、用户或家长关系。
- 只有存在有效主监护人关系的学生可以自助绑定微信。
- 首次绑定采用学生登录码和主监护人短信验证码双重验证。
- 一个学生账号只能绑定一个微信身份，一个微信身份只能绑定一个学生账号。
- 解绑只能由当前主监护人在家长侧学生账号管理功能发起，并进行明确二次确认。
- 功能由后台统一开关控制；停用后前端入口隐藏，后端接口同时拒绝调用。

8 位学生账号是本设计补充的必要定位字段。4 位登录码不具备全局唯一性，若不提交学生账号，服务端无法在不泄露或猜测学生身份的前提下确定校验对象。

## 3. 应用边界

### 3.1 小程序

- 学生登录页在 `mp-weixin` 且功能启用时显示“微信登录”。
- H5 构建不显示、也不调用微信授权入口。
- 首次微信授权未绑定时进入绑定表单，输入 8 位学生账号和 4 位登录码。
- 学生身份校验通过后，服务端只向当前主监护人账号保存的手机号发送验证码。
- 输入 6 位短信验证码后完成绑定并建立学生小程序会话。
- 微信授权或绑定失败时保留账号登录能力，不改变学生原有登录码。
- 家长端新增“学生微信绑定”页面，列出当前家长具备主监护人关系的学生及绑定状态，仅已绑定学生可解绑。

### 3.2 Web

- 不新增学生登录入口。
- 在既有“学生登录”管理页显示微信绑定状态，并向当前主监护人提供解绑操作。
- 机构管理员即使拥有学生读取权限，也不能执行学生微信解绑。

## 4. 数据模型

### 4.1 当前绑定表 `auth_student_wechat_binding`

- 主键 `id`：应用层雪花算法生成的 19 位数字，数据库类型 `BIGINT`。
- `student_id`、`student_user_id`：分别关联学生档案和学生用户。
- `app_id`、`open_id`、`union_id`：由服务端微信 `code2Session` 交换获得，客户端不能提交。
- `bound_at`、`last_login_at`：记录当前绑定建立时间和最近快捷登录时间。
- `student_id`、`student_user_id`、`(app_id, open_id)` 分别建立唯一约束。
- 表只保存当前有效绑定；解绑后删除当前绑定，历史由不可变审计表保留。

### 4.2 绑定变更审计表 `auth_student_wechat_binding_audit`

- 主键 `id`：应用层雪花算法生成的 19 位数字。
- 记录 `binding_id`、学生、学生用户、事件类型 `BIND/UNBIND`、操作者用户、客户端和发生时间。
- 自助绑定的操作者记为已完成双重校验的学生用户；解绑操作者记为当前主监护人用户。
- 不保存手机号、短信验证码、`openid`、`unionid`、会话令牌等敏感明文。
- 解绑审计不对已删除绑定建立外键，避免破坏历史记录。

### 4.3 功能和权限

- 功能开关：`STUDENT_WECHAT_AUTH`，内置、全局、默认停用。
- 权限：`STUDENT_WECHAT_UNBIND`，客户端范围 `BOTH`，只授予内置家长角色。
- 自助绑定和快捷登录是公开预认证接口，不使用 RBAC，但必须经过功能开关、客户端约束、微信身份交换、一次性票据和双重验证。

## 5. 安全状态机

### 5.1 微信身份交换

1. 小程序调用 `wx.login` 获取短期临时凭证。
2. 客户端提交临时凭证和设备信息到学生微信会话交换接口。
3. 服务端检查功能开关和微信集成可用性，再调用 `code2Session`。
4. 已存在绑定时，服务端校验学生与用户均启用，更新最近登录时间并创建 `MINIAPP` 学生会话。
5. 未绑定时，服务端签发只在 Redis 保存摘要的 5 分钟一次性微信绑定票据。

### 5.2 学生身份校验和短信发送

1. 客户端提交微信绑定票据、8 位学生账号、4 位登录码和设备标识。
2. 服务端原子消费微信绑定票据，复用学生登录码失败计数、图形验证码和锁定规则，但本步骤不创建会话。
3. 服务端查询学生有效主监护人关系，并校验主监护人用户为启用家长且手机号有效。
4. 服务端使用独立用途 `STUDENT_WECHAT_BIND` 发送短信，客户端不能指定手机号。
5. 服务端签发第二张 5 分钟一次性验证票据，票据绑定微信身份、学生、学生用户、主监护人和设备。
6. 对外响应只返回掩码手机号、短信过期时间、重发等待时间和验证票据。

### 5.3 最终绑定

1. 客户端提交验证票据、短信验证码和相同设备信息。
2. 服务端原子消费验证票据并锁定学生、学生用户、学生凭据和家长关系。
3. 服务端重新校验学生状态、当前主监护人、主监护人手机号和设备绑定信息，防止校验后关系或手机号变化。
4. 服务端消费 `STUDENT_WECHAT_BIND` 短信验证码。
5. 服务端在数据库唯一约束保护下写入当前绑定和不可变 `BIND` 审计，再创建学生小程序会话。

### 5.4 主监护人解绑

1. Web 或小程序家长端提交学生 ID 和固定确认语句“确认解绑学生微信”。
2. 服务端检查功能开关、`STUDENT_WECHAT_UNBIND` 权限和当前用户身份。
3. 服务端锁定并确认当前用户仍是该学生的有效主监护人。
4. 服务端删除当前绑定并写入不可变 `UNBIND` 审计。
5. 解绑不删除学生数据、不修改登录码、不自动解除已有设备会话；后续微信快捷登录必须重新完成双重绑定。

## 6. 接口设计

- `POST /api/v1/auth/student-wechat-sessions`：交换微信临时凭证；返回已登录会话或微信绑定票据。
- `POST /api/v1/auth/student-wechat-binding-codes`：校验学生账号和登录码，向服务端确定的主监护人手机号发短信。
- `POST /api/v1/auth/student-wechat-bindings`：校验短信、建立一对一绑定和学生会话。
- `GET /api/v1/student-wechat-bindings`：当前家长读取其主监护学生的绑定状态。
- `POST /api/v1/students/{studentId}/wechat-unbindings`：当前主监护人二次确认解绑。

公开认证接口只允许 `MINIAPP` 语义，服务端固定创建 `MINIAPP` 会话。管理接口沿用 Web 与小程序各自独立前端和统一后端 API。

## 7. 异常与隐私

- 学生账号、登录码、绑定冲突、微信身份冲突统一返回模糊认证失败，不暴露账号、关系或绑定存在性。
- 无主监护人、主监护人停用或手机号不可用时阻止自助绑定，并提示联系主监护人或机构处理。
- 票据无效、过期或已消费时不能重放。
- 账号登录风控触发时沿用图形验证码和锁定响应。
- 日志、响应和审计均不得记录短信验证码、登录码、完整手机号、`openid`、`unionid`、微信临时凭证或访问令牌。
- 数据库唯一约束冲突统一转换为认证失败，避免并发双绑。

## 8. 验收基线

- 功能停用时所有相关前端入口不可见，全部相关后端接口返回功能停用。
- 未关联主监护人的学生不能微信绑定，但仍可使用原有账号登录。
- 错误登录码计入既有学生登录保护，错误短信使用独立短信验证频控。
- 绑定成功后相同微信可快捷登录，其他学生不能绑定该微信。
- 只有当前主监护人可以解绑；次监护人、机构管理员和其他家长均被拒绝。
- 所有新增主键为 19 位雪花数字，Flyway V46 不含自增、数据库生成主键或环境特定数据。
- 后端、Web、小程序测试与构建全部通过，微信入口在 H5 隐藏，在 `mp-weixin` 按功能开关显示。
