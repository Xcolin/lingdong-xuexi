# 灵动学习学生账号与登录码登录设计

## 1. 目标与实施范围

本设计对应 V21，完成学生账号从创建到移动端登录的首个可用闭环：系统生成独立学生账号和 4 位登录码，主家长或授权机构管理员初始化历史学生账号、重置登录码，学生通过 uni-app 小程序登录并建立可撤销设备会话。

V21 同时落实登录码连续失败、图形验证码、账号锁定、接口限流、功能开关和安全审计。扫码登录、微信快捷登录、学生微信绑定、短信验证、副家长管理、账号注销及 Web 学生登录不属于 V21；其中扫码登录后续仍须以 4 位登录码二次校验，微信绑定仍须满足主家长短信验证要求。

## 2. 核心业务原则

1. 学生账号属于学生本人，不属于机构或家长。学生没有机构关系、转学、退出机构或解除家长关系时，账号和历史数据均继续保留。
2. 学生禁止自主注册。只有家长或机构管理员创建学生，系统才可在同一事务内创建学生账号。
3. 学生账号为 8 位纯数字，格式为“创建年份后两位 + 6 位年度全局流水号”，例如某年度第一名学生对应 `YY000001`。每年最多分配 999999 个账号，达到上限后拒绝继续分配并产生运维告警，不循环、不复用。
4. 学生账号与数据库雪花主键分离。所有数据表主键继续使用应用层生成的 19 位雪花 `BIGINT`；学生账号只是全局唯一业务标识。
5. 4 位登录码由安全随机数生成，不允许人工指定或编辑。明文只在创建、历史账号初始化或重置成功响应中出现一次，后续不可查询或找回，忘记时只能重置。
6. 主家长或学生当前活动机构的直接机构管理员可以重置登录码。系统管理员、系统审核员、教师、副家长和学生本人均不能直接查看或重置登录码。
7. 登录码重置必须撤销学生全部活动设备会话，旧登录码和旧会话同时失效。

## 3. 方案选择

V21 采用“学生账号 + 登录码 + 图形验证码风控 + 小程序会话”的增量方案。该方案可以形成独立可验收闭环，又不依赖当前个人主体暂不稳定的微信绑定能力。

不采用以下方案：

- 不将学校、区域或创建来源编码进学生账号，避免无机构学生无法生成账号以及转学后账号含义失真。
- 不使用 4 位登录码作为全局唯一账号，避免账号空间不足和无法定位学生。
- 不在 V21 同时实现扫码和微信登录，避免把二维码状态机、微信主体、主家长短信验证混入基础凭证能力。
- 不只生成凭证而缺少登录接口和小程序页面，避免形成不可用的后台孤立数据。

## 4. 数据模型

### 4.1 学生用户

沿用 `sys_user` 作为认证主体。学生用户满足以下约束：

- `type = STUDENT`；
- `username` 保存 8 位学生账号并使用既有全局唯一约束；
- `display_name` 与学生姓名保持创建时一致，V21 不实现学生资料修改同步；
- `password_hash` 保持为空，学生不得通过平台密码接口登录；
- 固定授予内置 `STUDENT` 角色；
- `edu_student.student_user_id` 与学生用户一对一关联。

学生档案状态或学生用户状态任一不是 `ENABLED` 时，均不得建立或继续使用学生会话。停用时撤销全部活动会话，恢复启用后不恢复旧会话。

### 4.2 年度账号流水

V21 新增 `auth_student_account_sequence`：

| 字段 | 说明 |
|---|---|
| `id` | 应用层 19 位雪花主键。 |
| `sequence_year` | 四位完整年份，唯一。 |
| `current_value` | 当前已分配流水值，范围 1 至 999999。 |
| `created_at`、`updated_at` | 审计时间。 |

账号分配服务在事务内按完整年份读取并锁定对应流水记录，原子增加 `current_value`，再使用年份后两位和六位左补零流水生成账号。首次分配某年度时创建流水记录；并发创建依赖唯一约束和重试一次解决初始化竞争。账号写入 `sys_user.username` 后永久占用，即使学生停用或未来注销也不得复用。

账号流水以数据库为事实源，不使用 MySQL 自增、不从雪花主键截取、不依赖 Redis，因此服务重启、Redis清理和数据库切换不会造成重复账号。

### 4.3 学生登录凭证

V21 新增 `auth_student_credential`：

| 字段 | 说明 |
|---|---|
| `id` | 应用层 19 位雪花主键。 |
| `student_user_id` | 学生用户标识，唯一外键。 |
| `code_hash` | 登录码的带密钥摘要。 |
| `code_salt` | 每个凭证独立的安全随机盐。 |
| `key_version` | 服务端登录码密钥版本。 |
| `failure_count` | 当前失败周期的连续登录码错误次数。 |
| `captcha_required` | 后续尝试是否必须提交图形验证码。 |
| `locked_until` | 第十次错误后的锁定截止时间。 |
| `code_updated_at`、`last_success_at` | 登录码变更和最近成功登录时间。 |
| `created_at`、`updated_at` | 审计时间。 |

4 位登录码只有一万个组合，单独使用 BCrypt 或普通 SHA-256 仍可能在数据库泄露后被离线穷举。因此 V21 使用“服务端密钥 + 每凭证随机盐 + HMAC-SHA-256”生成摘要，并以常量时间比较。服务端密钥只能通过环境变量或受控密钥配置注入，不得写入 Git、数据库、日志、接口或普通配置文档；测试环境使用独立测试密钥。`key_version` 为后续密钥轮换保留兼容边界。

## 5. 账号创建与历史初始化

### 5.1 新建学生

家长或机构管理员调用现有学生创建接口时，在同一事务内执行：

1. 校验现有角色和家长/机构数据范围；
2. 分配 8 位学生账号；
3. 创建 `STUDENT` 类型 `sys_user`；
4. 授予内置 `STUDENT` 角色；
5. 生成 4 位登录码并写入凭证摘要；
6. 创建学生档案并写入 `student_user_id`；
7. 建立主家长关系或机构关系；
8. 返回学生档案、学生账号和仅本次可见的初始登录码。

任一步失败必须整体回滚，不允许出现只有用户、只有学生档案或只有凭证的半成品。

### 5.2 V21 前的历史学生

V21 不在 Flyway SQL 中动态生成雪花主键、账号和凭证，也不修改 V19 历史迁移。`student_user_id` 为空的历史学生显示“账号未初始化”。

主家长或该学生活动机构的直接机构管理员可以调用初始化接口。服务端重新校验关系和学生状态后，以与新建学生相同的事务步骤创建用户、角色和凭证。学生已初始化时返回 `409 STATE_CONFLICT`，绝不再次返回原登录码。并发初始化依赖 `edu_student.student_user_id` 唯一约束和条件更新保证只成功一次。

当前尚未在共享测试、预生产或生产库执行 V1-V20，因此正常空库部署不会产生历史学生；该流程仍作为升级兼容能力保留。

## 6. 权限与数据范围

V21 新增以下 Web 管理操作权限：

| 权限 | 默认角色 | 服务端范围规则 |
|---|---|---|
| `STUDENT_CREDENTIAL_INITIALIZE` | `PARENT`、`ORG_ADMIN` | 家长必须是活动主家长；机构管理员必须直接管理学生当前活动机构。 |
| `STUDENT_LOGIN_CODE_RESET` | `PARENT`、`ORG_ADMIN` | 与初始化相同，且学生账号已经初始化。 |

路由 RBAC 通过后，应用服务仍必须执行对象关系校验。前端传入的组织、家长或角色信息不能扩大范围。无对象范围时统一返回 `404 RESOURCE_NOT_FOUND`，避免泄露其他家庭或机构学生；具备对象范围但业务状态不允许时返回 `409 STATE_CONFLICT`。

学生登录、图形验证码和令牌刷新是认证入口，不使用业务 RBAC 注解，但受功能开关、请求限流、账号状态、学生状态和凭证风控约束。系统管理员不能绕过主家长或机构关系直接初始化、查看或重置学生登录码；未来确需平台级恢复时必须另行设计经系统审核员审批的高风险系统任务。

## 7. 登录与风控流程

### 7.1 登录请求

小程序提交学生账号、4 位登录码、设备标识、设备名称，以及被要求时提交的图形验证码挑战标识和答案。服务端固定创建 `MINIAPP` 客户端会话，不接受客户端自行指定用户、角色或客户端类型。

服务端按以下顺序处理：

1. 校验 `STUDENT_CODE_LOGIN` 功能开关和预认证限流；
2. 规范化 8 位账号和 4 位登录码，错误格式使用统一认证失败响应；
3. 查询学生用户、学生档案和凭证，不向客户端区分账号不存在、状态停用或登录码错误；
4. 若 `locked_until` 晚于当前时间，返回锁定状态和截止时间；
5. 若 `captcha_required = true`，先校验与账号摘要、设备标识绑定的一次性图形验证码；
6. 常量时间比较登录码摘要；
7. 登录成功后清零失败次数、验证码要求和锁定状态，记录成功时间，并创建可撤销设备会话；
8. 返回访问令牌、刷新令牌和有效期，原始令牌仍只在本次响应中出现，数据库只保存摘要。

### 7.2 连续错误规则

登录码错误按学生凭证原子递增：

- 第 1 至 4 次：返回统一学生认证失败；
- 第 5 次：将 `captcha_required` 置为真，并返回需要图形验证码；
- 第 6 至 9 次：每次必须先通过一次性图形验证码，再校验登录码；登录码仍错误时继续计数；
- 第 10 次：设置 `locked_until = 当前时间 + 15 分钟`；
- 锁定期内：不校验登录码，不增加失败次数；
- 锁定期结束：开始新的失败周期，失败次数和验证码要求归零；
- 登录成功：立即清零当前失败周期。

验证码错误或缺失不触发登录码摘要比较，也不增加登录码失败次数。图形验证码一次使用、短时有效，并绑定账号摘要和设备标识，防止跨账号、跨设备复用。

### 7.3 图形验证码与限流

图形验证码使用成熟组件生成图片和答案，服务端只返回挑战标识、Base64 图片和过期时间。答案摘要、绑定范围和使用状态保存到 Redis，并设置短 TTL；测试环境使用同一接口的内存实现。Redis 不可用时，已要求验证码的登录必须失败关闭，不能绕过验证码继续校验登录码。

预认证接口使用 Redis 实施可配置限流，V21 默认规则为：单一账号与设备组合每分钟最多 10 次登录请求，单一来源地址每分钟最多 60 次登录请求，单一账号与设备组合 5 分钟最多申请 10 个验证码。超限返回 `429 RATE_LIMITED`。限流键不保存原始登录码、验证码答案或访问令牌。

## 8. 会话与功能开关

`AuthClientType` 新增 `MINIAPP`。现有访问令牌、刷新轮换、退出当前设备、下线指定设备和一键全端下线能力复用于学生账号，但认证服务必须按会话客户端类型验证用户类别：现有 `WEB` 密码会话仍只接受平台账号；V21 的 `MINIAPP` 登录码会话只接受学生用户，并额外验证对应学生档案为启用状态。

同一学生允许多个小程序设备同时在线，不互相挤下线。重置登录码、学生用户停用或学生档案停用时撤销全部活动会话；恢复启用不恢复旧会话。

V21 新增 `STUDENT_CODE_LOGIN` 功能开关并默认启用。小程序启动时读取公开能力摘要：开关关闭后隐藏学生登录入口并展示功能暂不可用状态；认证接口同时在后端拒绝新建学生会话，不影响已保存的学生档案和历史数据。开关关闭是否撤销既有学生会话不在 V21 自动执行，需后续系统任务明确影响范围，避免普通配置变更无审计地强制全员下线。

## 9. HTTP 契约

| 方法与路径 | 用途 | 成功结果 |
|---|---|---|
| `GET /api/v1/public/capabilities?client=MINIAPP` | 获取无需登录的客户端能力摘要。 | 返回 `STUDENT_CODE_LOGIN` 是否启用。 |
| `POST /api/v1/auth/student-captchas` | 获取一次性图形验证码。 | 返回挑战标识、Base64 图片和过期时间。 |
| `POST /api/v1/auth/student-sessions/code` | 学生账号和登录码登录。 | 返回 `MINIAPP` 设备会话令牌。 |
| `POST /api/v1/students/{id}/credentials/initialize` | 为历史学生初始化账号。 | 返回学生账号及仅本次可见的登录码。 |
| `POST /api/v1/students/{id}/login-code-resets` | 重置登录码并撤销全部学生会话。 | 返回学生账号及仅本次可见的新登录码。 |

新建学生接口的成功响应扩展 `studentAccount` 和 `initialLoginCode`；两个字段只用于创建成功响应，学生目录和详情不得返回登录码。所有 19 位数据库标识继续按 JSON 字符串返回，8 位学生账号始终按字符串处理，避免年份前导零被丢失。

主要错误码：

| HTTP 状态 | 错误码 | 场景 |
|---|---|---|
| 400 | `VALIDATION_ERROR` | 已认证管理接口字段不合法。 |
| 401 | `STUDENT_AUTH_FAILED` | 学生账号不存在、状态不可用或登录码错误的统一响应。 |
| 409 | `STATE_CONFLICT` | 学生账号已初始化、状态不允许初始化或账号流水耗尽。 |
| 423 | `STUDENT_ACCOUNT_LOCKED` | 登录码连续错误十次，返回锁定截止时间。 |
| 428 | `CAPTCHA_REQUIRED` | 需要图形验证码、验证码缺失/失效/错误。 |
| 429 | `RATE_LIMITED` | 登录或验证码请求超过限流阈值。 |
| 503 | `AUTH_PROTECTION_UNAVAILABLE` | 已要求验证码但 Redis/验证码保护不可用，登录失败关闭。 |

认证失败响应不得回显登录码、验证码答案、用户主键、凭证摘要或账号是否真实存在。

## 10. 小程序交互

uni-app 新增独立学生登录页，首屏读取公开能力摘要。入口启用时展示 8 位学生账号、4 位登录码和登录按钮；服务端返回 `CAPTCHA_REQUIRED` 后再展示验证码图片、答案输入和刷新按钮；返回锁定状态时显示可重试时间并禁用提交。

登录成功后将会话保存到小程序安全存储，进入学生端应用壳；V21 不提前实现任务、积分等业务页面。退出、刷新令牌和会话失效沿用现有后端契约并在小程序建立独立客户端封装，不与 Web 的 `sessionStorage` 或路由代码混用。

页面不得显示、记录或上报原始登录码。学生账号可以由家长或机构复制给学生，但小程序不得将登录码写入日志、埋点、错误报告或长期自动填充存储。

## 11. 并发、事务与异常处理

1. 学生创建、历史初始化、登录码重置均使用事务。
2. 年度流水分配以数据库行锁和唯一约束防并发重复；年度记录初始化冲突只允许有限重试一次。
3. 历史账号初始化以学生条件更新和唯一约束防并发双建，冲突转换为 `409 STATE_CONFLICT`。
4. 登录失败次数使用条件更新或数据库原子递增，不能采用“先查后写”的丢失更新方式。
5. 登录成功清零失败状态与会话创建处于同一事务，任一步失败均不返回令牌。
6. 登录码重置、凭证更新和全部学生会话撤销处于同一事务；撤销失败时新登录码不得生效。
7. 不记录原始登录码、验证码答案、访问令牌、刷新令牌、服务端密钥或其可逆内容。安全日志仅记录脱敏账号、结果、设备摘要、来源摘要、追踪标识和时间。

## 12. Flyway 与数据库兼容

V21 新增迁移脚本，创建 `auth_student_account_sequence`、`auth_student_credential`，写入学生凭证管理权限和 `STUDENT_CODE_LOGIN` 功能开关基础数据。所有新增表使用应用层 19 位雪花主键，不使用 identity、自增、数据库函数生成主键或触发器。

迁移不得为历史学生动态创建用户或凭证。MyBatis XML 使用参数绑定；流水锁定 SQL优先采用 MySQL 8 和 H2 MySQL 兼容模式均支持的写法。未来切换其他数据库时，由数据库方言 Mapper 处理锁语法差异，应用服务和领域接口不绑定 MySQL 特有函数。

本轮只在本地 H2 MySQL 兼容模式验证 V1 至 V21，不加载 `application-local.yml`，不连接或迁移远程 MySQL、Redis、共享测试、预生产或生产环境。

## 13. 测试与验收

V21 必须先建立失败测试，再实现最小代码。至少覆盖：

1. 家长和机构分别创建学生时自动生成符合 `YY + 6位流水` 的唯一账号、学生用户、角色和凭证；事务失败不留半成品。
2. 无机构学生可以正常拥有并使用学生账号；解除或改变机构关系不修改账号。
3. 历史学生由主家长或直接机构管理员初始化成功，越权用户、教师、系统管理员和重复初始化被拒绝。
4. 明文登录码只在创建、初始化和重置响应出现一次；数据库不保存明文，普通学生详情不返回登录码。
5. 正确登录创建 `MINIAPP` 会话；Web 密码入口拒绝学生账号；学生登录入口拒绝平台账号。
6. 第 1 至 4 次错误、第五次要求验证码、第十次锁定 15 分钟、锁定期结束新周期和成功后清零均符合规则。
7. 验证码一次性、过期、错误、跨账号、跨设备、Redis 故障失败关闭及限流返回均有测试。
8. 主家长和直接机构管理员可重置；跨家庭、跨机构、已离校机构、无权限角色均不能重置。
9. 重置后旧登录码失败、全部旧会话失效，新登录码可登录。
10. 功能开关关闭后公开能力摘要为关闭、小程序入口隐藏、后端拒绝新登录，历史数据不删除。
11. V21 两张表的雪花主键、唯一约束、外键、权限和功能开关基础数据通过 Flyway 迁移测试。
12. 后端全量测试、Web 测试和构建、uni-app 类型检查及微信小程序构建全部通过。

## 14. 明确不包含的能力

- 学生扫码登录二维码生成、自动刷新、单次消费和二次登录码校验；
- 学生微信授权绑定、主家长短信验证码和微信一对一解绑；
- 家长短信注册或未注册家长通过邀请自动注册；
- 副家长新增、主副家长变更和全部家长解绑流程；
- 学生头像、资料编辑、转班转学和注销；
- 学生任务、积分、奖励和成长页面；
- 共享测试、预生产或生产数据库迁移与真实 Redis、微信联调。

这些能力必须在 V21 稳定后按独立设计、迁移和验收计划逐步实现，不得通过临时字段或绕过安全校验提前接入。
