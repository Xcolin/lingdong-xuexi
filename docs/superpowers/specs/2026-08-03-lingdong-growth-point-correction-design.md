# 灵动学习 V26 积分纠错闭环设计

## 1. 范围与依据

V26 严格落实原始素材“家长误操作审核通过后，可在 72 小时内发起积分纠错；填写原因；原积分扣除；任务状态回退至待审核；全程日志留存”的要求。

本里程碑不实现奖励兑换、休眠清零、积分导出、统计报表、超时自动审核或消息通知。纠错入口先落在已经具备主家长身份认证的 Web 应用；小程序当前只有学生身份认证，因此仅同步展示纠错台账，不提供无法安全鉴别家长身份的操作入口。

## 2. 业务规则

1. 仅 Web 端活动主关系家长可以发起纠错，且必须具备 `GROWTH_POINT_CORRECT_CHILD` 权限。
2. 仅允许纠正 `FAMILY` 来源、`TASK_REWARD` 类型、由当前家长本人审核产生的奖励台账；不得纠正机构任务或教师任务积分。
3. 纠错时限从原奖励台账 `occurred_at` 起算 72 小时，截止时刻可提交，超过后拒绝。
4. 纠错原因为必填，去除首尾空格后长度为 1 至 500 个字符。
5. 每次纠错必须整笔冲销原奖励，不允许输入积分数量；同一原奖励只能纠错一次。
6. 累计总积分扣除原奖励整笔积分。可用积分扣除 `min(当前可用积分, 原奖励积分)`，避免未来已兑换场景出现负余额。
7. 纠错成功后，任务实例从 `COMPLETED` 回退为 `PENDING_REVIEW`，`completed_at` 清空；最近一次已通过打卡恢复为 `SUBMITTED`，等待原审核人重新审核。
8. 原奖励台账不得修改或删除。系统新增 `CORRECTION` 反向台账，并通过 `correction_of_id` 唯一关联原奖励。
9. 系统新增 `POINT_CORRECTED` 任务事件，记录操作人、前后状态、纠错原因、原台账与纠错台账标识。
10. 重新审核通过后允许生成新的任务奖励台账；并发幂等由任务实例行锁、状态版本和原台账唯一纠错约束共同保证。

## 3. 事务顺序

1. 校验功能开关、客户端、角色、权限和主家长关系。
2. 锁定原奖励台账，校验来源、原审核人、72 小时时限及未纠错状态。
3. 锁定任务实例，要求当前状态为 `COMPLETED` 且审核人仍为当前家长。
4. 锁定最近一次已通过打卡和学生积分账户。
5. 原子扣减账户累计积分与可用积分，版本号加一。
6. 写入 19 位雪花标识的纠错台账。
7. 将打卡恢复为 `SUBMITTED`，任务恢复为 `PENDING_REVIEW` 并清空完成时间。
8. 写入 19 位雪花标识的 `POINT_CORRECTED` 任务事件。
9. 任一步骤失败时整体回滚。

## 4. 接口与展示

`POST /api/v1/growth-points/students/{studentId}/corrections`

请求体：

```json
{
  "originalLedgerId": "19位雪花标识",
  "reason": "误点审核通过，需重新核对打卡内容"
}
```

响应包含学生、任务实例、原台账、纠错台账、冲销积分、账户最新余额、任务状态和发生时间。所有 19 位标识均以字符串输出。

家长台账查询增加 `correctionOfId`、`correctionLedgerId`、`correctionDeadline` 和 `correctable`。Web 仅在服务端明确返回 `correctable=true` 且纠错功能开关启用时显示纠错操作。

## 5. 数据库与安全

V26 删除阻止同一任务重新发奖的旧唯一约束，新增 `correction_of_id` 唯一约束和纠错台账检查约束；扩展任务事件枚举约束。迁移同时写入独立功能开关、Web 权限和主家长角色授权，新增标识继续采用连续的 19 位雪花数字。

关闭 `GROWTH_POINT_CORRECTION` 后，公开能力摘要返回关闭、Web 隐藏操作、后端接口强制拒绝。越权学生标识统一返回资源不存在，避免泄露亲子关系和积分数据。
