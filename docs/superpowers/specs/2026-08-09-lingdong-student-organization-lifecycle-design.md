# 灵动学习 V41 学生机构关系生命周期设计

**版本**：V1.0  
**日期**：2026-08-09  
**状态**：已按确认的主开发计划进入实施  
**依据**：原始素材 4.2.1.5、4.4.2，BRD 3.3、3.6，V19 学生机构关系和 V22 学生班级关系。

## 1. 目标与范围

V41 完成机构管理员对学生机构关系的校内转班、离校或转学转出停用、当前关系查询和不可变变更记录，并在 Web 与 uni-app 两个独立应用提供操作入口。

跨机构转学严格遵循原始素材：原机构停用原学生的机构关系并保留历史；新机构重新创建学生账号并建立家长绑定，不把原学生账号直接迁移到另一租户。V41 不实现学生注销、家长注销、批量导入、班级基础信息编辑、考勤或跨租户身份合并。

## 2. 业务规则

### 2.1 校内转班

1. 目标必须是启用的 `CLASS` 组织，且位于学生当前活动 `ENROLLMENT` 组织子树内。
2. 操作者必须拥有 `ORG_ADMIN` 角色、`STUDENT_ORGANIZATION_MANAGE` 权限，并能访问目标班级和学生当前入学组织。
3. 学生必须启用，入学关系必须活动；同班重复提交按幂等成功处理，不新增变更记录。
4. 转班原子停用原活动班级并激活或新增目标班级，每名学生最多保留一条活动班级关系。
5. 首次分班记录 `CLASS_ASSIGN`，已有班级切换记录 `CLASS_TRANSFER`。历史任务、积分和已经形成的业务事实不删除；新班级目标从关系生效时间起计算。

### 2.2 离校或转学转出

1. 操作者选择学生当前活动入学组织，填写 1 至 200 字原因并二次确认。
2. 服务端锁定学生，停用该入学组织子树内的全部活动班级关系，再停用指定 `ENROLLMENT` 关系。
3. 学生档案、学生账号、家庭关系、家庭私有数据和历史机构数据均保留；机构基于活动关系的新增、下发和当前学员查询立即失效。
4. 重复停用已失效关系返回资源不存在或不可访问，不伪造第二条审计记录。
5. 目标学校不得通过本接口接管原学生账号，必须使用现有机构创建学生和邀请家长流程建立新的租户内学生。

## 3. 数据与审计

新增 `edu_student_organization_change`，主键为应用层生成的 19 位雪花 `BIGINT`，字段包括学生、变更类型、来源组织、目标组织、原因、操作者和发生时间。该表只允许插入，不提供更新或删除 Mapper。

`edu_student_organization` 继续保存当前关系和最近一次有效区间，不修改 V19 的业务唯一约束。重复回到同一班级时允许重新激活原关系行，完整事件顺序以不可变变更表为准。

## 4. API 与权限

| 接口 | 用途 | 约束 |
|---|---|---|
| `GET /api/v1/students/{id}/organization-relationships` | 查询当前入学、班级和变更历史 | 仅当前活动关系范围内机构管理员 |
| `POST /api/v1/students/{id}/class-transfers` | 首次分班或校内转班 | 目标班级、原因；同班幂等 |
| `POST /api/v1/students/{id}/organization-deactivations` | 离校或转学转出 | 入学组织、原因；高风险二次确认 |

新增 `STUDENT_ORGANIZATION_MANAGE`，客户端类型为 `BOTH`，授予内置 `ORG_ADMIN`。新增默认启用的 `STUDENT_ORGANIZATION_RELATIONSHIP` 功能开关；关闭后 Web 和小程序入口隐藏，后端拒绝查询与变更。所有 API 标识以字符串返回，避免 JavaScript 精度损失。

## 5. 应用边界

Web 在组织管理中使用独立“学员关系”抽屉，支持学生、目标班级、原因和转出确认。uni-app 在机构工作台进入独立学员关系页，调用同一业务 API，但使用机构小程序令牌，不复用 Web 状态或页面代码。复杂历史统计和批量操作不放入小程序。

## 6. 异常与安全

跨组织范围、非活动关系和不可见学生统一返回 `404 RESOURCE_NOT_FOUND`；缺少动态权限返回 `403 ACCESS_DENIED`；功能停用返回 `409 FEATURE_DISABLED`；非法组织类型、原因或同校约束返回 `400 VALIDATION_ERROR`。事务中任一步失败均回滚关系和审计写入。

客户端类型继续参与动态 RBAC 判定：`BOTH` 权限允许 Web 与机构小程序使用，其他 Web 权限不能被小程序令牌调用。日志和响应不返回家庭关系、手机号、登录码、令牌或家庭私有业务数据。

## 7. 验收基线

1. Flyway 从空库连续执行 V1-V41；新表主键和基础数据标识为 19 位数字，无自增列。
2. 校内首次分班、转班、同班幂等、跨校拒绝、停用班级拒绝和并发唯一关系均有自动化测试。
3. 转出后活动入学和班级关系全部失效，家庭关系及学生账号保持不变，历史关系和变更记录可追溯。
4. Web 与小程序使用独立页面和会话，功能关闭或权限不足时入口隐藏且直达 API 被拒绝。
5. 后端全量测试、Web 测试与构建、uni-app 类型检查及 H5/微信小程序构建全部通过；不对远程 MySQL、Redis、共享测试、预生产或生产环境执行迁移和写入。
