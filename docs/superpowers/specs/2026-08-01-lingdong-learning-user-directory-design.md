# 灵动学习用户目录与账号状态管理设计

**版本**：V1.0  
**日期**：2026-08-01  
**状态**：已实施并完成本地验证

## 1. 建设范围

本轮补齐 Web 管理端的用户管理基础闭环：系统按条件分页查询用户、创建用户、修改账号状态，并在用户被停用或锁定时立即撤销其活动设备会话。

不包含机构范围 SQL 过滤、用户资料编辑、用户删除、用户角色/组织关联详情、批量导入、学生关系、微信登录和学习业务。已有的组织关联、角色授予和平台密码设置接口保持原行为。

## 2. 接口与数据契约

### 2.1 用户目录

新增 `GET /api/v1/users`，需要 `IAM_USER_LIST` 权限。查询参数如下：

| 参数 | 规则 | 默认值 |
|---|---|---|
| `keyword` | 按账号或显示名称模糊匹配，去除首尾空格，最长 64 个字符 | 不筛选 |
| `type` | `PLATFORM`、`ORGANIZATION`、`FAMILY`、`STUDENT` | 不筛选 |
| `status` | `ENABLED`、`DISABLED`、`LOCKED` | 不筛选 |
| `page` | 大于等于 1 | 1 |
| `pageSize` | 1 至 100 | 20 |

响应使用 `{ items, page, pageSize, total }`。用户按创建时间倒序、标识倒序稳定排序；用户标识继续按 JSON 字符串输出。`mobile` 在响应中统一脱敏，避免目录接口暴露完整手机号。

### 2.2 账号状态

新增 `PATCH /api/v1/users/{id}/status`，需要 `IAM_USER_STATUS_CHANGE` 权限。请求体为 `{ "status": "ENABLED|DISABLED|LOCKED" }`，返回更新后的安全用户响应。

状态为 `DISABLED` 或 `LOCKED` 时，服务端在同一业务事务内撤销目标用户的所有活动设备会话。后续访问凭证和刷新凭证均无法继续使用；重新设置为 `ENABLED` 不恢复旧会话，用户必须重新登录。重复设置为同一状态视为幂等成功。

## 3. 权限与边界

Flyway V18 仅新增两条 WEB 操作权限并默认授予内置 `SYS_ADMIN`：`IAM_USER_LIST`、`IAM_USER_STATUS_CHANGE`。后续系统管理员可通过既有角色权限管理向自定义角色授予该权限；前端菜单和按钮不能替代服务端的 `@RequirePermission` 校验。

本轮目录查询仍是全局目录，因为组织数据范围 SQL 过滤尚未实现。不得将该接口授权给机构管理员，直到其查询条件能够按授权组织树收敛。

## 4. Web 交互

在管理端增加“用户管理”路由。页面包含账号/名称关键字、用户类型、账号状态筛选器，分页表格和“新增用户”按钮；每条记录提供图标操作用于启用、停用或锁定。状态操作必须使用确认弹窗，成功后刷新当前页数据。

创建弹窗只调用已存在的用户创建接口，不伪造密码、组织关联或角色授予成功。手机号在目录中按服务端返回的脱敏值展示。
