# 灵动学习附件管理核心设计

## 1. 范围

本模块实现 FSD-SYS-02 的统一附件规则、文件元数据和业务关联能力。业务模块只能声明模块编码、业务对象、关系类型和可见范围，不得自行定义文件格式、大小、删除和访问规则。

对象存储供应商、CDN、病毒检测和预览转换服务尚未指定。本轮不实现具体供应商 SDK、长期公开链接或绕过权限的上传/下载 Controller；后续通过对象存储端口生成短时受控上传、预览和下载结果。

## 2. 数据模型

Flyway `V13` 新建以下雪花主键表：

| 表 | 用途 | 关键约束 |
|---|---|---|
| `sys_attachment_rule` | 按模块和文件分类配置白名单、大小、批量数、预览和下载范围 | `(module_code, file_category)` 唯一；规则停用后不得用于新增文件。 |
| `sys_attachment_rule_extension` | 规则允许的扩展名 | `(rule_id, extension)` 唯一，扩展名使用小写。 |
| `sys_file` | 对象存储中文件的受控元数据 | `storage_key` 唯一；只存内部对象键，不存供应商密钥或长期 CDN 地址。 |
| `sys_file_relation` | 文件与业务对象的可见关系 | `(file_id, module_code, business_id, relation_type)` 唯一；解除关系不删除文件元数据。 |

文件状态为 `UPLOADING`、`AVAILABLE`、`RETIRED`。只有 `AVAILABLE` 文件可以建立业务关系；删除默认将关系标记解除，不物理删除文件。上传人、上传时间和业务归属均在元数据与关系中保留。

## 3. 规则与流程

1. 系统管理员创建或更新附件规则；配置变更即时生效。
2. 文件登记前必须根据模块与文件分类取得启用规则，校验扩展名、大小和单批数量。
3. 文件登记生成不含个人信息的内部对象键，并保存 `UPLOADING` 元数据；实际对象上传由后续对象存储适配器执行。
4. 上传完成后，存储适配器回调应用服务确认已校验的大小与内容类型，文件变为 `AVAILABLE`。
5. 业务模块仅可为 `AVAILABLE` 文件建立可见关系；解除关系后文件不再对该业务对象可见。
6. 预览与下载必须先通过业务数据权限校验，再由存储端口生成短时受控结果；本轮没有认证上下文或存储供应商，因此不创建 HTTP 端点。

## 4. 验证边界

测试覆盖规则唯一性、扩展名与大小校验、停用规则拒绝新增、雪花主键、上传完成前禁止关联、关系解除后的不可见状态。对象存储供应商确定后，补充预签名授权、短时链接、失败重试、病毒检测和真实 MySQL 8 集成验证。
