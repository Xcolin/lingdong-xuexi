# 灵动学习学员批量导入设计说明

## 1. 目标

在 V56 通用 XLSX 校验作业之上，增加机构学员批量开户、可选班级绑定、逐行结果、失败重试和初始凭证安全交付能力。V58 不改变“校验通过不等于业务导入成功”的既有语义，不向小程序加入批量操作。

## 2. 范围与边界

- 仅处理业务类型为 `STUDENT`、模板类型为 `IMPORT`、状态为 `VALIDATED` 的校验作业。
- 仅 Web 端提供执行、查询、失败重试和凭证下载；小程序不增加页面、路由、接口封装或权限码。
- 每个校验作业最多创建一个学员导入执行，防止重复开户。
- 每批必须绑定一个学校组织，可选绑定该学校下的一个启用班级；多班级数据使用多个批次处理。
- 模板至少包含 `STUDENT_NAME` 字段，可选包含 `GRADE_CODE`；不按姓名跨批次去重，同名学员视为合法业务事实。
- 本专项不包含家长邀请、家长确认、教师导入、跨学校转学和历史学员合并。

## 3. 角色、权限与功能开关

- 操作角色为机构管理员 `ORG_ADMIN`，并且每次操作都重新校验账号、角色、动态权限和组织数据范围。
- `STUDENT_IMPORT_EXECUTE`：创建执行及重试失败行。
- `STUDENT_IMPORT_RESULT_READ`：查看执行台账、详情和逐行结果。
- `STUDENT_IMPORT_CREDENTIAL_DOWNLOAD`：一次性下载初始凭证。
- `STUDENT_BATCH_IMPORT`：总开关；停用后前端入口隐藏、后端接口拒绝、调度器不领取新任务。
- 同时依赖 `DATA_IMPORT_VALIDATION`、`ATTACHMENT_SERVICE` 和 `IMPORT_EXPORT_TEMPLATE_MANAGEMENT`。

## 4. 核心流程

1. 机构管理员创建并等待 V56 校验作业进入 `VALIDATED`。
2. 管理员在详情中选择可选目标班级并提交执行。
3. 后端锁定校验作业，校验模板业务类型、组织范围、创建人和唯一执行约束，创建 `QUEUED` 执行及 `PENDING` 行。
4. 调度器用状态和版本号竞争领取，执行进入 `RUNNING`。
5. 每一行在独立事务内创建学生、分配8位学员账号和4位初始登录码、建立学校关系，并按请求绑定班级。
6. 单行任一步失败时整行回滚，保存受限中文错误摘要；其他行继续执行。
7. 登录码只以 AES-GCM 密文临时保存，关联数据包含执行标识和行号，禁止写日志。
8. 全部行完成后生成凭证 XLSX，经应用层加密后调用统一附件服务保存，随后清除逐行临时密文。
9. 执行根据计数进入 `SUCCEEDED`、`PARTIAL_SUCCEEDED` 或 `FAILED`。
10. 仅原操作人可以在24小时内下载一次凭证。后端在返回内容前原子消费下载资格；网络中断也不得再次下载，遗失凭证使用既有重置流程。
11. 到期任务由清理器标记 `EXPIRED`，删除物理内容并使附件不可继续读取。

## 5. 状态模型

执行状态：

- `QUEUED`：已经创建，等待领取。
- `RUNNING`：正在逐行处理。
- `SUCCEEDED`：全部业务行成功。
- `PARTIAL_SUCCEEDED`：至少一行成功且至少一行失败。
- `FAILED`：没有业务行成功，或执行级故障导致无法完成。

行状态：`PENDING`、`SUCCEEDED`、`FAILED`。

凭证状态：`NONE`、`AVAILABLE`、`CONSUMED`、`EXPIRED`。失败重试只处理当前 `FAILED` 行；已成功行不得重复开户。

## 6. 数据模型

### 6.1 `sys_student_import_execution`

保存19位雪花主键、执行编码、校验作业、操作人、学校、可选班级、状态、版本号、计数、失败摘要、凭证文件、凭证状态、下载截止时间、下载时间和审计时间。`validation_job_id` 建立唯一约束。

### 6.2 `sys_student_import_row`

保存19位雪花主键、执行标识、源工作表行号、行状态、成功后的学生标识和学员账号、受限错误编码与摘要、临时凭证密文/随机数/密钥版本、尝试次数和审计时间。`execution_id + row_number` 建立唯一约束。

数据库不保存初始登录码明文。前端与接口中的所有雪花标识均使用字符串传输。

## 7. 事务、幂等和异常

- 创建执行以校验作业行锁和数据库唯一约束共同保证幂等。
- 领取使用 `QUEUED + version_no` 条件更新，支持多实例竞争。
- 单行服务使用独立事务，学生档案、账号、学校关系、班级关系和行结果同成同败。
- 执行级异常只记录固定错误码和脱敏中文摘要，不记录姓名、登录码、文件内容或存储键。
- 重试失败行时增加尝试次数，达到配置上限后仍可保留失败事实，但不自动无限重试。
- 凭证生成失败时不得把执行标记成功；已经创建的学生保留，执行可从成功行临时密文恢复生成凭证。

## 8. 凭证安全

- `lingdong.student-import.credential-key` 从环境变量读取，生产环境不得使用默认值；密钥至少32字节并带版本号。
- 行凭证和最终附件分别使用随机96位随机数执行 AES-256-GCM 加密，认证附加数据绑定执行标识。
- 统一附件中保存的是加密包，不是可直接打开的 XLSX；下载服务鉴权后解密为受控响应。
- 下载权限、操作人归属、有效期和状态在同一事务内复核，`AVAILABLE` 原子变为 `CONSUMED`。
- 凭证下载响应禁止缓存，设置 `Cache-Control: no-store` 和安全文件名。
- 清理任务删除物理内容并清除可恢复材料；数据库只保留已消费或已过期的审计状态。

## 9. API 与 Web 交互

- `POST /api/v1/student-import-executions`：由已校验作业创建执行。
- `GET /api/v1/student-import-executions`：按本人和当前组织范围分页查询。
- `GET /api/v1/student-import-executions/{id}`：查询详情和计数。
- `GET /api/v1/student-import-executions/{id}/rows`：分页查询逐行结果。
- `POST /api/v1/student-import-executions/{id}/retry-failures`：重试失败行。
- `GET /api/v1/student-import-executions/{id}/credentials`：一次性下载凭证。

Web 在 V56 作业详情中仅对满足条件的作业显示“执行学员导入”。执行详情显示进度、成功数、失败数、失败摘要、重试按钮和凭证剩余有效期；凭证下载前必须进行明确的不可重复下载确认。

## 10. 验收基线

- 空库连续执行58个 Flyway 迁移，新增主键和种子标识均为19位数字且无自增。
- 非机构管理员、越权组织、权限撤回、角色撤回和功能关闭均被后端拒绝。
- 重复提交同一校验作业不会重复开户；同名学员可以在不同有效行创建。
- 单行失败不影响其他行，班级绑定失败不会留下半成品学生。
- 凭证明文不进入数据库普通字段、日志、错误响应和浏览器持久存储。
- 凭证只能由原操作人下载一次，24小时后不可下载且物理内容被清理。
- 后端、Web 测试和构建通过；miniapp 双目标构建通过且扫描不到 V58 管理能力。
