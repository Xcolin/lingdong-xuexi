# 灵动学习 V23 任务执行与审核基础设计

**日期**：2026-08-01

**状态**：按既定实施顺序执行

**依据**：《灵动学习业务需求说明书》3.4、《功能详细设计》FSD-TASK-02、V22 学习任务基础实现。

## 1. 建设目标

V23 在 V22 已发布学生任务实例上增加学生执行和业务审核基础，使任务可以从待认领流转到进行中、暂停、待审核、待优化或免执行，并完整保留打卡、暂停、状态变化和审核人转交历史。

审核通过与积分入账必须保持原子一致。由于积分账户和积分台账将在 V24 建设，V23 不提供审核通过接口或按钮，只提供审核驳回和审核人转交，避免出现任务已完成但积分未发放的数据不一致。

## 2. 方案选择

### 2.1 采用方案

采用“任务实例当前状态加独立事件表”的方案：`learn_task_assignment` 保存当前快照，暂停、打卡、状态事件和审核转交使用独立表保留历史。所有状态变化先锁定任务实例，再执行条件更新和事件写入。

### 2.2 未采用方案

1. 只更新任务实例状态：实现简单，但无法审计暂停、重复打卡、驳回和转交历史。
2. 引入通用工作流引擎：扩展能力强，但当前状态机规模有限，会增加部署、模型和排障复杂度。

## 3. V23 范围

### 3.1 本期实现

1. 学生认领任务。
2. 学生按“情绪暂停”或“难题搁置”暂停任务，单次最长 2 小时。
3. 学生手动恢复任务；暂停超时后读取和后续操作按已恢复处理。
4. 学生放弃任务并进入待优化，不扣分、不记录负面评价。
5. 学生提交文字打卡，任务进入待审核；每次提交形成独立版本。
6. 当前审核人查询本人待审核任务和打卡详情。
7. 当前审核人驳回打卡，审核意见必填，任务退回进行中。
8. 当前审核人将任务转交给服务端校验通过的审核候选人。
9. 家长、任务创建教师或具备组织范围的机构管理员设置免执行。
10. Web 提供审核待办、驳回和转交；小程序提供认领、暂停、恢复、放弃和文字打卡。

### 3.2 后续范围

1. 审核通过、积分账户和积分台账由 V24 同一事务实现。
2. 图片、音视频等打卡素材统一引用附件管理，待附件 REST 和对象存储适配完成后开放页面入口。
3. 23:59 自动转待优化、待优化顺延、审核超时处理和审核人失效自动转交进入后续定时任务计划。
4. 任务模板、昨日任务复制、消息通知和统计不在 V23 范围。

## 4. 状态模型

任务实例基础状态包括：

| 状态 | 含义 | V23 可进入方式 |
|---|---|---|
| `PENDING_CLAIM` | 待认领 | 发布生成 |
| `IN_PROGRESS` | 进行中 | 学生认领、审核驳回 |
| `PENDING_REVIEW` | 待审核 | 学生提交打卡 |
| `NEEDS_IMPROVEMENT` | 待优化 | 学生放弃 |
| `EXEMPT` | 免执行 | 授权管理角色设置 |
| `COMPLETED` | 已完成 | V24 审核通过与积分入账 |

暂停不修改 `current_status`。存在未关闭且未到期的暂停记录时，响应中的 `effectiveStatus` 为 `PAUSED`；否则等于基础状态。暂停任务不能打卡或再次暂停，恢复后继续保持 `IN_PROGRESS`。

## 5. 数据模型

### 5.1 任务实例扩展

`learn_task_assignment` 的状态约束扩展为完整状态集合，新增 `last_transition_at` 和 `version_no`。状态更新使用主键、学生或审核人、期望状态和版本号共同约束。

### 5.2 状态事件

`learn_task_assignment_event` 记录事件类型、操作人、变更前后状态、原因和发生时间。暂停事件的前后基础状态均为 `IN_PROGRESS`。

### 5.3 暂停记录

`learn_task_pause` 记录暂停类型、开始人、开始时间、到期时间、恢复时间和关闭方式。服务层通过任务实例行锁保证同一任务最多一个有效暂停。

### 5.4 打卡记录

`learn_task_checkin` 记录提交序号、文字内容、状态、提交人、提交时间、审核人、审核时间和审核意见。每个任务实例的提交序号从 1 递增，驳回后旧记录保留为 `REJECTED`。

附件不在打卡表保存路径或外部地址。后续使用统一 `sys_file_relation`，模块编码为 `LEARNING_TASK_CHECKIN`，业务标识为打卡记录雪花标识。

### 5.5 审核转交

`learn_task_reviewer_transfer` 记录原审核人、新审核人、转交人、原因和时间；任务实例的当前审核人和转交记录在同一事务更新。

所有新增表使用应用层生成的 19 位雪花 `BIGINT` 主键，不使用自增、触发器或数据库序列。

## 6. 权限与范围

新增权限：

| 权限 | 客户端 | 默认角色 |
|---|---|---|
| `TASK_ASSIGNMENT_EXECUTE_SELF` | MINIAPP | 学生 |
| `TASK_ASSIGNMENT_REVIEW` | WEB | 家长、机构管理员、教师 |
| `TASK_ASSIGNMENT_EXEMPT` | WEB | 家长、机构管理员、教师 |

学生执行服务只从当前小程序会话解析学生档案，不接受学生标识参数。审核待办只返回 `current_reviewer_id` 等于当前用户的任务。免执行还需校验任务来源：家庭任务限活动主家长，教师任务限创建教师或来源班级组织管理员，机构任务限来源组织数据范围内的机构管理员。

审核候选人必须启用且与任务来源一致：家庭任务候选人为活动主家长；教师任务候选人为来源班级活动教师；机构任务候选人为覆盖目标学生的活动教师或来源组织范围管理员。客户端不得自行扩大候选范围。

## 7. 接口设计

### 7.1 小程序学生接口

| 方法与路径 | 用途 |
|---|---|
| `POST /api/v1/task-assignments/{id}/claim` | 认领本人待认领任务 |
| `POST /api/v1/task-assignments/{id}/pause` | 暂停本人进行中任务 |
| `POST /api/v1/task-assignments/{id}/resume` | 恢复本人暂停任务 |
| `POST /api/v1/task-assignments/{id}/abandon` | 放弃本人进行中任务 |
| `POST /api/v1/task-assignments/{id}/check-ins` | 提交本人文字打卡 |

所有操作返回更新后的本人任务详情。重复操作或非法状态返回 `409 STATE_CONFLICT`，跨学生标识统一返回 `404 RESOURCE_NOT_FOUND`。

### 7.2 Web 审核接口

| 方法与路径 | 用途 |
|---|---|
| `GET /api/v1/task-reviews` | 当前审核人待审核分页 |
| `GET /api/v1/task-reviews/{assignmentId}` | 当前审核人读取任务与最近打卡 |
| `GET /api/v1/task-reviews/{assignmentId}/reviewer-options` | 服务端裁剪审核候选人 |
| `POST /api/v1/task-reviews/{assignmentId}/reject` | 驳回最近一次待审核打卡 |
| `POST /api/v1/task-reviews/{assignmentId}/transfer` | 转交审核责任 |
| `POST /api/v1/managed-task-assignments/{assignmentId}/exempt` | 授权管理角色设置免执行 |

V23 不存在审核通过接口。客户端即使构造请求也只能得到 404 或方法不允许，不得直接把任务更新为 `COMPLETED`。

## 8. 事务和并发

1. 每个写操作先 `SELECT ... FOR UPDATE` 锁定任务实例。
2. 校验当前用户、功能开关、客户端、RBAC、对象范围、状态和暂停状态。
3. 写入暂停、打卡或转交明细。
4. 使用期望状态和版本号更新任务实例。
5. 写入状态事件后提交事务，任一步失败整单回滚。
6. 重复点击、并发请求和旧页面提交最多一个成功，其余返回状态冲突。

## 9. 页面行为

小程序详情根据有效状态显示操作：待认领显示“认领任务”；进行中显示“提交打卡”“暂停”“放弃”；暂停显示“继续任务”；待审核、待优化和免执行只显示中性状态说明。打卡内容离开页面或提交成功后清空，不进入本地持久化。

Web 学习任务页增加“审核待办”视图。待办列表展示任务标题、学生、来源、提交时间和当前审核人；详情展示文字打卡、历史提交次数、驳回和转交操作，不展示审核通过按钮。

## 10. 验收基线

1. 状态机、并发、跨学生访问、功能开关和客户端隔离测试通过。
2. 暂停最长 2 小时，重复暂停和未暂停恢复被拒绝。
3. 驳回意见必填且最长 500 字，旧打卡记录不可覆盖。
4. 转交候选项由服务端按来源和数据范围生成，转交历史完整。
5. 免执行不产生积分、待优化或待审核记录。
6. Web、H5 和微信小程序独立构建通过，功能停用时入口、直达页和接口一致阻断。
7. 本地测试不连接远程 MySQL、Redis、微信或生产服务。
