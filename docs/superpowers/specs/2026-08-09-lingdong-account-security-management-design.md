# 灵动学习 V39 设备会话与账号安全管理设计

## 1. 目标与依据

V39 完成原始需求中的多设备自主管理和异常设备风险提醒：所有角色可查看自己的活动设备、退出当前设备、下线指定陌生设备和一键全端下线；学生端具备同等能力。系统记录站内安全事件，并在用户登录后展示未读风险提醒。本版本不发送真实短信、微信服务通知或站外消息。

现有 V15 已具备可撤销设备会话表及设备列表、当前退出、指定设备下线和全部下线后端接口，Web 工作台已有未完整测试的设备操作区，小程序仅支持当前退出。V39 复用这些事实和接口，不重建会话体系。

## 2. 方案选择

采用“现有设备会话 + 独立安全事件表”。设备会话继续表示当前认证状态，安全事件保存登录和下线事实及未读状态。该方案比直接向会话表追加提醒字段更容易追溯，也不依赖尚未建设的通用消息中心。后续消息中心可读取相同事件事实，但不得反向改变认证状态。

不采用把安全事件混入 `auth_device_session` 的方案，因为会话轮换、失效和下线会覆盖状态，无法稳定表示用户是否已阅读提醒。不采用直接建设通用消息中心，因为短信、微信通知、夜间抑制和消息跳转属于独立工作包，会扩大本次范围。

## 3. 范围与非范围

V39 范围：

1. Web、H5 和微信小程序查看当前账号全部仍可刷新的活动设备。
2. 明确标识当前会话，当前设备使用“退出当前设备”，其他设备使用“下线设备”。
3. 一键全端下线撤销全部活动会话，包括发起操作的当前会话。
4. 用户、客户端类型和设备标识组合首次出现时，记录新设备登录风险事件；后续相同组合不重复提醒。
5. 指定设备下线和全部设备下线记录普通安全事件。
6. 查询本人安全事件、标记单条已读和全部已读；登录后展示未读风险提醒。
7. 家长和学生小程序会话、设备入口及退出逻辑保持独立，不相互覆盖或清除。
8. `ACCOUNT_SECURITY_MANAGEMENT` 后台开关控制设备管理和安全提醒入口及相应管理接口。

V39 非范围：IP 地理位置判断、设备指纹 SDK、短信或微信通知、通用消息中心、强制单设备登录、互踢、账号换绑、账号注销、管理员代用户下线、离线数据 100MB 管理。

## 4. 新设备判定

“异常设备”在当前可落地条件下固定解释为首次出现设备，不推测地理位置或硬件风险。服务端在创建会话前，按 `user_id + client_type + device_id` 查询历史设备会话：

- 存在历史会话：视为已知设备，不生成新设备风险提醒。
- 不存在历史会话：创建会话成功后生成 `NEW_DEVICE_LOGIN` 安全事件。
- Web、家长小程序和学生小程序使用不同客户端或不同设备标识时分别判断。
- 应用重新安装导致设备标识变化时，按新设备处理。
- 并发首次登录由安全事件唯一范围键兜底，同一设备最多产生一条首次登录事件。

设备标识只用于服务端会话识别。安全事件保存 SHA-256 摘要，不向 Web、小程序、日志或异常返回原始设备标识。

## 5. 数据模型

V39 新增 `auth_security_event`：

| 字段 | 规则 |
|---|---|
| `id` | 应用层生成的 19 位雪花 `BIGINT` 主键，禁止自增。 |
| `user_id` | 事件所属用户，外键关联 `sys_user`。 |
| `session_id` | 可空关联会话标识；会话删除不级联删除事件。 |
| `event_type` | `NEW_DEVICE_LOGIN`、`DEVICE_REVOKED`、`ALL_SESSIONS_REVOKED`。 |
| `risk_level` | `WARNING` 或 `INFO`；只有新设备登录为 `WARNING`。 |
| `client_type` | `WEB` 或 `MINIAPP`。 |
| `device_name` | 事件发生时的展示名称，最长 100 字符。 |
| `device_fingerprint_hash` | 原始设备标识的 SHA-256 摘要，不对客户端返回。 |
| `event_scope_key` | 新设备使用 `DEVICE:<摘要>`，其他事件使用 `EVENT:<事件雪花标识>`。 |
| `status` | `UNREAD` 或 `READ`。 |
| `occurred_at`、`read_at` | 发生时间和可空已读时间。 |
| `created_at`、`updated_at` | 数据库审计时间。 |

`(user_id, event_type, event_scope_key)` 唯一，保证同一设备首次登录风险事件只生成一次。按 `user_id + status + occurred_at` 建立查询索引。事件不保存令牌、密码、手机号、来源地址或完整设备标识。

V39 为 `auth_device_session(user_id, client_type, device_id)` 增加历史设备判定索引，不修改 V1-V38。迁移后共有 67 张显式非自增主键表，后续迁移从 V40 开始。

## 6. 应用与事务

### 6.1 登录

`AuthenticationApplicationService.createSession` 在插入新会话前查询设备是否历史出现。会话插入成功后，由 `AccountSecurityEventService` 在同一数据库事务记录首次设备事件。并发唯一冲突按“事件已存在”处理，不回滚已经成功的合法会话。

平台密码、家长短信、家长密码、家长微信、学生账号和学生扫码最终都复用 `createSession`，因此新设备规则统一生效，不在各登录流程重复实现。

### 6.2 设备下线

指定设备下线先校验会话归属和活动状态，条件更新成功后记录 `DEVICE_REVOKED`。一键全端下线先锁定或读取当前活动会话摘要，批量撤销成功后记录一条 `ALL_SESSIONS_REVOKED`。当前正常退出只更新为 `SIGNED_OUT`，不产生风险提醒。

账号停用或锁定导致的后台会话撤销沿用现有行为，本版本不伪装成用户主动下线事件。

### 6.3 查询与已读

安全事件只允许所属用户读取和标记已读，默认按发生时间倒序，单次最多 50 条。标记已读使用带 `user_id` 和 `UNREAD` 条件的更新；重复操作幂等。功能停用时设备管理和安全事件管理接口拒绝，但当前会话退出和内部安全事实记录继续可用。

设备列表仅返回字符串会话标识、客户端、设备名称、当前会话标识、访问/刷新到期时间和最近活动时间，不再返回原始设备标识。列表排除刷新凭证已经到期的历史会话。

## 7. HTTP 契约

沿用：

- `DELETE /api/v1/auth/sessions/current`：退出当前会话，不受管理开关影响。
- `GET /api/v1/auth/devices`：查询本人有效活动设备，增加 `current` 字段。
- `DELETE /api/v1/auth/devices/{sessionId}`：下线本人指定设备。
- `POST /api/v1/auth/devices/sign-out-all`：撤销本人全部活动会话。

新增：

- `GET /api/v1/auth/security-events?unreadOnly=true|false`：查询本人最近 50 条安全事件。
- `POST /api/v1/auth/security-events/{eventId}/read`：标记本人单条事件已读，返回 204。
- `POST /api/v1/auth/security-events/read-all`：标记本人全部未读事件已读，返回 204。

事件响应包含字符串事件标识、事件类型、风险级别、客户端、设备名称、状态、发生时间和已读时间；不返回 `user_id`、`session_id`、设备摘要和内部范围键。对象不属于当前用户时按资源不存在处理。

## 8. 前端交互

### 8.1 Web

工作台保留设备区并增加自动化测试。当前设备显示“当前设备”标签，操作为“退出当前设备”；其他设备使用图标按钮下线。全部下线必须二次确认并在成功后清除本地 Web 会话。

工作台加载未读安全事件。存在 `WARNING` 时在设备区上方显示风险提醒，可查看事件列表、标记单条已读或全部已读。功能开关关闭后隐藏设备管理和安全事件区，当前退出仍保留。

### 8.2 uni-app

新增设备与安全页，由家长首页和学生首页分别携带明确身份参数进入。页面只读取对应身份的本地会话和令牌；家长操作不得清除学生会话，学生操作不得清除家长会话。

页面展示当前设备、其他 Web/小程序设备和最近安全事件，支持指定下线、全部下线、单条已读和全部已读。全部下线后只清除当前身份本地会话并返回角色选择页。功能关闭后入口隐藏，直达页读取公开能力后拒绝操作。

## 9. 安全与错误处理

1. 设备和事件接口使用当前认证身份，不接收请求体用户标识。
2. 指定设备和事件不属于当前用户时返回资源不存在，防止标识枚举。
3. 会话、事件及功能开关标识按字符串传输，避免 JavaScript 丢失 19 位数字精度。
4. 所有下线操作使用条件更新；重复下线幂等，不恢复已失效会话。
5. 日志、响应和前端存储不得出现访问/刷新令牌摘要、设备标识原文或设备指纹摘要。
6. 站内提醒失败不恢复已成功登录或下线的核心状态；数据库写入异常则按同一事务回滚。
7. 系统继续允许同一账号多设备同时在线，不增加强制互踢或设备数量上限。

## 10. 测试与验收

1. Flyway 从空库连续执行 V1-V39，验证 67 张非自增主键表、19 位基础数据、事件约束、索引和功能开关。
2. 真实 MyBatis 测试覆盖首次设备事件、同设备不重复、不同客户端分别提醒、并发唯一、已读幂等、越权不可见和过期会话不出现在设备列表。
3. 回归平台、家长短信/密码/微信、学生账号/扫码登录，确认全部经过统一新设备判定且原会话签发行为不变。
4. Web 测试覆盖当前设备、其他设备下线、全部下线、风险提醒、已读和功能停用。
5. uni-app 类型检查与双端构建覆盖家长/学生独立入口、令牌使用、会话清理和直达拦截。
6. 全量验证只使用本地 H2、测试短信/微信适配器和本地前端工具链；不在远程 MySQL、Redis、共享测试、预生产或生产环境执行迁移。
