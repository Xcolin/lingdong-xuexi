# 灵动学习 V35 学生扫码登录设计

## 1. 需求依据

- 登录二维码由主家长或学生当前机构的直接机构管理员在学生详情中生成。
- 二维码有效期为 5 分钟，只能使用一次；展示端到期后自动刷新。
- 学生使用小程序扫码后，仍需输入该学生的 4 位登录码。
- 扫码失败、二维码失效或登录码错误时，不建立会话，并提示重新扫码。
- 功能由后台开关控制；停用后 Web 入口和小程序扫码入口全部隐藏，后端同步拒绝访问。

## 2. 范围与边界

### 2.1 本次实现

- 新增扫码登录功能开关与二维码签发权限。
- 新增二维码票据表、签发、消费和失效处理。
- 新增 Web 学生登录管理页面，供主家长和直接机构管理员查看学生并生成登录二维码。
- 新增 uni-app 扫码登录入口和登录码确认流程。
- 复用既有学生登录码风控、验证码、账号锁定和小程序会话。

### 2.2 本次不实现

- 不实现微信授权登录、手机号短信登录和副家长绑定。
- 不接入真实微信、短信或地图服务。
- 二维码不承载学生账号、姓名、登录码或其他个人信息。

## 3. 数据设计

新增 `auth_student_qr_ticket`：

| 字段 | 规则 |
|---|---|
| `id` | 应用层雪花算法生成的 19 位 `BIGINT` 主键 |
| `student_id` | 对应学生档案 |
| `student_user_id` | 对应学生登录用户，便于消费时锁定目标 |
| `token_hash` | 随机票据经 SHA-256 摘要后的十六进制值，唯一 |
| `status` | `ACTIVE`、`CONSUMED`、`REVOKED` |
| `expires_at` | 签发时间后 5 分钟 |
| `consumed_at` | 首次扫码消费时间 |
| `issued_by_user_id` | 签发人 |
| `created_at`、`updated_at` | 审计时间 |

同一学生签发新票据时，先将旧的 `ACTIVE` 票据改为 `REVOKED`。过期状态由 `expires_at` 判定，不依赖定时任务。

## 4. 安全与并发

1. 服务端生成至少 32 字节安全随机数，只返回原始票据一次，数据库仅保存摘要。
2. 签发人必须是学生主家长，或学生当前机构的直接机构管理员。
3. 扫码登录接口先按摘要执行 `FOR UPDATE`，校验状态和有效期后原子更新为 `CONSUMED`。
4. 票据在登录码正确或错误时均只允许消费一次；登录失败后必须重新扫码。
5. 登录码校验复用既有失败次数、图形验证码、账号锁定和设备限流规则。
6. 功能停用时，签发和消费接口都返回 `FEATURE_DISABLED`。
7. 二维码内容格式为 `lingdong-learning://student-login?ticket=<随机票据>`，不含业务主键和个人信息。

## 5. 接口设计

### 5.1 签发二维码票据

`POST /api/v1/students/{studentId}/login-qr-tickets`

- 客户端：Web。
- 权限：`STUDENT_LOGIN_QR_CREATE`。
- 响应：`ticketId`、`qrContent`、`expiresAt`。

### 5.2 扫码登录

`POST /api/v1/auth/student-sessions/qr`

- 客户端：uni-app，公开预认证接口。
- 请求：`qrContent`、`loginCode`、`deviceId`、`deviceName`，以及需要时的图形验证码字段。
- 响应：既有学生 `SessionResponse`。

## 6. 前端交互

### 6.1 Web

- 新增“学生登录”菜单，只有功能开启且当前角色为家长或机构管理员时可见。
- 页面按当前用户数据范围列出学生，点击“登录二维码”打开弹窗。
- 弹窗展示二维码、到期倒计时和手动刷新按钮；到期后自动签发新票据。
- 关闭弹窗即停止计时，不在浏览器持久化原始票据。

### 6.2 uni-app

- 学生登录页在功能开启时展示“扫码登录”入口。
- 扫描成功后只保留二维码内容于当前页面内存，并要求输入 4 位登录码。
- 登录成功后清空二维码和登录码并进入学生首页。
- 二维码无效、过期、已使用或登录码错误时清空扫码结果，提示重新扫码。

## 7. 验收基线

- 主家长和直接机构管理员可签发其范围内学生二维码，其他用户或越权对象不可签发。
- 新票据会撤销同一学生旧票据，票据 5 分钟后不可用。
- 同一票据并发请求最多一个进入登录码校验流程，且不能建立两个会话。
- 错误登录码会消费票据，并累加既有学生登录失败次数。
- 功能停用后两端入口隐藏，直接调用签发和扫码接口均失败。
- Flyway、后端测试、Web 测试与构建、uni-app 类型检查和双端构建全部通过。
