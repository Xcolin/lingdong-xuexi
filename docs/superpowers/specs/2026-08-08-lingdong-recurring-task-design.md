# 灵动学习 V30 每日固定任务设计

## 1. 目标与边界

V30 为家庭、机构和教师来源的已发布任务增加“每日固定任务”能力。一个固定任务始终复用同一个 `learn_task.id`，按计划自然日生成独立 `learn_task_assignment`，使 V29 能按同一任务标识连续计算积分衰减。

本版本只实现原始需求能够确定的每日重复，不扩展每周、自定义星期、法定节假日、Cron 表达式或复杂排除日。任务计划日期是首个执行日；结束日期可不填，未填写时持续到管理者主动停止。停止只阻止尚未生成的未来实例，不删除或修改历史实例。

“复制昨日任务”仍是另一个业务功能：复制会创建新任务标识，不进入原固定任务的衰减连续链。V30 不实现复制昨日、待优化顺延、23:59 自动逾期、任务模板或家长/教师小程序管理入口。

## 2. 方案选择

1. 每日复制任务定义：实现直观，但每天产生新任务标识，与已确认衰减规则冲突，不采用。
2. 在 `learn_task` 直接保存调度游标：字段少，但任务定义、运行状态、失败恢复和停止审计混杂，不采用。
3. 独立周期计划：新增一张计划表引用同一任务，任务定义保持稳定，调度游标和停止状态独立审计，采用此方案。

## 3. 数据模型

新增 `learn_task_recurrence`：

| 字段 | 规则 |
|---|---|
| `id` | 应用层生成的 19 位雪花 `BIGINT` 主键。 |
| `task_id` | 唯一引用一个已发布任务；一个任务最多一个周期计划。 |
| `frequency_type` | V30 固定为 `DAILY`。 |
| `start_date` | 等于任务计划日期，不允许早于任务计划日期。 |
| `end_date` | 可空；非空时不得早于开始日。 |
| `next_generation_date` | 下一个尚未生成的计划日；首日由发布事务生成后初始化为开始日加一天。 |
| `status` | `ACTIVE`、`COMPLETED`、`STOPPED`。 |
| `stopped_by_user_id`、`stopped_at` | 主动停止审计；自动结束时为空。 |
| `version_no` | 条件更新和并发保护。 |
| `created_at`、`updated_at` | 创建与更新时间。 |

`learn_task` 增加 `recurrence_enabled` 和可空 `recurrence_end_date`，用于草稿输入与管理查询。周期计划是运行时事实，草稿字段是发布前配置快照。V30 新增的表主键禁止自增，基础迁移不写远程连接或密钥。

## 4. 创建、发布与停止流程

1. 管理者创建或编辑草稿时可选择“每日固定任务”，并可填写结束日期。结束日期必须不早于计划日期；非固定任务不得携带结束日期。
2. 现有来源、目标、审核人、组织和对象范围校验保持不变。固定任务不扩大管理者的数据范围。
3. 发布事务先按任务计划日期生成首日学生实例，再把任务置为 `PUBLISHED`；固定任务同时创建 `ACTIVE` 周期计划，`next_generation_date` 为首日加一天。
4. 任务和周期计划均由唯一约束及行锁防止重复发布。发布任一步失败时，首日实例、周期计划和任务状态整体回滚。
5. 只有原任务当前可管理角色可以停止周期计划。停止操作锁定任务和计划，把 `ACTIVE` 改为 `STOPPED` 并记录操作人、时间；重复停止返回状态冲突。
6. 已生成实例继续按原状态机执行、审核和发奖，停止计划不得删除实例或改写积分。

## 5. 自动生成流程

后台任务使用 `Asia/Shanghai` 时区，每日 00:05 执行，测试环境默认关闭：

1. 先校验 `LEARNING_TASK_MANAGEMENT` 开关；关闭时不生成实例，也不推进游标。
2. 按周期计划雪花标识游标分页读取 `ACTIVE` 且 `next_generation_date <= 当日` 的计划。
3. 每个周期计划使用独立事务和行锁处理，单个计划失败只记录任务标识、计划标识和中性错误摘要，不阻断其他计划。
4. 按日期从 `next_generation_date` 逐日处理到当日。每个日期重新使用现有目标展开服务读取当前启用学生，按 `(task_id, student_id, scheduled_date)` 查询并跳过已存在实例，再为缺失学生生成 `PENDING_CLAIM` 实例。
5. 实例审核人、来源类型和来源组织取任务定义快照，截止时间为对应计划日 23:59:59。没有有效学生时，该日期仍推进游标并记录 0 条结果，避免计划永久卡住。
6. 每完成一个日期即推进 `next_generation_date`。超过非空结束日期后把计划置为 `COMPLETED`；重复执行依靠唯一约束和已存在查询保持幂等。

服务停机恢复后会补生成游标至当日的缺失实例。组织或班级历史成员快照当前不存在，因此补生成按恢复时可查询到的活动目标展开；该限制必须在真实环境运维和后续组织历史化设计中保留记录，不能宣称为历史成员精确回放。

## 6. API 与前端

既有任务创建和更新请求增加：

- `recurrenceEnabled`：布尔值，默认 `false`。
- `recurrenceEndDate`：可空 ISO 自然日，仅在启用每日固定任务时有效。

任务详情和列表返回同名字段，以及可空 `recurrenceStatus`、`nextGenerationDate`。新增 `POST /api/v1/learning-tasks/{taskId}/recurrence/stop`，成功返回任务标识、周期状态和停止时间；客户端不提交用户、来源、目标或调度游标。

Web 任务表单使用开关控制“每日固定任务”，启用后显示可空结束日期；已发布且周期活动的任务提供“停止每日生成”操作并二次确认。uni-app 学生端无需增加配置入口，自动生成实例按原任务列表和详情展示。家长与教师的小程序任务管理依赖对应移动端身份与管理能力，留在 WBS-03 后续子任务，不能复用学生会话绕过。

## 7. 权限、错误与幂等

- 创建、编辑、发布、停止和后台生成均受 `LEARNING_TASK_MANAGEMENT` 后端开关约束。
- 停止接口复用现有任务 `requireManageable` 范围；越权或不可见任务统一返回资源不存在。
- 非法结束日期返回参数错误；非草稿修改周期、非活动计划停止、并发旧请求返回状态冲突。
- 调度任务不伪造登录用户，也不重新授予权限；它只执行已由合法管理者发布并仍为 `PUBLISHED` 的计划，目标展开继续限制为当前启用关系。
- `task_id` 唯一计划约束和 `(task_id, student_id, scheduled_date)` 实例唯一约束共同保证重试不重复。

## 8. 测试与验收

1. Flyway 从空库执行到 V30，核对 55 张表、草稿字段、外键、状态检查、唯一约束和全部非自增 19 位雪花主键。
2. 校验非固定任务、无限期固定任务、有结束日固定任务、结束日早于开始日和非固定任务携带结束日。
3. 发布固定任务时首日实例与周期计划原子生成；重复发布和事务失败不留下重复计划。
4. 调度覆盖逐日补生成、结束日自动完成、目标为空、重复执行、功能停用、并发幂等和单计划失败隔离。
5. 停止覆盖合法管理者、越权、重复停止及历史实例不变。
6. 回归 V29：同一固定任务跨日期实例使用相同任务标识并连续衰减；复制功能未来创建的新任务标识不受 V30 影响。
7. Web 覆盖表单联动、请求字段、列表状态和停止确认；小程序回归生成实例仍可正常认领、执行和打卡。
8. 全量验证只使用本地 H2 和本地前端工具链，不连接远程 MySQL、Redis、微信、共享测试、预生产或生产环境。
