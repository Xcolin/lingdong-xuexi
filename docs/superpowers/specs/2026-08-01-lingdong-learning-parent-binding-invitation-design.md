# 灵动学习机构邀请家长绑定设计

## 1. 目标与范围

本设计对应 V20，只解决“机构创建学生后，邀请既有家长账号确认成为该学生主家长”的关系闭环。机构和家长仍是独立主体；机构通过该关系只能继续读取学生的机构数据，不能读取家庭任务、奖励、家庭积分配置或家庭复盘。

本轮实现创建邀请、确认接受、拒绝、过期重发和审计时间，不实现短信、微信、站内消息投递、小程序页面、家长自注册、学生账号、学生登录码、二维码、副家长、解绑、主家长变更、转班转学或注销。

## 2. 参与方与流程

1. 机构管理员对自己直接管理组织下、尚未建立主家长关系的学生创建邀请。
2. 后端生成高熵一次性确认令牌；数据库仅保存 SHA-256 摘要，原始令牌只在创建响应中返回一次，供机构通过线下受控渠道交给家长。
3. 已登录并拥有 `PARENT` 角色的家长携带邀请标识和原始令牌接受或拒绝邀请。
4. 接受时，在同一事务内将邀请置为 `ACCEPTED`，并写入 `edu_parent_student` 的唯一主家长关系；任何并发或既有主家长冲突均返回状态冲突，不覆盖既有关系。
5. 拒绝时邀请置为 `REJECTED`。创建新邀请前会将已过期的待处理邀请置为 `EXPIRED`；未过期待处理邀请不允许重复创建。

邀请有效期固定为 7 天，与既有 FSD 的机构邀请规则一致。V20 不发送通知，因此“邀请”在技术上是一次受控令牌签发；真实消息投递将由后续通知和微信能力完成。

## 3. 权限与数据范围

| 操作 | 路由权限 | 服务端范围规则 |
|---|---|---|
| 创建机构家长邀请 | `STUDENT_PARENT_INVITE_CREATE` | 当前用户必须有 `ORG_ADMIN`，是学生活动机构关系所属组织的直接组织管理员，且学生没有主家长。 |
| 接受/拒绝邀请 | `STUDENT_PARENT_INVITE_RESPOND` | 当前用户必须有 `PARENT`，令牌正确、邀请待处理且未过期。 |

系统管理员不以管理身份代替机构管理员发起邀请，也不以管理身份代替家长接受邀请。接口从 Bearer 会话取得操作者，绝不接收请求体中的家长、机构管理员或学生范围声明。邀请标识、令牌错误、过期、已完成和无访问范围均使用不泄露额外信息的响应。

## 4. 数据模型与约束

V20 新增 `edu_parent_binding_invitation`：

| 字段 | 说明 |
|---|---|
| `id` | 应用层生成的 19 位雪花主键。 |
| `student_id`、`organization_id`、`inviter_user_id` | 邀请对象、发起机构和发起人，均为外键。 |
| `token_hash` | 原始令牌的 SHA-256 摘要，唯一且不对外返回。 |
| `status` | `PENDING`、`ACCEPTED`、`REJECTED`、`EXPIRED`。 |
| `pending_scope_key` | 待处理时固定为 `PENDING`；完成时改为 `CLOSED:<邀请标识>`，与 `(student_id, pending_scope_key)` 唯一约束共同保证每名学生最多一个待处理邀请。 |
| `expires_at`、`responded_at`、`responded_by_user_id` | 有效期和响应审计信息。 |

接受邀请继续使用 V19 已有 `edu_parent_student` 的 `(student_id, primary_scope_key)` 唯一约束。新表及权限、角色权限关系的所有 `id` 都使用预生成 19 位雪花常量；运行期实体主键均由 `IdGenerator` 分配。

## 5. HTTP 契约

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/students/{studentId}/parent-invitations` | 机构管理员创建邀请；响应返回邀请摘要、`expiresAt` 与仅本次可见的 `acceptToken`。 |
| `POST` | `/api/v1/parent-invitations/{id}/accept` | 当前家长确认绑定；请求体仅有 `acceptToken`，成功返回 204。 |
| `POST` | `/api/v1/parent-invitations/{id}/reject` | 当前家长拒绝绑定；请求体仅有 `acceptToken`，成功返回 204。 |

所有标识以 JSON 字符串表达。令牌字段最长 128 字符，禁止写入日志、异常消息、文档示例、数据库或前端持久化存储。

## 6. 测试与边界

测试先覆盖以下行为：机构管理员创建邀请并只获得一次令牌；正确家长接受后产生主家长关系；错误令牌拒绝且不改变邀请状态；跨机构管理员不能为其他组织学生创建邀请；已有主家长或未过期待处理邀请不能重复创建；拒绝和过期后的重新邀请可创建；没有新权限的已认证用户返回 403。

全部测试继续在本地 H2 MySQL 兼容模式执行。不得加载 `local` profile、连接、迁移或清理远程 MySQL、Redis、微信或消息服务。
