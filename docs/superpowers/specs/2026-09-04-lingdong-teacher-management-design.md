# V59 教师账号与班级管理设计

## 1. 目标与需求追溯

V59 对应 `BRD-3.1-01`、`BRD-3.1-06`、`BRD-3.6-03` 和 WBS-07，完成机构管理员在授权学校范围内维护教师账号、绑定多个班级、按活动班级限制教师业务数据范围，以及 Web 批量管理。Web 与 uni-app 保持独立前端；复杂批量操作只进入 Web，高频单项操作两端都可使用。

本专项不新增原始需求之外的教师档案字段，不实现教师任务剩余流程、班级统计、考勤或异常报备。教师任务与小程序教师工作台在 V60 接续完成。

## 2. 方案选择

采用独立教师管理模块，复用 `sys_user`、`sys_user_organization`、`sys_user_role` 和 `edu_teacher_class`，不创建重复的教师主表。

未采用直接开放全局用户管理的方案，因为全局目录分页无法天然保证机构数据隔离；未采用新的 XLSX 导入流水线，因为 V59 的批量目标是对已选教师执行有限状态和班级操作，教师文件导入属于后续通用业务导入适配器范围。

## 3. 身份与数据模型

1. 教师账号固定使用 `ORGANIZATION` 用户类型并授予内置 `TEACHER` 角色，用户名全局唯一且创建后不可修改。
2. 创建教师时必须选择一个启用学校，并建立教师到学校的人员组织关系；初始班级可为空或为该学校下多个启用班级。
3. 教师业务数据范围不从前端参数推导，以 `edu_teacher_class` 中的活动班级关系为唯一事实；教师可同时绑定多个班级。
4. V59 新增 `edu_teacher_class_change_log`，不可变记录绑定、解绑、操作人和发生时间；既有关系表继续保存当前有效状态。
5. 所有新主键和基础数据标识均为 19 位雪花数字，不使用自增主键；Flyway 从 V59 连续新增且不修改 V1-V58。

## 4. 功能开关与权限

新增全局功能开关 `TEACHER_MANAGEMENT`。停用后两端隐藏教师管理入口，后端拒绝教师目录、创建、编辑、状态、密码、批量及班级关系维护；历史教师、班级关系和审计日志保留。

新增权限：

| 权限编码 | 客户端 | 用途 |
|---|---|---|
| `TEACHER_READ` | BOTH | 查询授权组织范围内教师及班级 |
| `TEACHER_CREATE` | BOTH | 在授权学校创建教师账号 |
| `TEACHER_UPDATE` | BOTH | 修改教师姓名和手机号 |
| `TEACHER_STATUS_CHANGE` | BOTH | 启用、停用或锁定教师账号 |
| `TEACHER_PASSWORD_RESET` | BOTH | 重置教师登录密码 |
| `TEACHER_BATCH_MANAGE` | WEB | 批量启停、锁定、绑定或解绑班级 |

继续复用 `TEACHER_CLASS_ASSIGN` 作为班级关系写权限。内置机构管理员获得上述最小权限；教师、家长、学生和系统审核员不获得教师维护权限。动态角色可由系统管理员按 RBAC 规则另行授权，但后端仍要求当前操作者是机构管理员并应用组织范围。

## 5. 核心流程

### 5.1 单个创建

1. 后端校验 Web/小程序客户端、功能开关、动态权限和机构管理员角色。
2. 校验学校位于当前操作者有效组织范围内，学校及祖先链均启用。
3. 校验用户名、可选手机号、姓名和初始密码；初始班级必须全部属于所选学校且启用。
4. 同一事务创建用户、设置 BCrypt 密码摘要、建立学校关系、授予教师角色、建立班级关系并写班级变更日志。
5. 任一步失败整体回滚；响应不返回密码或密码摘要。

### 5.2 查询与修改

教师分页查询在 SQL 中按当前组织范围根路径裁剪，支持姓名/账号、学校、班级和状态筛选，默认每页 20 条、最大 100 条。详情只返回账号、姓名、脱敏手机号、学校、活动班级、状态和时间，不返回密码摘要。

用户名和学校关系在 V59 不允许编辑。姓名最多 20 字；手机号可清空或改为系统内唯一值。密码重置由机构管理员输入符合现有密码策略的新密码，服务端只保存 BCrypt 摘要并撤销该教师全部活动会话。

### 5.3 状态与班级关系

停用或锁定教师账号后立即撤销活动会话。若教师仍持有待审核任务，状态变更或对应班级解绑返回冲突，防止生成无人可处理的审核任务。V60 完成自动转交后再替换该临时保护边界。

班级绑定只允许同一学校关系下且位于操作者范围内的启用班级。重复绑定返回当前结果，重复解绑按不存在处理；绑定和解绑均追加不可变变更日志。

### 5.4 Web 批量管理

Web 可选择最多 100 名当前页或跨页已勾选教师，执行启用、停用、锁定、绑定班级或解绑班级。请求只包含操作类型、教师标识集合和按操作需要提供的班级标识。每名教师在独立事务中执行，返回成功/失败逐项结果；一个失败不回滚其他成功项，失败信息不泄露范围外教师是否存在。小程序不提供批量入口。

## 6. API 与前端

后端新增 `/api/v1/organization-teachers` 资源：分页、详情、创建、资料修改、状态修改、密码重置和批量操作。既有 `/api/v1/teachers/{teacherUserId}/classes` 保留，并补上教师管理开关、班级管理开关、待审核保护和变更日志。

React Web 新增独立“教师管理”页面，提供筛选、分页、创建、编辑、状态、密码、班级抽屉和批量工具栏。无权限或开关停用时菜单、路由和按钮均不可见。

uni-app 在机构工作台新增“教师管理”入口和独立页面，提供查询、创建、编辑、状态、密码和单项班级绑定；不包含批量选择、导入和复杂统计。

## 7. 安全与异常

1. 组织范围外教师、学校和班级统一返回不存在，避免对象枚举。
2. 用户名、手机号和密码不写日志；所有响应排除密码摘要，手机号按既有管理端规则脱敏。
3. 创建、资料、状态、密码、绑定和解绑均写既有 IAM 审计或教师班级变更日志。
4. 批量结果只返回请求项标识、成功状态、稳定错误码和中性错误说明。
5. 功能关闭、权限变化、组织停用或角色停用均在每次请求时重新校验，不能依赖前端缓存。

## 8. 验收范围

后端覆盖迁移、19 位主键、单个创建原子性、唯一约束、组织越权、分页范围、编辑、会话撤销、密码策略、待审核保护、班级日志、批量部分成功和功能停用。Web 覆盖入口裁剪、创建、筛选、单项操作、批量结果和直达拒绝；uni-app 覆盖机构管理员单项入口、功能停用隐藏和构建产物不包含 Web 批量逻辑。

本地验证继续只使用 H2、测试密钥和内存替身，不连接远程 MySQL、Redis、微信、共享测试、预生产或生产环境。

## 9. 实施确认

V59 已按本设计完成。实际实现补充了更严格的组合权限：新增教师仅在携带初始班级时追加校验 `TEACHER_CLASS_ASSIGN`；Web 批量状态操作同时要求 `TEACHER_STATUS_CHANGE`，批量班级操作同时要求 `TEACHER_CLASS_ASSIGN`。前端只展示当前组合权限允许的字段和批量操作，小程序不展示批量入口。

2026-09-06 本地验收结果为：Flyway V1-V59 连续迁移、85 张非自增主键表；后端 149 个测试套件、552 项全部通过；Web 31 个测试文件、121 项全部通过并完成类型检查、生产构建及 1440×900、390×844 视觉检查；uni-app 完成类型检查、H5 和微信小程序构建。真实环境与业务 UAT 未执行。
