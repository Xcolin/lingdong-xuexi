# 灵动伴随 V45 学生账号注销设计

## 1. 目标与依据

V45 落实原始材料“学生账号不支持自主注销，仅机构管理员可操作，且必须确认学生已无任何机构关联”的规则。结合原文前后顺序，彻底注销前同时要求所有家长关系均已解绑；无家长但仍有机构关系的学生继续由机构正常管理，不能注销。

原始材料未规定学生注销冷静期、系统审核员审批、证明附件或统一物理删除期限，因此 V45 不照搬家长 7 天冷静期，不采集证明材料，也不新增系统审核流程。系统审核员仍只审批系统管理员提交的系统任务。

## 2. 角色与数据范围

1. 学生、家长、教师、系统管理员和系统审核员均不能发起学生注销。
2. 只有机构管理员可操作，且权限必须同时通过动态 RBAC、客户端和后端数据范围校验。
3. 因注销前活动机构关系必须为零，操作范围取学生最近一次已停用的 `ENROLLMENT` 关系；只有该组织或其上级组织的直接管理员可见并注销。
4. 若学生仍有任一活动机构或班级关系、任一活动主副家长关系，候选列表不展示，提交时也再次拒绝。
5. 从未存在机构入学关系的独立学生没有合法机构核验主体，本版本不开放注销，不允许系统管理员旁路。

## 3. 状态与流程

1. 新增全局功能开关 `STUDENT_ACCOUNT_CANCELLATION`，默认停用；停用时 Web、小程序入口隐藏，候选和注销接口全部拒绝。
2. 机构管理员查询本人范围内满足前置条件的学生，页面展示学生名称、8 位账号和最近停用机构。
3. 管理员填写 1 至 200 字原因，并输入固定确认语句“确认注销学生账号”。
4. 后端锁定学生与对应学生用户，复核学生和用户均启用、具有学生角色、无活动机构关系、无活动家长关系，并重新解析最近停用入学组织的数据范围。
5. 成功后立即执行不可恢复注销：学生档案名称改为“已注销学生”、状态改为 `CANCELLED`；用户名称改为“已注销学生”、用户名改为 `cancelled_student_{studentId}`、手机号和密码摘要清空、状态改为 `CANCELLED`。
6. 删除学生 4 位登录码凭证，撤销全部活动二维码票据和设备会话；任务、积分、奖励、审核、复盘、历史机构关系和历史家长关系继续引用稳定内部标识，不物理级联删除。
7. 写入不可变注销审计，记录 19 位审计标识、学生、学生用户、最近停用机构、操作者、原因、客户端和完成时间，不保存登录码、令牌或直接身份快照。

## 4. 并发与异常

学生行锁是主事务锁，用户行随后锁定。前置关系和范围在锁后复核；档案与用户匿名化、凭证删除、二维码撤销、会话撤销和审计写入位于同一事务。重复提交、状态变化、关系恢复、组织越权或部分写入失败均不产生第二条成功记录，也不留下部分注销状态。

已注销学生不能通过 4 位登录码、二维码、访问令牌或刷新令牌认证，不能被重新启用、重置登录码、重新分班或继续作为新任务目标。历史业务查询以“已注销学生”展示，不恢复原名称或账号。

## 5. 数据库与权限

新增 `V45__add_student_account_cancellation.sql`，不修改 V1-V44：

- `auth_student_account_cancellation`：不可变成功审计，应用层 19 位雪花 `BIGINT` 主键。
- `STUDENT_ACCOUNT_CANCELLATION`：全局内置功能开关，默认 `DISABLED`。
- `STUDENT_ACCOUNT_CANCELLATION_MANAGE`：`BOTH` 操作权限，只授予 `ORG_ADMIN`。

`StudentStatus` 增加不可恢复终态 `CANCELLED`。数据库不增加自增列，不删除历史外键，不设置原始材料未明确的统一留存期限。

## 6. 前端边界

Web 在组织管理页提供独立“注销学生账号”抽屉；uni-app 在机构工作台提供独立页面。两端只共享 API 契约，不共享页面、路由或会话状态。提交采用危险操作样式和二次确认；功能停用时入口隐藏，小程序直达页面重新校验机构会话和公开能力。

## 7. 验收基线

1. V1-V45 空库迁移成功，新增表主键为 19 位非自增 `BIGINT`，功能默认停用且权限只授予机构管理员。
2. 活动机构、活动班级、活动家长、非最近机构管理员、无历史机构、停用账号和功能关闭均拒绝。
3. 成功后学生和用户匿名化为注销终态，登录码删除，二维码与全部会话撤销，审计只追加且历史业务事实保留。
4. Web 与 uni-app 分别通过入口、直达、提交和异常测试；后端、Web、小程序全量验证及静态扫描通过。
