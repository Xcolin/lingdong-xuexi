# 灵动学习班级基础管理设计

**日期**：2026-08-15  
**状态**：本地完成  
**依据**：原始素材 4.4.1，业务需求说明书 BRD-3.1-10、BRD-3.6-02，主开发计划 WBS-05。

## 1. 目标

在不新增原始需求外业务字段的前提下，允许机构管理员在授权学校范围内新增、编辑、启用、停用班级，并复用现有教师班级和学生班级关系。Web 与 uni-app 为独立前端应用，均提供班级高频操作；复杂组织树配置仍只在 Web 平台组织管理中完成。

## 2. 范围

### 2.1 本次实现

1. 班级列表、新增、编辑、启用和停用。
2. 班级字段仅包含班级名称、所属学校、排序、自身状态、有效状态和版本号。
3. 复用现有教师班级绑定和学生班级关系，不新增第二套关系表。
4. 班级停用后阻止新机构/教师任务，并使班内学生尚未完成的机构/教师任务失效。
5. 班级创建、编辑、启停写入不可变组织审计。
6. 独立 `CLASS_MANAGEMENT` 功能开关和 `BOTH` 动态权限。

### 2.2 本次不实现

1. 不新增学年、学制、容量、班主任、教室、课程等原始材料未给出的字段。
2. 不实现班级删除和移动；系统管理员仍通过 V47 高风险组织变更流程处理全局组织移动或受控删除。
3. 不实现批量导入、教师账号创建、考勤、复杂统计和报表。
4. 不执行远程 MySQL、Redis、共享测试、预生产或生产环境变更。

## 3. 角色与权限

| 操作 | 角色 | 权限 | 客户端 |
|---|---|---|---|
| 查询班级 | 机构管理员 | `CLASS_READ` | `BOTH` |
| 新增班级 | 机构管理员 | `CLASS_CREATE` | `BOTH` |
| 编辑班级 | 机构管理员 | `CLASS_UPDATE` | `BOTH` |
| 启用/停用班级 | 机构管理员 | `CLASS_STATUS_CHANGE` | `BOTH` |
| 绑定/解绑教师 | 机构管理员 | `TEACHER_CLASS_ASSIGN` | `BOTH` |

系统管理员和系统审核员不通过班级业务接口处理日常班级维护。系统管理员仍可在平台组织树中维护组织；系统审核员仍只审核系统管理员提交的系统任务。

## 4. 业务规则

### 4.1 班级创建

1. 所属节点必须是有效启用的 `SCHOOL`，且位于当前机构管理员授权范围内。
2. 班级名称必填，去除首尾空白后长度为 1 至 50 个字符。
3. 同一学校下班级名称不得重复；班级必须直接创建在学校下，因此复用组织表同父级名称唯一约束作为并发最终保护。
4. 组织编码由服务端以 `CLS_` 加 19 位雪花标识生成，客户端不输入编码。
5. 新建班级自身状态和有效状态均为 `ENABLED`，版本号为 1。

### 4.2 编辑与状态

1. 编辑只允许修改名称和排序，不允许借编辑接口更换学校。
2. 编辑、启用、停用均提交当前版本号；版本变化返回冲突，不覆盖最新数据。
3. 停用班级保留教师、学生、任务、打卡、积分和审计历史；班级有效状态变为 `DISABLED`。
4. 重新启用要求所属学校仍有效启用；教师和学生关系继续保留，但已失效任务不重新激活。
5. 功能停用时 Web、小程序入口和按钮隐藏，后端列表及写接口均拒绝。

### 4.3 未完成任务失效

1. 班级停用时，锁定班级当前活动学生的机构与教师来源任务实例。
2. `PENDING_CLAIM`、`IN_PROGRESS`、`PENDING_REVIEW`、`NEEDS_IMPROVEMENT` 变为 `INVALIDATED`。
3. `FAMILY`、`COMPLETED`、`EXEMPT` 和已经 `INVALIDATED` 的任务不变。
4. 活动暂停记录以 `TERMINATED` 关闭；每个失效任务写入 `CLASS_INVALIDATED` 事件，原因记录班级停用。
5. 失效任务不产生积分、不进入完成统计，已有打卡和事件历史继续保留。
6. 系统管理员通过 V47 审批停用 `CLASS` 节点时执行同一失效逻辑，避免两套状态口径。

## 5. 接口

| 方法与路径 | 说明 |
|---|---|
| `GET /api/v1/classes/schools` | 返回当前机构管理员授权范围内可用于新增班级的有效学校。 |
| `GET /api/v1/classes` | 返回当前机构管理员授权范围内全部班级，包含停用班级。 |
| `POST /api/v1/classes` | 新增班级。 |
| `PUT /api/v1/classes/{classId}` | 编辑名称与排序。 |
| `POST /api/v1/classes/{classId}/enable` | 重新启用班级。 |
| `POST /api/v1/classes/{classId}/disable` | 二次确认后停用班级并使未完成机构/教师任务失效。 |

全部雪花标识按 JSON 字符串返回。教师绑定继续复用 `/api/v1/teachers/{teacherUserId}/classes/{classId}`，学生关系继续复用现有转班和学员关系接口。

## 6. 数据库与迁移

V48 不新增业务表。迁移内容为：

1. 扩展任务实例状态约束，加入 `INVALIDATED`。
2. 扩展任务事件约束，加入 `CLASS_INVALIDATED`。
3. 扩展组织审计事件约束，加入 `CREATE` 和 `DISABLE`。
4. 初始化 `CLASS_MANAGEMENT` 开关和四项 `BOTH` 权限并授予内置机构管理员。
5. 将既有 `TEACHER_CLASS_ASSIGN` 客户端范围从 `WEB` 调整为 `BOTH`。

V48 基础数据标识全部为 19 位雪花数字，不使用自增列；V47 不修改。

## 7. 验收

1. 跨学校、范围外、停用学校、非学校父节点和同校重名均拒绝。
2. 乐观锁冲突、重复启停和功能关闭均有明确结果。
3. 停用只失效班内未完成机构/教师任务，家庭任务、完成任务、积分及历史不变。
4. Web 和 uni-app 均完成角色、开关、直达页面和二次确认验证。
5. 后端全量测试、Web 全量测试与构建、uni-app 类型检查和双目标构建全部通过。
