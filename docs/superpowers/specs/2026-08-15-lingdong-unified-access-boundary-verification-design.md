# 灵动学习统一访问边界验证设计

## 1. 目标

本专项完成 WBS-05 最后一项验证，使用真实 H2、Flyway、MyBatis、认证会话和 MockMvc 串联检查组织数据范围、动态 RBAC、旧会话和功能停用边界。本专项不新增业务功能，不创建 V51 空迁移。

## 2. 验证矩阵

| 场景 | 预期 |
|---|---|
| 同地区、授权学校下的班级 | 机构管理员可列表和维护。 |
| 另一地区、另一学校及其班级 | 列表不返回，新增或编辑返回不可访问。 |
| 令牌签发后移除权限 | 同一令牌下一请求立即拒绝。 |
| 令牌签发后角色停用 | 同一令牌下一请求立即拒绝，不依赖重新登录。 |
| `CLASS_MANAGEMENT` 停用 | Web、小程序业务接口拒绝，公共能力接口两端均返回关闭。 |

## 3. 安全规则

1. 认证会话中的角色编码只用于界面上下文和角色类型初筛，最终功能权限每次请求从数据库活动角色与权限关系动态判定。
2. 组织数据范围由服务端根据用户、活动角色、用户组织关系和组织管理员范围解析，客户端不能提交可访问根路径。
3. 对越权对象统一返回不存在或不可访问，不泄露另一机构的组织名称、状态或版本。
4. 功能开关在业务应用服务再次校验，不能只依赖前端隐藏。

## 4. 完成边界

本专项完成现有班级管理代表性业务链路的统一拦截矩阵，不等于所有后续机构、教师、报表和导出查询均已接入数据范围组件。`BRD-3.1-06` 在全部业务查询迁移完成前继续保持开发中。
