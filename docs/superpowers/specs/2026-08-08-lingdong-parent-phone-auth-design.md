# 灵动伴随 V36 家长手机号注册与登录设计

## 1. 目标与需求依据

V36 落地家长手机号注册/登录主链路：手机号验证码校验、用户协议、首次登录引导、Web 验证码/密码双方式和 uni-app 家长入口。微信登录、手机号变更、机构人工找回和副家长仍按后续专项实现，不在 V36 假接真实供应商。

## 2. 当前问题

1. `sys_user.mobile` 已由 V4 增加唯一约束，V36 必须复用并增加显式迁移测试，不能重复创建约束。
2. V36 前的通用密码登录只建立 Web 会话，无法正确表达家长小程序客户端边界。
3. 当前小程序只有学生身份入口与学生会话，尚无家长独立路由和存储。
4. 当前没有短信服务端口、验证码一次消费、协议版本接受记录和首次引导状态。

## 3. V36 范围

### 3.1 本次实现

- 手机号 11 位格式归一化并复核 V4 数据库唯一约束。
- `PARENT_PHONE_AUTH` 独立功能开关。
- 短信验证码发送端口、生产未配置失败关闭、本地/测试假实现。
- Redis 保存验证码摘要、5 分钟有效期、发送和校验频控、单次消费；测试使用独立内存实现。
- 家长手机号注册或登录：新手机号创建 `FAMILY` 用户并授予 `PARENT`，已有家长直接登录。
- 当前用户协议版本查询、首次注册同意、协议升级后重新同意。
- Web 验证码与密码双方式；uni-app 独立家长登录、首次引导和家长首页骨架。
- 家长首次引导完成状态；完成前不能进入普通家长业务页。
- 家长密码设置与手机号验证码重置，密码遵循 8 至 20 位字母加数字。

### 3.2 本次不实现

- 不实现微信授权、微信绑定或真实微信调用。
- 不实现更换手机号、原手机号失效时机构人工处理。
- 不实现副家长、注销或家校关系变更。
- 不连接真实短信供应商；供应商确定后实现同一发送端口，不改变业务接口。

## 4. 数据与迁移

### 4.1 `sys_user` 手机号唯一性

- V4 已增加 `mobile` 唯一约束，V36 只补自动化断言，不重复修改历史脚本或创建同名约束。
- `NULL` 仍允许多个，非空手机号全局唯一。
- 家长手机号同时作为初始 `username`，后续换号时账号与手机号同步规则由换号专项定义。

### 4.2 `auth_user_agreement_acceptance`

- 19 位雪花 `BIGINT id` 主键。
- 字段：`user_id`、`agreement_type=PARENT_USER_AGREEMENT`、`agreement_version`、`accepted_at`、`client_type`、`source_address_hash`。
- `(user_id, agreement_type, agreement_version)` 唯一，协议接受事实不覆盖。

### 4.3 `auth_parent_profile`

- 19 位雪花 `BIGINT id` 主键，`user_id` 唯一。
- 字段：`onboarding_status=PENDING|COMPLETED`、`first_login_at`、`onboarding_completed_at`、审计时间。
- 新注册家长固定为 `PENDING`；完成四步引导后原子改为 `COMPLETED`。

## 5. 短信验证码安全

1. 验证码为 6 位数字，安全随机生成，服务端只保存 HMAC 摘要。
2. 固定 5 分钟有效，同手机号、用途和客户端只保留一条有效验证码；校验成功立即删除。
3. 60 秒内最多发送 3 次，达到上限后冷却 60 秒；同时按来源地址限流。
4. 用途至少区分 `REGISTER_OR_LOGIN` 与 `RESET_PASSWORD`，不同用途不能互换。
5. Redis 不可用时失败关闭，不把验证码写入响应、普通日志、数据库或前端存储。
6. 本地假实现只记录投递结果，不打印验证码；自动化测试通过测试专用固定生成器取得验证码。

## 6. 账号和会话规则

1. 首次验证码登录在事务内创建 `FAMILY` 用户、授予内置 `PARENT` 角色、创建家长档案、记录协议接受并建立会话。
2. 已存在手机号必须对应启用的 `FAMILY` 用户并具有 `PARENT` 角色；其他类型、停用或锁定统一返回认证失败，避免账号枚举。
3. Web 家长会话类型为 `WEB`；uni-app 家长会话类型为 `MINIAPP`。学生会话规则保持不变。
4. 登录成功响应增加 `onboardingRequired` 和 `agreementAcceptanceRequired`；需要接受新协议或完成引导时建立受限会话，服务端禁止访问普通业务接口。
5. 通用密码登录允许平台、机构和家长建立 Web 会话；家长专用密码端点按请求建立 Web 或小程序会话；学生继续明确拒绝 Web 密码登录。
6. uni-app 家长会话使用独立存储键、API 和路由，不复用学生本地会话。

## 7. 接口

- `GET /api/v1/public/parent-auth-context`：返回功能能力、当前协议版本和短信倒计时规则。
- `POST /api/v1/auth/parent-sms-codes`：发送注册/登录或重置密码验证码。
- `POST /api/v1/auth/parent-sessions/sms`：家长注册或验证码登录。
- `POST /api/v1/auth/parent-sessions/password`：家长手机号密码登录，显式指定 Web 或小程序客户端。
- `GET /api/v1/auth/parent-state`：已登录家长查询协议和首次引导前置状态。
- `POST /api/v1/auth/parent-passwords`：已登录家长首次设置或修改密码。
- `POST /api/v1/auth/parent-password-resets`：手机号验证码重置密码。
- `POST /api/v1/auth/parent-agreement-acceptances`：协议更新后重新接受。
- `POST /api/v1/parent-onboarding/completion`：完成首次四步引导。

所有认证失败使用中性错误，不返回手机号是否注册、用户类型或账号状态。

## 8. 前端

### 8.1 Web

- 登录页提供“验证码登录”“密码登录”页签，不展示微信入口。
- 验证码按钮有稳定 60 秒倒计时，提交前必须勾选当前用户协议。
- 新注册或协议升级后按服务端状态进入协议/引导流程，完成后进入家长首页。

### 8.2 uni-app

- 角色首页固定家长端、学生端入口；学生现有流程保持独立。
- 家长页默认验证码登录，同时提供密码页签；V36 不展示未实现的微信按钮。
- 首次登录进入四步引导：欢迎、任务模式、产品理念、专注模式；完成后进入家长首页。
- 家长和学生会话不能相互覆盖，退出时只清理当前身份会话。

## 9. 验收

- 并发注册同一手机号最多创建一个家长账号和一条全局角色关系。
- 验证码过期、重复使用、用途错配、超频和 Redis 故障均不能登录。
- 未同意协议、协议版本过期或首次引导未完成时不能进入普通家长业务页。
- Web 不出现微信入口，学生不能通过 Web 密码登录。
- 功能停用后发送、验证码登录、注册和两端入口全部不可用；既有密码登录是否关闭由服务端统一规则验证。
- 全部本地测试与构建不连接远程 MySQL、Redis、短信、微信、共享测试、预生产或生产环境。
