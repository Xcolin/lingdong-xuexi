# 灵动学习 V62 非定位考勤设计

## 1. 设计目标

本专项依据原始素材中的考勤结果字段、BRD 第 4 章考勤统计口径和用户已确认的非定位方案一，建设不依赖地理位置的人工考勤闭环，单列追溯为 `BRD-3.6-11`。这是已确认的实现调整，不把原始地理考勤 `BRD-3.6-07` 改写为人工考勤，也不计作地理能力完成。

本专项只实现：

1. 教师、机构管理员按班级和日期人工登记学生考勤结果。
2. 考勤结果包含正常、迟到、早退、缺勤、请假五种状态。
3. 可记录人工签到时间和签退时间，形成考勤台账。
4. 教师、机构管理员按数据范围查询和更正；家长、学生只读本人结果。
5. Web 提供完整台账、组合筛选和班级点名；uni-app 提供高频点名与个人结果查看。

本专项不实现家长请假申请、请假审批、补卡审批、排班、课程节次、地理围栏、位置采集、地图调用、轨迹记录和自动签到签退。原始需求只把“请假”定义为考勤结果，没有给出申请与审批规则，因此本专项不得自行新增请假审批流程。

## 2. 方案选择

### 2.1 已采用方案

采用“人工班级点名 + 单日学生考勤事实台账”方案。教师或机构管理员选择有效班级和日期，载入当日学生名单，逐人登记考勤状态和可选签到签退时间后提交。同班级同学生同日期只保留一条事实；异内容更正受版本号保护，同内容重试不增加版本。

### 2.2 未采用方案

1. 家长申请、教师审批方案：原始需求没有申请人、审批人、撤回、驳回、超时和证明附件规则，实施会扩充业务。
2. 等待地理考勤方案：会让考勤台账继续受主体资质阻塞，且不能满足当前非定位操作需求。
3. 仅提供单人登记方案：虽然实现简单，但班级考勤操作效率不足，不符合教师高频操作场景。

## 3. 角色与权限

### 3.1 权限码

| 权限码 | 作用 | 默认角色 |
|---|---|---|
| `ATTENDANCE_READ` | 查询考勤台账、班级选项和个人考勤结果 | 机构管理员、教师、家长、学生 |
| `ATTENDANCE_RECORD` | 新增或更正人工考勤结果 | 机构管理员、教师 |

权限由现有动态 RBAC 执行。系统管理员可以将权限分配给新增角色，但数据范围仍必须通过服务端组织、班级或亲子关系校验；系统审核员不参与机构考勤业务。

### 3.2 数据范围

| 身份 | 查询范围 | 操作范围 |
|---|---|---|
| 机构管理员及获授权自定义角色 | 授权组织子树内班级的全部历史考勤 | 限当前启用且实际生效的班级 |
| 教师 | 本人与有效班级关系覆盖的学生考勤 | 与查询范围相同 |
| 家长 | 当前有效亲子关系下学生的机构考勤 | 只读 |
| 学生 | 当前学生账号对应的本人机构考勤 | 只读 |

范围外班级、学生和考勤统一返回“不存在或不可访问”，不得通过响应差异暴露对象是否存在。

## 4. 功能开关与应用隔离

新增全局开关 `ATTENDANCE_MANAGEMENT`，默认启用，用于人工考勤和考勤结果查询。停用后：

1. Web 和 uni-app 隐藏全部人工考勤及考勤结果入口。
2. 后端拒绝查询、登记、更正和选项接口。
3. 历史考勤和动作记录保留，不产生新数据。

`ATTENDANCE_MANAGEMENT` 与 `GEO_ATTENDANCE`、`STUDENT_LOCATION_TRACK` 相互独立。V62 不修改后两者的默认停用状态，不添加位置、坐标、围栏、地图或轨迹字段和接口。微信小程序构建产物继续扫描并确保不包含定位 API。

## 5. 业务规则

### 5.1 每日事实唯一性

同一机构班级、同一学生、同一自然日只允许一条考勤事实，数据库唯一键为：

`class_organization_id + student_id + attendance_date`

学生必须启用，登记时学生班级关系必须处于活动状态，且关系有效期覆盖考勤日期；不允许补录加入班级之前的数据。班级必须启用且实际生效。关系失效或班级停用后保留既有事实，但不能再通过该关系新增或更正，即使目标日期为历史日期。历史查询仍按当前授权范围裁剪。

### 5.2 状态与时间

| 状态 | 中文含义 | 时间规则 |
|---|---|---|
| `NORMAL` | 正常 | 签到、签退时间均可填写 |
| `LATE` | 迟到 | 签到、签退时间均可填写 |
| `EARLY_LEAVE` | 早退 | 签到、签退时间均可填写 |
| `ABSENT` | 缺勤 | 签到、签退时间必须为空 |
| `LEAVE` | 请假 | 签到、签退时间必须为空 |

签到和签退只保存时分，不引入地理信息。两项同时存在时，签到时间不得晚于签退时间。状态由登记人明确选择，V62 不根据时间自动推导迟到或早退，也不自动生成缺勤记录，因为原始需求没有给出考勤时段与人工考勤推导规则。

### 5.3 登记与更正

1. 班级点名接口接收 1 至 100 名学生结果，每名学生独立校验，但整个请求原子提交，任一项失败则全部不写入。
2. 首次提交创建考勤事实和 `CREATE` 动作记录。
3. 已存在记录必须携带当前 `versionNo` 才能更正；成功后版本号加一并写入 `CORRECT` 动作记录。
4. 更正动作保存更正前后状态、时间及操作人；事实和动作均不提供物理删除接口。
5. 完全相同的重复请求返回当前记录，不增加版本号和动作记录，避免网络重试制造无意义历史。

### 5.4 日期边界

考勤日期按系统业务时区 `Asia/Shanghai` 的自然日记录。允许在第 5.1 节有效关系范围内补录和更正历史考勤，不允许登记未来日期。当前停用班级禁止任何日期写入。V62 不提供事实删除或自动销毁；长期留存期限仍需后续留存专项明确，不能宣称已完成永久保留策略。

## 6. 数据设计

### 6.1 `attendance_record`

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | `BIGINT` | 应用层生成 19 位雪花主键，禁止自增 |
| `student_id` | `BIGINT` | 学生标识 |
| `class_organization_id` | `BIGINT` | 班级组织标识 |
| `attendance_date` | `DATE` | 上海时区自然日 |
| `checkin_time` | `TIME` | 可空，人工签到时间 |
| `checkout_time` | `TIME` | 可空，人工签退时间 |
| `status` | `VARCHAR(20)` | 五种考勤状态之一 |
| `source` | `VARCHAR(16)` | V62 固定为 `MANUAL` |
| `recorded_by` | `BIGINT` | 最近登记或更正人 |
| `version_no` | `BIGINT` | 乐观锁版本，初始为 0 |
| `created_at` | `TIMESTAMP` | 创建时间 |
| `updated_at` | `TIMESTAMP` | 最近更新时间 |

### 6.2 `attendance_record_action`

动作表使用 19 位雪花主键，保存考勤标识、`CREATE/CORRECT`、操作人、变更前后状态、变更前后签到签退时间、事实版本号和发生时间。`record_id + version_no` 唯一。动作表只追加，不更新、不删除。

### 6.3 索引与引用保护

1. 唯一索引：班级、学生、考勤日期。
2. 查询索引：班级与日期、学生与日期、状态与日期。
3. 班级组织删除引用检查纳入 `attendance_record.class_organization_id`。
4. 学生、班级和操作人使用外键约束，动作记录引用考勤事实。

## 7. 后端接口

统一前缀为 `/api/v1/attendance-records`。

| 方法与路径 | 权限 | 说明 |
|---|---|---|
| `GET /api/v1/attendance-records` | `ATTENDANCE_READ` | 按班级、学生、日期范围、状态分页查询 |
| `GET /api/v1/attendance-records/class-options` | `ATTENDANCE_READ` | 返回当前身份可访问班级 |
| `GET /api/v1/attendance-records/roster` | `ATTENDANCE_RECORD` | 返回指定班级、日期的活动学生及已有考勤 |
| `POST /api/v1/attendance-records/batch` | `ATTENDANCE_RECORD` | 原子新增或更正班级点名结果 |
| `GET /api/v1/attendance-records/{id}` | `ATTENDANCE_READ` | 查询考勤详情和不可变动作历史 |

分页大小为 1 至 100。日期范围可同时省略，默认最近 30 天；提供时开始日期不得晚于结束日期。后端在每个接口内再次校验功能开关、身份、组织范围和对象关系，不能依赖前端隐藏入口。

### 7.1 实施校正

权限查询和写操作在应用服务内复核动态 RBAC。教师根据有效教师班级关系访问；机构管理员及获授权的自定义角色根据通用组织数据范围访问；纯家长、学生身份保持只读；系统审核员不进入机构考勤业务。历史查询保留停用班级，写操作只允许当前有效班级与学生关系。唯一性为班级、学生和日期组合，同一学生跨班级的记录互不覆盖。更正时提交版本号；相同内容网络重试返回现有记录，不新增历史。无排班情况下未登记不能等同缺勤。详情、筛选、批量载荷与响应字段以 V62 实施计划第 1 节契约为准。

## 8. Web 交互

新增独立 `/attendance-records` 页面：

1. 筛选区支持班级、学生关键字、状态、开始日期和结束日期。
2. 台账展示日期、班级、学生、状态、签到、签退、来源、最近登记人和更新时间。
3. 机构管理员和教师有“班级点名”命令；选择班级和日期后打开点名抽屉，逐生选择状态和填写可选时间，一次提交。
4. 点击记录可查看不可变动作历史。
5. 纯家长和学生身份不提供操作按钮；同时具有机构管理员或教师职责的账号按该工作职责与当前范围决策。复杂汇总统计留到 V64-V65。
6. 台账与详情姓名使用首字掩码；仅通过登记权限及班级范围核验的点名名单显示完整姓名，避免同姓学生混淆。接口不返回完整学生账号、手机号或登录凭证。同名学生仍以字符串学生标识区分，不以姓名作为提交键。

## 9. uni-app 交互

新增独立考勤页面，按登录身份裁剪：

1. 教师、机构管理员：显示可访问班级、日期和学生点名列表，支持单班最多 100 人原子提交。
2. 家长：显示有效亲子关系学生的考勤结果，只读。
3. 学生：显示本人考勤结果，只读。
4. 功能关闭或无权限时，首页入口隐藏；直达页面立即返回角色首页。
5. 页面、API 和构建产物不引用 `getLocation`、`startLocationUpdate`、地图组件、经纬度或轨迹模型。

## 10. 错误处理与并发

1. 功能关闭返回统一功能停用错误。
2. 无权限、无数据范围或对象关系无效时失败关闭。
3. 唯一键冲突转换为并发冲突，不返回数据库异常文本。
4. 版本号不一致返回“考勤记录已被更新，请刷新后重试”。
5. 批量请求包含重复学生、超过 100 人、未来日期、非法状态或非法时间组合时整体拒绝。

## 11. 测试与验收

### 11.1 后端

1. Flyway 验证两张表、唯一键、检查约束、19 位种子和非自增主键。
2. 教师仅可登记本人有效班级；同班其他教师可按班级职责读取和更正，但不能越班。
3. 机构管理员只能处理授权组织树内班级。
4. 家长只读有效关系学生，学生只读本人，系统审核员拒绝访问。
5. 批量原子性、重复请求幂等、乐观锁冲突、历史动作不可变。
6. 功能关闭后所有接口拒绝且不产生新记录。

### 11.2 Web 与 uni-app

1. 开关和权限正确控制入口、直达路由和操作按钮。
2. Web 组合筛选、点名抽屉、详情历史和错误反馈可用。
3. uni-app 四类身份显示正确，家长和学生没有写操作。
4. Web 类型检查、生产构建，uni-app 类型检查、H5 和微信小程序构建通过。
5. 小程序源码和构建产物定位能力扫描命中数为 0。

## 12. 需求追溯和边界结论

| 设计内容 | 需求依据 |
|---|---|
| 五种考勤状态、签到签退、机构和教师范围 | 原始素材 4.4.4、4.5.2，BRD 3.6 |
| 家长和学生仅查看本人结果 | 原始素材 4.3.5、4.4.4，BRD 3.6.7 |
| 考勤台账筛选和统计字段 | BRD 4.2 考勤统计报表 |
| 功能停用隐藏并由后端拒绝 | 已确认的全局功能开关规则，BRD 3.2 |
| 不包含定位、地图和轨迹代码 | 已确认的个人主体工具类目发布约束 |
| 请假仅作为结果、不建设审批流 | 原始素材只给出请假状态，未给出申请审批规则 |

V62 完成后代表非定位人工考勤可本地运行，不代表地理考勤、自动签到签退、请假审批、复杂统计报表、真实消息投递或生产环境联调完成。
