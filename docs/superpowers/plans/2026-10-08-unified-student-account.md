# 统一学生账号与学生档案 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task.

**Goal:** 用户管理与组织用户新增学生均建立同一学生业务链，并补齐xiangsihan。
**Architecture:** 在管理端用户创建事务中复用学生专属凭据、档案、积分账户、角色与学校/班级关系；保持原用户名和账号ID。学校/年级创建入学关系，班级附加入班；其他组织必须显式选择学校。权限和当前机构范围校验保留，不通过扩大候选范围掩盖缺档案。
**Tech Stack:** Spring Boot/MyBatis/MySQL、React/Ant Design。

- [x] 后端统一创建与补齐服务，扩展学生学校与年级输入及HTTP请求，回归同事务、跨范围拒绝、用户名保留和幂等修复。
- [x] 共用新增用户表单按所选组织带学校、年级；其他组织选择学校，学生年级信息必填，避免重复选择；前端回归及构建。
- [x] 只读检查xiangsihan实际档案和关系，使用同一服务补齐，保留已有账号/授权/有效凭据，不创建重复用户。
- [x] 独立复核、串行Maven测试、打包重启、真实接口验证，记录结果。

完成时补充：首次生成登录码仅在受保护创建/补齐POST返回并在创建成功弹窗展示；GET/列表不返回，已有凭据不重置。年级/班级窄范围以当前有效CLASS或未分班的GRADE会员裁剪，旧班级会员不延续读权限，共用SQL按字面路径前缀比较。创建学生后通过不含数据的内部通知刷新一次当前班级。

不重置数据库、不修改其他账号或密码，不提交历史工作区变更。修复仅指定xiangsihan，其他存量学生账号不自动批量猜测归属。若存在冲突学校/班级先报告，禁止覆盖已有有效入学关系。
