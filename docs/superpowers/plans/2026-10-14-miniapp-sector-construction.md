# 小程序按板块施工总计划

日期：2026-10-14。此施工顺序覆盖此前按小步骤或按技术层推进的安排。原78个视图清单及原图基准继续有效，不重新计算为78个独立路由。

## 施工原则

1. 同时只施工一个业务板块。内部按“原型核对 → 页面与接口 → 权限和业务规则 → 联调回归 → 原生对照验收”推进，不横跳其他板块做零散美化。
2. 一个按钮、一条CSS、一次类型检查不是板块完成。每块必须交付可实际使用的完整流程。
3. 已有实现先复核复用，缺接口则在该板块内补齐，不用静态数据或错误业务替代原型。
4. 板块完成直接进入下一板块，不逐项请求用户发送继续。普通进展写施工日志；只在板块里程碑、真实阻塞或需要人操作时汇报。
5. 不使用定时自动推进。保留微信首次关联、四位登录码、家庭/机构切换和Web兼容；不清空真实数据。
6. 所有写入测试在明确隔离fixture完成。候选通过权限、范围和回滚验证后才备份更新本机服务。
7. 功能、构建、视觉验收分别记录；微信原生截图不可用时不得标记视觉验收或整体1:1完成。若仅原生验收受工具阻塞，明确记为待验收，不假报板块完成；可继续该板块剩余独立工作。

## 第一板块：组织与人员管理施工清单

### 1.1 组织架构与基础设置
- [ ] 学校/培训机构 → 校区 → 年级或课程分类 → 班级的真实层级浏览。
- [ ] 新增/编辑所需字段与原型对齐；课程分类学段、学科和描述补真实契约，不做假保存。
- [ ] 父子类型、状态、排序、学校范围、重复名称和非法访问回归。

### 1.2 班级与教师
- [ ] 班级详情、成员搜索、真实数量、教师列表和新增编辑。
- [ ] 教师班级多选、年级/校区层级、全选本校，不能跨校。
- [x] 批量差量接口事务回滚和权限隔离HTTP验证，已备份部署。
- [ ] 客户端真实交互、最终构建与原生对照验收。

### 1.3 组织成员、管理员与负责人
- [ ] 已加入/待加入、关联/移除、组织筛选和范围排序。
- [ ] 设置/撤销管理员与对应角色同步，负责人限制和转交。
- [ ] 用户类型/组织类型规则、孩子/教师自动挂接，失败/重复操作回归。

### 1.4 学员与入学关系
- [x] 隔离同校转班成功、重复目标、恢复原班级及跨校拒绝验证。
- [x] 候选异步旧响应、账号变化、确认弹窗重复提交回归。
- [ ] 入学邀请码、有效期、申请与审核完整链路。
- [ ] 离校关系停用完整隔离验证。
- [ ] 独立转学申请：目标学校、原因、预计日期、证明材料及审批状态机；不得以立即离校功能冒充。

### 1.5 第一板块联合验收
- [ ] 真实角色/权限、组织边界、页面隐藏/切换、双击、失败保留、回滚全部验证。
- [ ] 第一板块所有原型视图的微信原生截图与差异核对。
- [ ] 更新catalog证据并列出确切未解决项；未通过不得写“第一板块完成”。

## 第一板块接续点

教师批量接口和隔离转班已通过部分功能验证，不重复开发。接着核实已有入学邀请/审核与组织成员/管理员链路，完成离校隔离验证；对转学申请及课程分类差距在第一板块内形成具体契约并落实。原生截图通道恢复也属于第一板块验收工作，不跳去其他板块靠零散CSS刷新进度。

## 后续板块统一交付清单

每块开始时列出视图、文件、接口、权限与验收用例；施工中持续记录同一个板块的进度；交付时附成功/失败测试、原生对照、兼容回归与剩余差异。技术细分步骤可参考旧module-delivery计划，但不能改变此业务板块顺序。
