# 灵动学习完整开发实施计划

> **执行要求：** 使用既定实施计划逐项推进，按复选框（`- [ ]`）记录状态；复杂工作包编码前必须完成中文设计和测试驱动实施计划。

**目标：** 在不拆分建设期次、不裁剪已确认需求的前提下，将灵动学习 BRD 全部功能组织为可追溯、可计算进度、可逐项验收的开发任务总表。

**架构：** 项目继续采用 Spring Boot 模块化单体后端、React Web 独立应用和 uni-app 小程序独立应用，共享 API 契约但不共享页面代码和私密配置。总计划只规定需求边界、依赖顺序、完成口径和专项计划入口；每个复杂工作包在编码前单独形成中文设计与 TDD 实施计划。

**技术栈：** Spring Boot 3、JDK 17、Maven 3.9+/4 兼容、MyBatis XML、MySQL 8+、Redis、Flyway、React 18、Ant Design Pro、uni-app/Vue 3。

---

## 1. 计划使用规则

1. 本计划是全项目唯一开发任务总表，不使用“一期、二期”或 MVP 裁剪口径；任务排序只表示技术依赖和施工先后，不改变建设范围。
2. 业务内容优先级依次为《灵动学习业务需求说明书》、已确认的用户调整、`docs/design/00-12`、专项设计与专项计划、当前代码事实。低优先级材料不得覆盖高优先级业务规则。
3. BRD 功能按 `BRD-章节-序号` 建立追溯编号，例如 `BRD-3.5-06` 表示奖励库。编号只用于追踪，不新增业务含义。
4. 每次只允许一个业务工作包处于“开发中”；出现外部资质、供应商或生产参数阻塞时，可切换到不依赖该条件的下一个工作包，但必须记录阻塞项。
5. 后续数据库迁移从 `V35` 连续新增，不修改 `V1-V34`，不预留空迁移号。所有新表主键均为应用层生成的 19 位雪花 `BIGINT`，禁止自增主键。
6. 所有项目文档、代码注释、数据库脚本说明、测试用例说明和界面文案使用中文；标准技术名词、类名、字段名和 API 路径除外。
7. 本地测试不得连接远程 MySQL、Redis、微信服务、共享测试、预生产或生产数据库；真实外部连接必须经过单独批准。

## 2. 完成判定规则

功能点只有同时满足适用项后才能标记“完成”，不能因后端接口存在就计算为整项完成：

| 关口 | 完成证据 |
|---|---|
| 需求与设计 | BRD 编号、角色、流程、状态、字段、异常和端侧边界已写入中文设计，无未确认内容被默认固化。 |
| 数据库 | Flyway 从空库连续迁移成功；表、索引、约束、初始权限和 19 位主键通过自动化断言。 |
| 后端 | API、事务、幂等、并发、状态机、功能开关、RBAC、对象/组织数据范围全部实现。 |
| Web | 仅实现 Web 责任范围；入口、直达路由、权限态、开关态、空态、异常反馈和窄屏布局完整。 |
| 小程序 | 仅实现小程序责任范围；独立会话、入口、直达页、操作反馈和微信构建产物完整。 |
| 测试 | 先观察预期失败，再实现通过；包含主流程、边界、越权、开关、迁移和重复操作。 |
| 文档 | FSD、交互、HLD、数据库、Flyway、API、安全、统计、测试和一致性文档按影响范围同步。 |
| 本地验收 | 后端全量测试、Web 全量测试与构建、小程序类型检查与双目标构建、视觉检查、敏感信息扫描全部通过。 |

状态定义：

- `未开始`：尚无经核对的设计或实现。
- `已设计`：设计已形成，但不能计作代码完成。
- `后端完成`：数据库和后端闭环通过局部测试，前端或全量验收未完成。
- `开发中`：一个或多个适用端正在建设。
- `待本地验收`：代码与文档齐全，尚缺全量回归或视觉检查。
- `本地完成`：全部本地完成关口通过；不等同于真实环境上线。
- `外部阻塞`：依赖主体资质、供应商、域名、证书或生产参数，已完成不依赖外部条件的工作。

4. 专项计划完成后回填本总计划的复选框、工作包状态和得分，同时更新 `docs/design/12-当前实现一致性核对-V1.0.md`。
