# Web 权限体系统一与重建 Implementation Plan

**Goal:** 授权树、登录有效权限、导航、按钮和接口采用同一规范动作定义；授予可用功能后能在对应数据范围执行，无影子权限及隐藏角色门槛。

**Architecture:** 单一动作清单维护页面、规范动作、所属功能、客户端、功能开关、身份及数据范围前提。辅助交互不入权限。页面必要读取与业务动作关系显式定义，服务层只对外操作校验一次；固定默认角色/身份/档案等事务副作用不要求另一组通用权限。角色与用户授权及登录返回通过同一清单和可用性决策处理，显式拒绝优先，数据范围及业务关系仍独立防越权。

**Tech Stack:** Spring Boot/MyBatis/MySQL/Flyway, React/Ant Design/TypeScript/Vitest。

## Task 1: 全量链路审计
- [ ] 对照全部Web actionKey、API控制器注解和服务层校验，输出重复、缺失、组合权限及额外角色条件清单。
- [ ] 对照页面路由canAccess、功能开关和角色/用户授权树，明确不一致触发案例。
- [ ] 区分辅助控件、Web动作、小程序动作、全局配置及身份/业务状态前提。

## Task 2: 统一规范权限
- [ ] 生成可审查的规范清单，菜单/按钮编码直接等于规范权限码。
- [ ] 同功能入口、查询/保存/确认复用同一动作，不独立授权关闭/返回/重试/重置。
- [ ] 页面访问和必要数据读取对齐，权限不可用原因传递到授权树。
- [ ] 关闭功能不允许授权，身份/角色范围不适用的权限标明原因，服务校验与前端相同。

## Task 3: 实施前后端
- [ ] 替换影子actionKey，移除额外旧roleCodes/页面过滤门槛；保留实际身份/关系和组织范围约束。
- [ ] 服务协调器不要求用户另授内部副作用权限，固定组织管理员/账号默认角色等只在范围内维护。
- [ ] 角色/用户授权、实际登录权限和菜单输出使用统一决策。
- [ ] 不可用权限、显式拒绝、继承权限在授权树准确显示。

## Task 4: 数据库重建
- [ ] 在真实数据库清理前完成加密备份并核验可恢复。
- [ ] 用户已授权全部清理；优先重建权限、菜单、基础角色、用户组织与家庭/学校联调关系，不重置运行密钥。
- [ ] 清理重复和遗留配置并初始化规范模块/动作、默认角色和有限联调账号。
- [ ] 全局关闭的功能保持关闭，初始化授权与可用性一致；保留种子登录凭据受控记录。

## Task 5: 验证与交付
- [ ] 覆盖授予、撤销、角色合并、用户覆盖、拒绝优先、禁用角色/菜单/功能、身份/范围不适用。
- [ ] 管理员、家长、家庭管理员、学校管理员、教师、学生及自定义角色逐个核对授权树、auth/me、导航、按钮和真实接口。
- [ ] 同组织操作成功、跨家庭/学校拒绝；角色变更后及时刷新权限。
- [ ] 构建、相关测试、真实库查询及运行健康检查通过，记录清理与初始化结果。
