## 最终行为

- Web 登录页提供“注册账号”；移动端原有登录页提供注册入口。
- 注册默认邮箱验证码，短信宝作为配置可用时的备选方式。接收地址取用户输入，没有固定测试手机号或固定验证码。
- 用户可阅读当前版本协议；账号、密码确认、联系方式、协议版本及服务端密码规则均经过校验。
- 注册建立 PERSONAL 待入驻账号、已验证联系方式、协议记录和会话，不授予任何角色。已有用户名或验证地址不会被覆盖或重复创建。
- 家庭创建后事务内建立 PARENT_ADMIN、组织管理员及负责人，并保留家庭首次引导；学校、培训机构审批通过后才建立组织和范围 ORG_ADMIN。
- 已验证邮箱可以直接提交机构申请，不强制填写或验证手机号。审核任务展示邮箱联系方式。
- “我的组织”从正常菜单、顶部账号入口及移动端常规入口移除；内部入驻进度用于尚未完成入驻的账号。负责人转交在组织管理、移动端家庭/机构首页按真实所有权和权限显示。
- 旧入驻能力目录保持启用，避免隐藏菜单时破坏授权依赖；服务端菜单投影也不会把内部页面返回为导航菜单。
- 已有组织用户进入允许访问的业务页面；新账号、无组织及待审账号进入入驻进度。没有任何可访问页面且入驻读取被拒绝时显示明确状态和退出登录按钮。
- PERSONAL 会话刷新采用单次并发轮换，只同步或清理旧 token 完全匹配的家长、机构副本与组织选择，不触碰其他账号。

## 配置和验证边界

QQ/foxmail 发件邮箱 SMTP 认证已通过。本次流程测试通过本地 SMTP 捕获器执行，没有向真实用户发送验证码，也没有发送收费短信；真实邮件送达和微信真机体验仍需用户实际注册验收。

本地邮箱及短信配置在 `.local-verification` 已忽略文件中，由启动器读入进程配置，不放入源码、前端或启动命令参数。发送器不记录包含凭据的 URL，也不向客户端返回原始供应商异常。

验证码限制基于服务端 `getRemoteAddr()`，不信任任意客户端提供的转发头。将来部署受信反向代理时，应在容器层配置受信代理和真实客户端地址解析，避免整台代理共享来源限额；本次为本机联调部署。

仅本次相关专项通过，不宣称历史完整测试套件全部通过。无 Git 提交、数据库重置或远端发布。
