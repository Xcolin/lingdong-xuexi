# QA-04 方案：04-06 学员负责人多机构归属修订方案（待Codex确认，修订QA-02）

日期：2026-10-26。提交人：开发AI。本文修订 07-QA-02 方案，吸收 N05 质检意见；仅方案，未实施任何代码/迁移。

## 1. 修订背景（对齐 N05）

QA-02 的关键缺陷：`edu_student` 加全局单列 `responsible_user_id`，而孩子可同时在多所机构（多机构 ACTIVE 在读关系）有负责人，单字段会跨校互相覆盖。本修订改为 **student + institution 复合归属**，并吸收 N05 全部约束：默认班主任、显式指派、候选有效成员、版本并发、家长只读范围、菜单按钮码（不用 ORG_ADMIN 角色名兜底）、原因/说明/历史真实持久化、组织 owner 流程并存。

## 2. 数据域模型（修订后）

### 2.1 负责人归属表（新增，替代 QA-02 的单列方案）

`edu_student_institution_responsibility`：孩子在某机构（学校/培训机构）的负责人，按有效在读关系维护；**不对 edu_student 加任何列**。

| 列 | 说明 |
|---|---|
| student_id BIGINT NOT NULL | → edu_student |
| institution_organization_id BIGINT NOT NULL | 机构（须孩子在该机构有 ACTIVE 班级在读关系） |
| responsible_user_id BIGINT NULL | → sys_user；NULL=未显式指派，界面回退班级班主任 |
| version_no INT NOT NULL DEFAULT 1 | 乐观锁，CHECK(version_no>0) |
| updated_by BIGINT NULL | 最后指派操作人 |
| created_at / updated_at TIMESTAMP | |
| PRIMARY KEY (student_id, institution_organization_id) | 复合主键，同孩子两机构互不影响 |

对齐先例：V134 `edu_student_enrollment_metadata`（student+institution 复合主键 + version_no 乐观锁）与 `edu_class_academic_metadata`（head_teacher 派生 + audit）。

### 2.2 负责人解析规则（GET 时计算，不冗余存储）

1. 有行且 responsible_user_id 非空 → 显式指派（source=ASSIGNED）；
2. 无行或 NULL → 该机构内孩子 ACTIVE 班级的 head_teacher_user_id（多个班级按 edu_student_organization.effective_from DESC 取最新，source=HEAD_TEACHER）；
3. 都无 → 未指派（source=NONE，页面如实显示，不伪造）。

### 2.3 转交历史表（新增，原因/说明真实入库）

`edu_student_responsibility_transfer`：追加式转交记录。

| 列 | 说明 |
|---|---|
| id BIGINT PK | 雪花 |
| student_id / institution_organization_id BIGINT NOT NULL | 转交发生的机构范围 |
| from_user_id BIGINT NULL | 转交前实际负责人（可为派生班主任） |
| to_user_id BIGINT NOT NULL | 新负责人（本机构有效管理员） |
| reason_type VARCHAR(32) NOT NULL | CHECK IN('WORK_ADJUSTMENT','RESIGNATION_HANDOVER','TEMPORARY_TAKEOVER','OTHER')；枚举最长20字符，禁止截断 |
| reason_text VARCHAR(200) NULL | OTHER 时必填，其余可空；≤200 |
| transferred_by BIGINT NOT NULL | 操作人 |
| before_version_no INT / after_version_no INT NOT NULL | 版本并发留痕 |
| created_at TIMESTAMP | |

索引（student_id, institution_organization_id, created_at）。

## 3. 接口（挂 /api/v1/students，学员域）

1. `GET /api/v1/students/{studentId}/institution-responsibility?institutionOrganizationId=` —— 当前负责人解析结果 {responsibleUser:{id,name}, source: ASSIGNED|HEAD_TEACHER|NONE, className, versionNo}。家长（本家庭孩子，PARENT_RELATIONSHIP_READ）与本机构管理员可读；跨机构 403。
2. `GET /api/v1/students/{studentId}/institution-responsibility-transfer-options?institutionOrganizationId=` —— 候选人列表（复用 OrganizationOwnerGuard.administratorOptions 口径：本机构有效管理员 sys_organization_admin，不含本人）。
3. `POST /api/v1/students/{studentId}/institution-responsibility-transfer` —— body: institutionOrganizationId、targetUserId、reasonType、reasonText、expectedVersion。校验顺序：
   - 权限码 STUDENT_RESPONSIBILITY_TRANSFER + 操作者为本机构有效管理员（机构范围校验，跨机构 403）；
   - 孩子在该机构有 ACTIVE 在读关系，否则 404/400；
   - 目标为候选人且不可转给自己；
   - expectedVersion 与当前 version_no 不符 → 409（"负责人已变更，请刷新重试"）；
   - 成功后：upsert 责任行 version+1 + 落转交记录（同事务）。
4. `GET /api/v1/students/{studentId}/institution-responsibility-transfers?institutionOrganizationId=` —— 转交历史（家长只读可见；本机构管理员可见）。

## 4. 权限（菜单按钮码，不用角色名兜底）

- 新按钮码 `STUDENT_RESPONSIBILITY_TRANSFER`（BUTTON；Web 菜单挂学员管理页，MINIAPP 端教师/管理员可用）。授权经 sys_menu→sys_permission→sys_role_permission/sys_user_permission 统一链，**不**以 role_code='ORG_ADMIN' 字符串判断兜底。
- 查看负责人：家长复用 PARENT_RELATIONSHIP_READ（只读范围=本家庭孩子）；机构侧建议新建 `STUDENT_RESPONSIBILITY_READ`（BUTTON）或复用 CLASS_READ（待确认，见第 7 节）。
- 家长只读：不得调用转交接口，POST 一律 403。

## 5. 同孩子两机构互不影响示例（T08 实施时用此例证明）

孩子 S 同时就读：A 校班级 A1（班主任 T1）、B 机构班级 B1（班主任 T2）。

```sql
-- A 校管理员 U1 把负责人从班主任 T1 显式指派给 U2（转交）
INSERT INTO edu_student_institution_responsibility(student_id,institution_organization_id,responsible_user_id,version_no,updated_by,updated_at)
VALUES (S,A,U2,1,U1,CURRENT_TIMESTAMP)
ON DUPLICATE KEY UPDATE responsible_user_id=U2,version_no=version_no+1,updated_by=U1,updated_at=CURRENT_TIMESTAMP;
INSERT INTO edu_student_responsibility_transfer(student_id,institution_organization_id,from_user_id,to_user_id,reason_type,reason_text,transferred_by,before_version_no,after_version_no,created_at)
VALUES (S,A,T1,U2,'WORK_ADJUSTMENT',NULL,U1,1,2,CURRENT_TIMESTAMP);
-- B 机构无行 → 解析回退班主任 T2，A 机构转交不影响 B
-- A 机构负责人查询：U2（ASSIGNED）；B 机构负责人查询：T2（HEAD_TEACHER）
```

负例：A 机构转交请求带 institutionOrganizationId=B → 403；B 机构管理员不可操作 A 机构负责人行。

## 6. 与组织 owner 转交的关系（保持不变）

- owner 转交管机构负责人（sys_organization_owner），学生负责人转交管学员负责老师（新表），两者并存不互相替代；owner 流程代码不动。
- 候选人校验复用 OrganizationOwnerGuard 的 administratorOptions/isAdministrator 口径，抽取或同构实现，不改原 guard 行为。

## 2026-10-27 Codex 强制实施约束（覆盖上文 upsert 与版本示例）

1. 无显式负责人行时 GET versionNo=0；首次写入仅接受 expectedVersion=0，INSERT version=1，历史 before=0/after=1。已有行执行带版本条件 UPDATE，影响行数不为1则409；新建唯一键竞争也返回409。禁止使用上文无条件 ON DUPLICATE KEY UPDATE 示例。
2. 负责人更新与转交历史必须同事务；失败不留历史，重试不得重复历史。reason_type 已改 VARCHAR(32)，最长枚举20字符，DTO/迁移/页面一致。
3. 默认负责人仅取本机构有效班级/任职，effective_from 最新，唯一ID作平局排序。显式负责人失效时返回不可用状态，不继续当有效候选；历史保持可读。
4. 使用 STUDENT_RESPONSIBILITY_READ 与 STUDENT_RESPONSIBILITY_TRANSFER 挂菜单/按钮，不硬编码角色绕过；家长只读自身孩子该机构关系。本机构有效候选排除当前负责人（禁止无变化转交），不因操作人是候选而一律排除操作人。
5. 同孩子A/B机构各自版本、负责人、历史完全隔离。T08 可按此实施；T06-Q 待独立复验，不沿用开发自测勾选。
