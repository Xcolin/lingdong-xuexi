## 2. 推荐方案（学生负责人数据域，最小闭环）

- 持久化（新增迁移，不动现有表语义）：
  1. `edu_student` 加列 `responsible_user_id BIGINT NULL` → sys_user（学生当前负责人；NULL 表示未指派，界面回退显示班级班主任 head_teacher）
  2. 新建 `edu_student_responsibility_transfer`（转交记录，原因/说明真实入库）：
     - id、student_id → edu_student、from_user_id/to_user_id → sys_user、reason_type VARCHAR(16) CHECK IN('WORK_ADJUSTMENT','RESIGNATION_HANDOVER','TEMPORARY_TAKEOVER','OTHER')、reason_text VARCHAR(200)（OTHER 时必填，其余可空）、transferred_by、created_at；索引（student_id, created_at）
- 接口（小程序家长/老师端 + Web 兼容）：
  - `GET /students/{studentId}/responsibility` —— 当前负责人（responsible_user_id 优先，无则班级 head_teacher）+ 最近转交记录
  - `POST /students/{studentId}/responsibility-transfer` —— body: targetUserId、reasonType、reasonText（≤200）；校验：操作为本机构管理员（ORG_ADMIN 或持 CLASS_MANAGE 类码）、目标为本机构有效管理员、不可转给自己；成功后 responsible_user_id 更新 + 记录落库
  - `GET /students/{studentId}/responsibility-transfers` —— 转交历史（可查询）
- 权限与组织范围：
  - 操作权限：ORG_ADMIN 或持 CLASS_UPDATE/STUDENT_MANAGE 的本机构管理员（沿用 owner-transfer 的 administratorOptions 候选人口径）
  - 范围：仅本机构（学校/培训机构）在读学生；跨机构 403；家庭家长只读负责人信息不操作
- 页面形态：04-06 按原图重做（学生信息卡：头像/姓名/性别年龄/学号/当前班级 + 当前负责人 + 转交给 picker + 原因 radio 四选 + 说明 0/200 + 确认转交）。头像/性别年龄/学号无真实数据源时显示占位或空态，不伪造。

## 3. 与组织 owner 转交的关系

- 两者并存，不互相替代：owner 转交管机构负责人（sys_organization_owner），学生负责人转交管学员负责老师（edu_student.responsible_user_id）。
- 复用点：候选人校验逻辑（administratorOptions/isAdministrator）与"仅负责人可操作/不可转自己/乐观锁刷新重试"模式，从 OrganizationOwnerGuard 抽取复用或同构实现。
