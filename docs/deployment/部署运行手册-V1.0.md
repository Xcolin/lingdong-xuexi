# 灵动学习 部署运行手册（V1.0）

> 本手册面向运维人员，覆盖日常运行所需的启动/停止、健康监测、错误告警、日志脱敏与故障排查。
> 外置凭据与发布准入见《外置配置与发布检查.md》；备份恢复演练见任务 6.3 专项文档；发布方案设计见 `docs/design/11-部署运维与发布方案-V1.0.md`。

## 1. 运行环境与启动

- JDK 17+、MySQL 8+、Redis；构建工具链要求见《外置配置与发布检查.md》（正式发布保持 Maven 4 门槛，2026-09-29 确认）。
- 启动命令、外部受控配置文件要求、禁止 local/test profile 发布的约束，均以《外置配置与发布检查.md》为准。
- 应用日志默认写入工作目录 `logs/`（`LOG_PATH` 可覆盖），附件存储默认 `${user.dir}/data/attachments`（`ATTACHMENT_LOCAL_ROOT` 必须指向持久卷）。

## 2. 健康监测

- 探测端点：`GET /api/v1/health`（免认证，已在安全白名单）。
- 响应语义：
  - `200 {"status":"UP","application":"lingdong-learning","db":true,"redis":true}`：数据库与 Redis 均可连通。
  - `503 {"status":"DEGRADED",...,"db":布尔,"redis":布尔}`：任一依赖不可用；响应只含布尔结果，不输出异常细节或内部地址。
- 监控接入建议：负载均衡/看门狗以 HTTP 200 为健康判据，连续 3 次 503 触发人工介入。
- 验证方法（非真实敏感数据）：正常启动后 `curl http://127.0.0.1:8080/api/v1/health` 应返回 200 UP；停止 Redis 后再次探测应返回 503 且 `redis:false`。

## 3. 错误告警

- 未捕获的服务端异常统一返回 500（`INTERNAL_ERROR` + 追踪标识 `X-Request-Id`），响应不含内部细节；完整异常堆栈只写入应用日志。
- 每次未预期异常同时输出告警日志行（logger 名 `LINGDONG_ALERT`）：
  `[ALERT] exceptionType=<类型>, path=<请求路径>, traceId=<追踪标识>`
- 外置告警通道：环境变量 `ALERT_WEBHOOK_URL`（application.yml 键 `lingdong.alert.webhook-url`）。
  - 未配置（默认）：仅本地记录告警日志，不虚构送达。
  - 已配置：POST 白名单字段 JSON（application/exceptionType/path/traceId）；分发成功/失败均记录日志，失败不影响服务。
- 处置流程：根据 `traceId` 在应用日志中检索同请求的完整异常堆栈定位问题。
- 验证方法（非真实数据）：以未配置 webhook 启动后制造一次 500（如调用不存在内部依赖的开发调试入口），确认日志出现 `[ALERT]` 行；配置指向本地测试接收器后，确认接收器收到 JSON 且日志出现 `webhook 分发成功`。

## 4. 日志脱敏

- 应用日志（`logback-spring.xml`）：控制台 + 滚动文件（按天 + 50MB 滚动、保留 30 天、总量上限 2GB、gzip 归档）。
- 脱敏约束：
  1. 日志不得出现数据库密码、Redis 密码、微信/短信密钥、附件存储键、真实文件路径；
  2. 手机号、学生账号、姓名等个人信息在业务层统一脱敏后输出（样例：`138****8000`、姓名保留姓氏）；
  3. 错误告警行与对外错误响应均为白名单字段，不携带异常消息全文。
- 验证方法（非真实敏感数据）：使用样例手机号 `13800138000` 与样例学生账号完成一次登录，随后在当日日志文件中检索完整样例值，应无命中且仅见脱敏形式；检索 `password=`、`secret=` 不应出现非占位真实值。

## 5. 故障排查速查

| 现象 | 首查 | 说明 |
|---|---|---|
| `/api/v1/health` 503 | `db`/`redis` 字段 | 哪个依赖不可用；再到应用日志查对应 DEBUG 探测记录 |
| 用户反馈 500 | 响应头 `X-Request-Id` | 用 traceId 在 `logs/lingdong-learning.log` 检索完整堆栈 |
| 告警行大量出现 | `exceptionType` 分布 | 单一类型聚集通常对应单一依赖故障 |
| 导出文件下载 404 | 导出作业记录与附件状态 | 迟到文件会退役并清理内容，属预期行为 |

## 6. 与其他交付物的关系

- CI 门禁（后端测试/迁移校验/产物检查/敏感信息扫描/Web 与小程序构建）：`tools/ci.ps1` 与 `.github/workflows/ci.yml`，任一步骤失败即阻断。
- 备份与恢复：附件目录、数据库、日志均属备份范围；恢复演练与 Flyway 失败处置按任务 6.3 专项记录。
