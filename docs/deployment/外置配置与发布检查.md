# 外置配置与发布检查

本地配置原文件保持不变，不复制、不删除、不打印凭据。Git 忽略不能阻止 Maven 打包；POM 在资源复制和 JAR 两处排除 `application-local.*`，并在 initialize 阶段只移除构建输出目录中同名历史残留。不要将整个 target 目录作为发布包。

## 本地启动

在 server 目录，设置有效的 JDK 17 后执行：

```powershell
mvn spring-boot:run '-Dspring-boot.run.arguments=--spring.profiles.active=local --spring.config.additional-location=file:./src/main/resources/application-local.yml'
```

IDE 同样设置这两个应用参数，工作目录设为 server。外部路径不带 optional，指定文件不存在会明确失败；不自动回退至 classpath。启动会访问配置的数据库并可能执行 Flyway，运行前必须确认目标、备份和隔离授权。

## 正式运行

凭据通过受控外部文件或环境变量注入。外部文件位于部署目录之外、限制为运行账号可读；不放入源码 resources、不随 JAR 分发。不要使用 local/test profile 发布。示例路径只是占位，必须替换为运维实际挂载路径：

```powershell
java -jar lingdong-learning-server-0.0.1-SNAPSHOT.jar --spring.config.additional-location=file:/受控配置目录/application-prod.yml
```

所需配置键以 application.yml 和现有密钥配置校验为准，包括数据库、Redis、学生登录码加密、短信验证码 HMAC、导入凭证及导出来源签名密钥。不要把真实值写入命令行、文档或构建日志。缺少外部文件立即报错；密钥值仍由现有校验器校验。微信与短信业务必须等待真实供应商验收，内部队列不代表送达。

## 构建与准入

原要求保持 Maven 4+、JDK 17。当前 Maven 3.9.14 的构建只能证明该本地工具链下兼容；不能降低技术要求。使用 Maven 4 的实际回归证据缺失时，正式发布保持阻塞。

2026-09-10 核对 [Apache 官方下载页](https://maven.apache.org/download.cgi)：Maven 4.0.0-rc-6 仍为预览版，官方明确不适用于生产；运行要求 JDK 17+。因此 Maven 4 正式发布工具链尚不能收口，不能用预览版或 Maven 3 的验证冒充生产准入。

在 server 目录执行 `mvn -q '-DforkCount=0' package`，随后在仓库根目录执行 `powershell -File tools/check-release.ps1`。检查失败须阻断发布。仅检查当前产物可加 `-ArtifactOnly`，它不代表工具链准入通过。

测试使用 test profile 的 H2 和内存替身，不导入用户本地配置。发布检查只读 JAR 目录项，不输出凭据内容、不启动服务、不连接数据库或 Redis。旧的 `.jar.original` 及历史日志不是发布交付物。
