# 灵动学习部署运维与发布方案

**版本**：V1.0（设计基线草案）  
**状态**：待评审  
**适用阶段**：开发、测试、预生产、生产发布与运维  
**关联设计**：[HLD](03-系统架构设计-HLD-V1.0.md)、[Flyway 迁移规范](05-Flyway迁移规范-V1.0.md)、[测试方案](10-测试方案与验收用例-V1.0.md)

## 1. 环境与隔离

| 环境 | 用途 | 数据规则 | 密钥规则 |
|---|---|---|---|
| 开发 | 本地开发和单元/集成测试 | 虚拟/脱敏数据；可使用本地数据库和测试 Redis | 本地配置文件被 Git 忽略，不提交。 |
| 测试 | 功能、接口、自动化测试 | 仅测试数据；可重复初始化 | 使用测试账号，与生产完全隔离。 |
| 预生产 | 发布演练、迁移、压测、第三方联调 | 脱敏或经批准的受控数据 | 使用预生产凭证，与生产隔离。 |
| 生产 | 面向真实用户的服务 | 最小必要生产数据 | 通过受控环境变量或密钥服务注入，禁止写入仓库。 |

开发、测试、预生产和生产必须分别拥有数据库、Redis、对象存储桶/命名空间、第三方应用配置和日志访问权限。严禁将生产数据库、用户信息、微信密钥或对象存储密钥复制到前端工程、测试样本或文档。

## 2. 可发布单元

| 单元 | 技术 | 发布要求 |
|---|---|---|
| 后端服务 | Spring Boot 3、JDK 17+、Maven 3.9+并兼容 Maven 4、MyBatis XML | 包含通过测试的可追溯构建产物；启动时按 Flyway 规则校验数据库版本。 |
| 数据库迁移 | Flyway、MySQL 8+ | 版本化脚本随发布单执行；已执行脚本不可改写。 |
| Redis | 缓存/协调 | 不作为业务事实源；需要明确缓存失效、备份和连接配置。 |
| Web | Ant Design Pro React 独立构建产物 | 与小程序独立部署；无密钥、无位置 SDK 私密配置。 |
| 小程序 | uni-app 独立构建包 | 首发个人主体工具类目包不含定位、轨迹和地图能力。 |
| 对象存储/消息/第三方 | 适配器和环境配置 | 服务登记、凭证、授权范围和健康检查完成后接入。 |

## 3. 配置管理

1. 代码仓库只保存非敏感默认配置和配置键说明；密钥、密码、私钥、生产地址和第三方凭证使用环境变量或受控密钥服务注入。
2. 本地 `application-local.yml` 可保存开发机密钥，但必须被 Git 忽略，不打印、不复制到 Web 或小程序配置。任何已泄露或误提交的密钥均按安全事件更换。
3. Web 与小程序各自使用独立的环境配置，前端只允许保存可公开的应用标识、API 地址等内容，不保存应用密钥、对象存储凭证或数据库配置。
4. 配置变更遵循系统配置、接口服务和功能开关规则；重要配置、全局开关、恢复、敏感导出等由系统管理员发起、系统审核员审批。
5. 不以修改数据库 `sys_config` 或 Redis 键替代正式发布；需要持久化的配置变化必须有业务入口、审计和必要审批。

## 4. CI/CD 发布流水线

```mermaid
flowchart LR
    A[代码与设计评审] --> B[后端编译/单元测试]
    B --> C[Flyway 空库和升级库验证]
    C --> D[API/安全/集成测试]
    D --> E[Web 与小程序独立构建]
    E --> F[预生产部署与冒烟/UAT]
    F --> G[生产变更审批]
    G --> H[备份与 Flyway 发布]
    H --> I[后端、Web、小程序发布]
    I --> J[健康检查、缓存核对、功能开关确认]
```

### 4.1 最小自动化检查

1. 后端在 JDK 17 环境编译并执行 `mvn test`；当前开发机需显式使用可运行的 JDK 17，不能依赖错误的系统 JDK 配置。
2. 每次构建执行 Flyway `validate`，并在空库与升级库验证迁移。
3. 执行 MyBatis XML 映射、权限、数据范围、功能开关、系统任务、API 契约和关键状态机测试。
4. Web 与小程序分别构建；扫描产物确保首次小程序包不包含定位、地图和轨迹相关代码/权限声明。
5. 执行依赖、密钥、敏感日志和静态安全检查；失败不得以忽略告警方式继续发布。

## 5. 数据库与 Flyway 发布

1. 发布前确认本次版本的数据库设计、迁移清单、目标环境 `flyway_schema_history`、迁移校验和和备份状态。
2. 迁移执行前创建受控备份；生产备份采用每日全量备份并保留 30 天的既有业务要求。恢复点目标和恢复时间目标仍待项目侧确认。
3. 先执行 `validate`，再执行 `migrate`。出现版本漂移、校验和异常、锁等待或预期外影响行数时立即停止，不以手工改表继续发布。
4. 完成迁移后进行结构验证、基础数据验证、应用健康检查和关键 API 冒烟；必要时清理受影响缓存，但全量/会话缓存清除必须走系统任务流程。
5. 回退以应用向后兼容、前向补偿迁移和受控数据恢复为主。数据恢复属于高风险系统任务，不能直接从备份覆盖生产。

## 6. 发布顺序与开关策略

| 步骤 | 操作 | 核验 |
|---|---|---|
| 1 | 设计、测试、UAT、变更单审批 | 版本、风险、回退、数据迁移和责任人齐全。 |
| 2 | 备份与预检 | 数据库/Redis/对象存储配置可用，`validate` 成功。 |
| 3 | 执行 Flyway 迁移 | 仅新增版本执行，历史记录一致。 |
| 4 | 发布兼容后端 | 健康检查、日志、数据库连接、Redis 连接正常。 |
| 5 | 发布 Web 与小程序 | 两端 API 版本匹配；小程序包能力与发布主体条件匹配。 |
| 6 | 运行冒烟与权限检查 | 关键角色、关键开关、任务/积分主链路可用。 |
| 7 | 审批后调整全局功能开关 | 高风险开关通过系统任务审批，前后端及缓存结果一致。 |
| 8 | 观察期 | 监控错误、迁移、第三方、消息、导出和权限拒绝异常。 |

新功能可先以关闭状态随兼容代码发布；真正全局启用必须遵守功能开关审批规则。位置相关能力除了运行期开关，还必须发布不含该能力或含该能力的不同小程序构建包，不能把构建期要求推给开关处理。

## 7. 运行监控与日志

| 监控项 | 关注内容 |
|---|---|
| 应用健康 | 服务可用、数据库连接、Redis 连接、关键依赖状态；健康接口不得泄露配置。 |
| API | 请求量、错误码分布、响应时间、权限拒绝、功能关闭拒绝、幂等冲突、请求标识。 |
| 数据库/Flyway | 迁移状态、失败迁移、连接、慢查询、锁等待、备份结果。 |
| Redis | 连接、内存、命中、失效、缓存操作失败、分布式任务锁。 |
| 第三方 | 微信/短信/文件/地图/对外接口成功率、超时、失败重试、回调签名失败。 |
| 业务任务 | 日/周/月复盘、审核超时、兑换超时、日志归档、轨迹清除、导入导出任务执行结果。 |
| 安全 | 登录失败、锁定、异常导出、跨域/越权拒绝、敏感配置变更、密钥扫描。 |

日志按安全设计保存，操作日志热存 180 天后冷归档。日志、监控告警和错误页面不得输出密钥、认证令牌、完整手机号、位置坐标、文件永久地址或原始第三方敏感报文。

## 8. 备份、恢复与故障预案

1. 每日全量数据库备份，保留 30 天；对象存储、配置、接口服务登记和必要审计数据的备份范围在部署评审中一并确认。
2. 数据误删、历史回填错误或需要恢复时：评估影响范围 -> 系统管理员创建恢复任务 -> 系统审核员审批 -> 在受控窗口执行 -> 验证数据和审计 -> 记录结果。
3. 发生身份、权限、位置、家庭数据或密钥疑似泄露时，优先关闭受影响功能/接口、使相关会话或凭证失效、保全日志、评估影响并按组织安全流程处理；不通过删除日志掩盖事件。
4. 第三方不可用时，核心业务应保持可控：微信登录失败回落到允许的登录方式，消息失败保留站内消息并重试，地图/位置失败不生成伪造考勤，文件失败不写入无效附件关系。

## 9. 上线前待确认项

| 编号 | 待确认项 | 上线影响 |
|---|---|---|
| O-001 | 域名、HTTPS 证书、网络隔离、部署形态与容量 | 无法完成生产网络与证书配置。 |
| O-002 | MySQL/Redis/对象存储高可用方案、RPO、RTO | 无法完成灾备验收。 |
| O-003 | 微信、短信、地图、对象存储的生产主体、资质、合同和凭证 | 无法安全启用对应生产能力。 |
| O-004 | 小程序发布类目和位置能力的后续版本计划 | 首发包必须保持不含位置/地图能力。 |
| O-005 | 性能并发、数据量、可用性与告警阈值 | 无法形成量化性能准出。 |

这些项不应被开发阶段的默认配置掩盖；它们是生产上线前的显式评审关口。

## 11. V36 发布配置与准入

1. `PARENT_PHONE_AUTH` 在真实短信供应商、域名、模板和监控未验收前必须保持停用；停用后两端入口隐藏，服务端发送与登录接口拒绝。
2. 生产必须配置不少于 32 字节的验证码 HMAC 密钥，并使用独立 Redis 命名空间；Redis 不可用时不得降级为本机验证码存储。
3. 上线前在批准的 MySQL 8 与 Redis 环境验证 V1-V36 升级、并发消费、故障关闭、频控、协议升级和回滚恢复；本地 H2 结果不能替代。
4. 日志、链路追踪、告警和备份中不得记录验证码、令牌、密码、完整手机号或第三方凭证。
5. 本轮未在共享测试、预生产或生产环境执行，也未连接用户提供的远程数据库、Redis、短信或微信服务。

## 12. V37 微信认证发布配置与准入

1. `PARENT_WECHAT_AUTH` 默认停用；只有真实短信与微信能力均在批准环境验收后才允许启用，停用时小程序入口隐藏且后端接口拒绝。
2. 生产通过环境变量或受控密钥服务注入微信应用标识和密钥，不写入前端包、Flyway、日志或文档；发布前验证接口服务管理中微信出站服务登记为启用。
3. 生产 Redis 必须承载 5 分钟一次性绑定票据并支持原子取出删除；不可用时不得降级到本机内存。上线前验证重放、超时、并发绑定、唯一冲突和故障关闭。
4. V37 微信绑定发布前仍须在批准的 MySQL 8 环境验证其前向升级、唯一约束和回滚恢复；当前代码基线已推进到 V38，任何新迁移从 V39 开始且不修改 V1-V38。
5. 本地验收使用测试假微信网关，不构成真实微信接口、个人主体类目、域名、隐私合规或业务 UAT 的上线证据。

## 13. V38 家长关系发布准入

1. `PARENT_RELATIONSHIP_MANAGEMENT` 默认停用；真实短信模板、协议版本、邀请转交方式和客服争议处理流程验收前不得在生产启用。
2. 升级前备份关系、邀请、任务审核人与转交历史；在批准的 MySQL 8 环境验证 V1-V38 前向迁移、主副唯一约束、并发接受和事务回滚。该 V38 发布检查记录保留；V39 时点的下一迁移为 V40，且不得修改 V1-V39。
3. 启用前使用主家长、副家长、无关家长和多学生数据完成 Web/小程序 UAT，验证入口隐藏、直达拒绝、对象隔离、自动晋升和待审核任务转交。
4. 监控邀请创建/响应失败、唯一冲突、任务转交回滚和短信不可用，不记录完整手机号、验证码、令牌、来源地址或内部范围键。
5. 本地 H2、测试适配器和静态构建结果不替代真实 MySQL、Redis、短信、微信、共享测试、预生产和生产发布验证。

## 15. V39 发布检查

1. 发布顺序为备份与校验、执行 V39、部署后端、部署 Web 与小程序，再按审批启用或停用账号安全开关；不得修改 V1-V39 历史脚本。
2. 在获批 MySQL 8 环境验证表约束、索引和 19 位标识，在获批 Redis 环境只验证既有认证保护，不把本地 H2 结果替代真实环境结论。
3. 验收设备下线后令牌立即失效、开关关闭后管理接口拒绝、当前退出仍可用，以及 Web/小程序入口和直达行为一致。
4. 监控事件写入冲突、会话撤销失败和管理接口异常，不记录令牌、原始设备标识、设备摘要或内部范围键。

## 16. V40 发布检查

1. 发布顺序为执行 V40、部署后端、部署 Web 契约版本、部署小程序，再按审批启用 `ORGANIZATION_MINIAPP_AUTH`；不得修改 V1-V40 历史脚本。
2. 启用前确认机构账号具有启用 `ORG_ADMIN` 角色和至少一个直接管理的启用组织；无效账号不得通过临时数据或前端绕过。
3. 在批准环境验证开关关闭、角色移除或停用、关系移除、组织停用后旧访问和刷新令牌立即失效，同时确认机构 Web 会话不受小程序开关影响。
4. 当前本地结果不替代真实 MySQL 8、Redis、微信开发者工具、共享测试、预生产、生产和机构业务 UAT。
5. 通过系统任务审批停用 `ORGANIZATION_MINIAPP_AUTH` 时，必须核对机构 `MINIAPP` 活动会话已批量撤销、机构 `WEB` 会话保持活动；重新启用后旧小程序令牌不得复活。

## 17. V41 发布检查

1. 发布顺序为备份学生、机构关系和任务来源事实，执行 V41，部署后端，再分别部署 Web 与小程序；不得修改 V1-V41 历史脚本。
2. 在批准的 MySQL 8 环境验证审计表检查约束、外键、索引、19 位标识和 V1-V41 前向迁移；本地 H2 结果不能替代真实环境验证。
3. 启用前使用同校两班、同一管理员管理两校、无关机构和已停用班级数据验证转班、跨校拒绝、转出及历史留存。
4. 功能关闭后核对两端入口隐藏、直达 API 拒绝且历史表不被删除；回滚应用版本时保留 V41 表和基础数据，不执行降级删表。
5. 当前未对远程 MySQL、Redis、共享测试、预生产或生产环境执行迁移和写入。

## 18. V42 发布检查

1. 发布顺序为备份用户、家长档案、微信绑定、亲子关系和设备会话，执行 V42，部署后端，再分别部署 Web 与小程序；不得修改 V1-V42 历史脚本。

## 19. V43 发布检查

1. 发布前备份用户、家长档案、微信绑定、亲子关系、设备会话和注销申请；先执行 V43，再部署后端和 Web，不得修改 V1-V43 历史脚本。
2. 首次启用调度前在批准的 MySQL 8 环境核对 V43 字段、回填数量和到期索引，并以小批量观察待处理、成功、关系延后和失败数量。
3. 配置 `LINGDONG_PARENT_ACCOUNT_FINALIZATION_SCHEDULING_ENABLED`、批量大小、cron 和关系延后周期；维护窗口或异常期间通过调度开关暂停，不手工伪造终结状态。
4. 监控日志不得包含直接身份或异常文本；验证终结后全部旧会话失效、微信绑定删除、用户不可恢复且历史业务查询仍可使用匿名身份。
5. 应用回滚时保留 V43 字段和已终结事实，不恢复匿名身份、不重新启用账号、不执行删列降级。当前本地结果不替代真实 MySQL、Redis、短信、微信、共享测试、预生产、生产和业务验收。
