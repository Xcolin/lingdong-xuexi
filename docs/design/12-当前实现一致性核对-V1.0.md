# 灵动学习当前实现一致性核对

**版本**：V1.0（核对记录）  
**核对日期**：2026-07-30  
**状态**：已核对，非验收结论  
**核对依据**：[设计追溯](00-设计文档体系与需求追溯-V1.0.md)、`server/` 实际代码、Flyway `V1` 至 `V9`

## 1. 核对结论

当前后端是“基础权限与系统管控骨架”，不是可上线的完整灵动学习系统。它已经为后续业务模块提供了组织树、RBAC、角色数据范围、系统任务审核和功能开关基础；但没有认证入口、真实业务 API、学生关系、任务、积分、配置公共能力或任一前端应用。

因此，现有实现只能标记为**基础能力已实现并通过当前自动化回归**，不能标记为 BRD 功能验收完成。

| P0 | REST API 与 OpenAPI 契约 | 只有健康端点，Web/小程序无法联调 | 每开发一个模块同步提供 API 与契约测试。 |

## 4. 已知设计/实现边界

1. `PermissionDecisionService` 已实现“明确禁止优先于角色允许和用户补充允许”，但尚未把功能开关、对象数据范围和 HTTP 接口串为一个统一拦截链。
2. `OrganizationDataScopeService` 已实现“角色范围、用户组织关联、组织管理员范围的交集”，但 `SELF` 不会自动授予组织树访问，这是正确的基础行为；后续学生/家庭数据授权必须单独建立亲子关系和本人对象判断。
3. `SystemTaskApplicationService` 正确限制系统管理员发起、系统审核员审核并禁止自审；`FeatureToggleChangeService` 已实现开关审批后生效。其他高风险操作尚没有统一的“任务载荷 -> 审批 -> 执行 -> 已生效”实现。
4. `GEO_ATTENDANCE` 与 `STUDENT_LOCATION_TRACK` 已在 V6 初始化为关闭，符合首发安全边界；但因小程序工程尚未创建，仍需要在前端构建阶段验证没有位置/地图依赖。
5. 当前测试在 H2 MySQL 兼容模式运行，Flyway 对 H2 2.3.232 输出“版本未测试”告警，但本次迁移与 26 个测试均通过。正式 MySQL 8 环境仍需执行迁移与升级验证。

## 6. 后续实施准入

1. 每个新模块必须先引用对应 FSD、数据库、Flyway、API、安全和测试章节，再新增迁移与代码。
2. 第一项建议实施的数据字典应从 `V10` 开始，先完成类型、字典项、默认项、启停、缓存失效、系统管理员授权和关键字典审核边界。
3. 在认证与 OpenAPI 基础落地前，不创建仅供内部测试使用的绕过鉴权业务 Controller，避免形成后续无法安全替换的临时接口。
4. 任何新模块完成后，更新本文件的覆盖表，并重复执行 Flyway 空库/升级库验证和全量后端回归。
