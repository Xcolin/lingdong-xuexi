## 1. 使用规则

1. 业务需求说明书（BRD）定义业务范围、角色、流程、规则和验收基线；所有设计文档不得改变 BRD 的业务含义。
2. 本目录的设计文档定义实现边界、数据模型、接口契约、交互和测试方式；设计选择必须可追溯到 BRD。
3. 当前 `server/` 中的代码和 `V1` 至 `V9` Flyway 脚本仅记录已有实现事实，不能替代本设计文档，也不能反向修改 BRD。
4. 未被 BRD 或已确认口径明确的内容，以“待确认”标记；在确认前不得写入生产实现或通过默认值暗中固化。
5. Web 与小程序是独立前端应用，页面工程、发布包和私密配置不得混用；二者以同一后端 API 契约和同一业务规则为准。

## 4. 已确认的不可变规则

1. 角色体系为系统管理员、系统审核员、机构（学校）管理员、教师、家长、学生；系统管理员可新增自定义角色并动态分配不超过授权边界的权限。
2. 系统审核员只审批系统管理员发起的高风险系统任务，不审批学习任务、打卡、积分或奖励兑换。
3. 机构与家长可独立存在并独立下发任务；因学生建立关联不代表机构取得家庭私有数据权限。
4. 权限采用 RBAC，组织采用区域、学校为主线的树形架构；功能开关优先于角色与数据权限，停用后前端隐藏且后端拒绝新操作。
5. Web 端与小程序端是独立应用；高频操作可双端提供，复杂统计、批量管理、权限组织配置和系统配置以 Web 为主。
6. 后端采用 Spring Boot 3+、JDK 17+、Maven 3.9+并兼容 Maven 4、MyBatis XML、MySQL 8+、Redis、Flyway；Web 使用 Ant Design Pro React，小程序使用 uni-app。
7. 未成年人定位和轨迹默认停用；首次个人主体、工具类目小程序构建包不得包含定位采集、轨迹记录和地图调用能力。后续全局启用须经系统管理员发起高风险任务、系统审核员审批，并取得家长授权。

## 5. 评审与实施关口

```mermaid
flowchart LR
    A[BRD 已确认] --> B[FSD 与交互评审]
    B --> C[HLD、数据、Flyway、API、安全评审]
    C --> D[模块编码与单元测试]
    D --> E[前后端联调与迁移验证]
    E --> F[测试验收与发布评审]
    F --> G[上线]
```

1. 新模块进入编码前，至少完成并评审该模块的 FSD、交互说明、数据模型、Flyway 方案、API 和权限规则。
2. 涉及第三方、统计、导出、定位、未成年人信息或高风险系统任务时，还必须完成对应专项设计与测试用例。
3. 实施状态只在测试通过、设计核对完成后更新；“代码已存在”不等同于“需求已验收”。
