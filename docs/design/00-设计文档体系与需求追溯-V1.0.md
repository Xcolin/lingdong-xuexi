## 1. 使用规则

1. 业务需求说明书（BRD）定义业务范围、角色、流程、规则和验收基线；所有设计文档不得改变 BRD 的业务含义。
2. 本目录的设计文档定义实现边界、数据模型、接口契约、交互和测试方式；设计选择必须可追溯到 BRD。
3. 当前 `server/` 中的代码和 `V1` 至 `V37` Flyway 脚本仅记录已有实现事实，不能替代本设计文档，也不能反向修改 BRD；V36 家长手机号认证和 V37 家长微信授权绑定已本地完成，但不能表述为真实短信、真实微信联调或生产上线完成。
4. 未被 BRD 或已确认口径明确的内容，以“待确认”标记；在确认前不得写入生产实现或通过默认值暗中固化。
5. Web 与小程序是独立前端应用，页面工程、发布包和私密配置不得混用；二者以同一后端 API 契约和同一业务规则为准。

## 4. 已确认的不可变规则

1. 角色体系为系统管理员、系统审核员、机构（学校）管理员、教师、家长、学生；系统管理员可新增自定义角色并动态分配不超过授权边界的权限。
2. 系统审核员只审批系统管理员发起的高风险系统任务，不审批学习任务、打卡、积分或奖励兑换。
3. 机构与家长可独立存在并独立下发任务；因学生建立关联不代表机构取得家庭私有数据权限。
4. 权限采用 RBAC，组织采用区域、学校为主线的树形架构；功能开关优先于角色与数据权限，停用后前端隐藏且后端拒绝新操作。
5. Web 端与小程序端是独立应用；高频操作可双端提供，复杂统计、批量管理、权限组织配置和系统配置以 Web 为主。
6. 后端采用 Spring Boot 3+、JDK 17+、Maven 3.9+并兼容 Maven 4、MyBatis XML、MySQL 8+、Redis、Flyway；Web 使用 Ant Design Pro React，小程序使用 uni-app。
7. 未成年人定位和轨迹默认停用；首次个人主体、工具类目小程序构建包不得包含定位采集、轨迹记录和地图调用能力。后续全局启用须经系统管理员发起高风险任务、系统审核员审批，并取得家长授权。

## 5. 评审与实施关口

```mermaid
flowchart LR
    A[BRD 已确认] --> B[FSD 与交互评审]
    B --> C[HLD、数据、Flyway、API、安全评审]
    C --> D[模块编码与单元测试]
    D --> E[前后端联调与迁移验证]
    E --> F[测试验收与发布评审]
    F --> G[上线]
```

1. 新模块进入编码前，至少完成并评审该模块的 FSD、交互说明、数据模型、Flyway 方案、API 和权限规则。
2. 涉及第三方、统计、导出、定位、未成年人信息或高风险系统任务时，还必须完成对应专项设计与测试用例。
3. 实施状态只在测试通过、设计核对完成后更新；“代码已存在”不等同于“需求已验收”。

## 10. V38 追溯补充

V38 对应 `BRD-3.3-07` 副家长关系生命周期：主家长邀请、目标手机号主动确认、主副关系唯一、解除副家长、主家长自行解绑、最早副家长自动晋升、监护权转移、不可变审计和家庭待审核任务转交。副家长仅可读取活动关系学生及其任务、积分、奖励和复盘，写操作继续要求活动主家长。Web 与 uni-app 使用独立页面和家长会话；真实短信投递、消息通知、手机号换绑、注销、转班转学和外部环境 UAT 不在 V38 完成口径内。

## 11. V39 追溯补充

V39 细化账号安全通用能力：六类角色均可管理本人的活动设备、查看最近 50 条站内安全事件并处理已读。首次设备按“用户、客户端、设备标识”判定，Web 与小程序分别识别；普通退出不产生风险事件，主动下线指定设备和全部设备记录信息事件。后端以 `ACCOUNT_SECURITY_MANAGEMENT` 强制控制管理接口，停用后两端隐藏且直达拒绝，当前会话退出保持可用。外部短信、微信通知和生产环境联调不在 V39 完成口径内。

## 12. V40 追溯补充

V40 对应机构管理员小程序操作能力的认证前置：只有启用的机构账号同时具有启用 `ORG_ADMIN` 角色和至少一个直接管理的启用组织时，才可通过专用密码端点获得 `MINIAPP` 会话。登录、访问令牌和刷新令牌持续复核用户、角色、组织关系和 `ORGANIZATION_MINIAPP_AUTH`；任一条件失效时旧小程序会话立即不可用，但机构 Web 会话保持独立。工作台只返回当前用户直接管理的启用组织摘要；转班转学、机构任务、考勤、统计和机构微信登录不在 V40 范围。

## 13. V41 追溯补充

V41 对应学生校内转班、离校或转学转出和机构历史留存：目标班级必须位于当前活动入学组织子树，跨机构不得直接迁移原学生账号；原机构停用活动入学及其子树班级关系并保留学生、家庭和历史业务事实，新机构沿用既有创建学生与家长确认绑定流程。关系变更写入只追加审计，Web 与 uni-app 分别提供操作入口，`STUDENT_ORGANIZATION_RELATIONSHIP` 停用后入口隐藏且后端拒绝。

## 14. V42 追溯补充

V42 对应家长常规手机号换绑和账号注销前置：旧手机号与新手机号分别使用隔离验证码用途，旧号验证票据绑定用户、客户端和当前手机号摘要；换绑只更新用户手机号及默认手机号登录名，保留微信绑定、亲子关系和历史事实，并撤销全部活动会话。注销申请要求不存在活动学生关系，校验当前手机号和“确认注销”文本后进入 7 天冷静期，期间可撤销；到期只展示待执行状态，不停用、匿名化或删除账号。原号码失效时的机构人工核验及最终注销另行设计。

## 15. V43 追溯补充

V43 对应家长冷静期到期后的最终注销与匿名化：后台有限批量扫描到期申请，单申请独立事务锁定申请和用户并复核活动学生关系；关系恢复时延后重试，无关系时匿名化用户直接身份、删除微信绑定、撤销全部活动会话并写入 `FINALIZED`。任务、积分、审核、历史关系和协议事实继续引用内部用户标识，不新增原始需求之外的留存期限。功能停用时调度暂停，后台已注销账号只读且不能通过通用状态接口恢复。学生注销及原号码失效人工核验不属于 V43。

## 16. V44 追溯补充

V44 对应家长原手机号不可接收验证码时的机构人工核验换绑：只允许活动学生所属机构的直接机构管理员在组织子树范围内操作，目标家长必须具有活动主家长或副家长关系。机构完成线下身份核验后，目标新手机号仍须通过专用短信验证码；成功换绑同步默认手机号登录名、撤销全部活动会话并写入只含新旧号码 HMAC 摘要、原因和操作者的不可变审计。系统审核员不参与机构业务换绑；原始材料未规定证件附件、双人审批和留存期限，因此不采集证件资料、不新增审批状态。没有活动机构关系的独立家庭暂不开放人工恢复。

## 17. V45 追溯补充

V45 对应原始材料中的学生账号彻底注销规则：学生不能自行注销，只有学生已无任何活动机构关系、无任何活动家长关系时，最近一条已停用入学关系所属组织范围内的机构管理员可以注销。执行后学生档案和学生用户直接身份匿名化，学生登录码删除、活动二维码和全部设备会话撤销，历史机构关系及业务外键保留。原始材料未规定冷静期、审核流或附件，因此不新增等待期、系统审核员审批和证明材料。没有任何机构历史的独立学生不存在合法机构操作主体，V45 不开放注销。

## V47 组织节点生命周期追溯补充

- 系统管理员负责组织节点低风险编辑、重新启用以及停用、移动、删除申请；系统审核员只审核系统管理员提交的组织变更，不创建、编辑或提交组织。
- 区域、学校继续采用树形架构。节点同时保存自身状态和由祖先状态计算的有效状态，任何祖先停用都会阻止其子树产生新的机构业务。
- 停用、移动和删除复用系统任务审批；删除前校验下级节点及已有组织业务引用，历史数据不因组织停用而删除。
- `ORGANIZATION_MANAGEMENT` 功能关闭后，Web 平台组织管理和审核入口隐藏，后端查询、编辑、申请和审核接口同步拒绝。
- Web 提供平台组织管理和审核界面；uni-app 不增加平台级组织树维护入口。现有机构小程序登录和机构业务继续校验组织有效状态。
- 需求、设计和实施证据见 `docs/superpowers/specs/2026-08-15-lingdong-organization-node-lifecycle-design.md` 及对应实施计划。

## V59 教师管理追溯补充

V59 追溯 `BRD-3.1-01`、`BRD-3.1-06`、`BRD-3.6-03` 和 WBS-07。机构管理员在授权学校范围内维护教师账号、状态、密码和多班级关系；教师固定复用机构用户、学校人员关系和全局教师角色，不新增重复教师主档。Web 提供筛选、分页和最多 100 人的批量状态或班级操作，uni-app 只提供高频单项操作。系统审核员不参与机构教师业务，仍只审批系统管理员提交的系统任务。

所有入口同时受 `TEACHER_MANAGEMENT`、动态 RBAC、机构管理员角色和组织数据范围控制。选择初始班级时还必须具备 `TEACHER_CLASS_ASSIGN`；Web 批量操作除 `TEACHER_BATCH_MANAGE` 外，还必须具备对应的状态或班级基础权限。手机号仅脱敏返回，密码重置撤销活动会话；待审核任务阻止教师停用、锁定或相关班级解绑，班级绑定与解绑写入不可变日志。V59 不包含教师文件导入、教师任务剩余流程、复杂统计、考勤、定位或异常报备。

## V60 机构与教师任务补齐追溯

## V61 学生异常报备追溯

V61 追溯 `BRD-3.6-09` 和 WBS-07。教师可对本人当前有效班级中的活动学生提交出勤、学习状态或心态异常，机构管理员可在本人组织数据范围内查询并处理。报备只允许从“待处理”单向进入“已处理”，不提供修改、撤回、删除或重新打开，提交与处理均追加永久动作记录。

Web 与独立 uni-app 均提供台账、详情和对应单项操作；Web 额外提供班级、异常类型和状态组合筛选。所有入口受 `STUDENT_EXCEPTION_REPORT`、动态 RBAC、角色和对象范围共同控制，范围外记录统一按不存在处理。创建采用教师加幂等键防重，处理采用状态和版本并发保护；业务事务内只写本地待分发消息事件，不声明微信消息已送达。系统审核员不参与异常报备处理。
